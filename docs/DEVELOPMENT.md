# 개발 및 실행 안내

## 빠른 시작

```powershell
node --version
npm ci
node server.mjs
```

Node.js 24 이상과 npm이 필요합니다. `npm ci`는 로컬 OCR 엔진·한국어·영어 모델을 설치하며 웹 빌드는 없습니다. `http://127.0.0.1:3100`에서 실행합니다. `npm start`, `npm test`, `npm run check`도 사용할 수 있습니다. 종료는 터미널에서 Ctrl+C입니다. 웹에 집중하며 별도의 모바일·데스크톱 앱을 개발하지 않습니다.

코드 변경을 자동 반영하려면 `node --watch server.mjs`를 사용합니다. 화면 파일 변경 후에는 브라우저를 새로고침합니다. 서버가 재시작되면 화면에서 입력한 API 키는 다시 등록해야 합니다.

## AI 설정

화면의 `AI 연결 설정`에서 API 키와 모델을 입력하고 `저장하고 연결 점검`을 누릅니다. 키 등록과 점검 통과를 구분해 표시합니다. 점검은 상담 없이 짧은 실제 Structured Outputs 요청으로 인증·모델·응답 형식을 확인하며 소량의 API 비용이 발생합니다. 성공 결과는 10분간 재사용하고 설정 변경 시 무효화합니다. 웹의 실제 AI 작업 전에도 자동 점검합니다. 키는 서버 메모리에서만 유지되고 브라우저 저장소·DB·내보내기에 포함하지 않습니다.

환경변수 방식이 필요하면 `.env.example`을 복사해 로컬 `.env`를 만들고 직접 값을 입력합니다.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5-mini
PORT=3100
REPLYTRACK_DATA_DIR=./data
```

`.env`는 Git에서 제외됩니다. 키를 채팅, 이슈, 소스 코드에 기재하지 않습니다. 화면과 `.env` 모두 설정했다면 화면에서 등록한 값이 현재 프로세스에서 우선합니다. 모델은 텍스트 Structured Outputs를 지원해야 합니다. 캡처는 로컬에서 전사하므로 이미지 입력 모델은 필요하지 않습니다.

API 요청은 [Responses API의 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 사용합니다. `store: false`로 전송하며, 이 설정을 제공자의 모든 로그가 남지 않는다는 보장으로 해석하지 않습니다.

## 구현 구조

```text
server.mjs            HTTP 라우팅, 로컬 출처 확인, 정적 화면
src/store.mjs         SQLite 저장, 레코드 버전 검사
src/service.mjs       상담·분석·사용자 수정·초안 유스케이스
src/domain.mjs        원문 검증, 날짜 계산, 상태 병합
src/openai.mjs        Responses API 호출과 오류 처리
src/operation.mjs     메모리 작업 상태, 실제 단계, 취소·전체 시간 제한
src/privacy.mjs       전화번호·주소 마스킹과 요청별 로컬 복원
src/ocr*.mjs          외부 전송 없는 로컬 캡처 인식과 작업자 종료
src/schema.mjs       분석·전사·초안 JSON 스키마
src/prompts.mjs       각 작업의 프롬프트
src/demo.mjs          API 없는 고정 예제와 후속 답변
public/              한국어 반응형 화면
tests/               도메인 및 HTTP API 테스트
scripts/             문법 검사와 실제 API 검증
data/                로컬 SQLite (Git 제외)
.artifacts/          검증 결과·화면 캡처 (Git 제외)
```

상담은 JSON 문서 단위로 SQLite에 저장합니다. `messages`가 근거 원문이며, `questions`·`promises`·`history`·`drafts`를 함께 보관합니다. 원문 메시지는 분석 뒤 편집하지 않으며 잘못 입력했다면 검토 화면에서 수정하거나 새 상담으로 다시 등록합니다. 질문 제목과 판정은 상세 화면에서 수정할 수 있습니다.

## 오류와 상태 처리

- 추가 메시지 저장과 분석을 분리합니다. API 실패 시 새 원문과 이전 분석이 남고 `새 답변 분석`으로 재시도합니다.
- 검증되지 않은 답변 인용은 `확인 필요`, 원문에 없는 새 질문·약속은 제외와 경고로 처리합니다. 기존 질문·약속은 AI가 누락해도 삭제하지 않습니다.
- 사용자가 직접 수정한 상태는 재분석 후에도 유지하고 최신 AI 제안을 별도로 표시합니다. `AI 제안 적용`으로 되돌릴 수 있습니다.
- 업체의 처리 안내만으로 사용자 확인 완료를 만들지 않습니다. 실제 확인 시각은 사용자 액션으로만 저장합니다.
- 새 메시지 추가만으로 이전 초안을 지우지 않습니다. 화면에 `이전 분석 기준`을 표시하고, 새 분석이 성공해 저장될 때 초기화합니다. 분석 취소·실패 시 DB의 초안과 화면의 미저장 편집을 모두 보존합니다. 질문 판정 수정·처리 확인은 기존대로 초안을 초기화합니다.
- 같은 버전에서 시작한 AI 결과라도 중간에 다른 수정이 저장되면 HTTP 409로 거절합니다. 화면은 최신 기록을 다시 읽되 미저장 초안을 유지하고, 사용자가 비교한 뒤 다시 저장하도록 안내합니다. 원래 초안이 초기화된 경우에는 복사용 편집 영역을 남깁니다.
- 현재 기한 계산은 연도까지 명시된 날짜, 기준 상담 날짜가 있는 오늘·내일·모레를 지원합니다. 영업일·불명확한 표현은 자동 계산하지 않습니다. 한국 시간 기준으로 날짜를 계산합니다.

## 입력과 보관 범위

상담당 최대 60개 메시지, 메시지당 6,000자, 합계 40,000자입니다. 붙여넣기 인식은 30,000자까지, 캡처는 PNG/JPEG/WebP 1장·4MB까지 지원합니다. 이미지 원본은 로컬 서버 메모리에서만 읽고 저장하거나 외부 AI에 보내지 않습니다. 음성 입력은 현재 구현하지 않았습니다.

캡처는 Tesseract.js와 설치한 한국어·영어 모델로 읽습니다. 언어 모델만 데이터 디렉터리의 `ocr-models/`에 캐시하며 상담 이미지·텍스트는 OCR 파일로 남기지 않습니다. 엔진 진단 로그도 노출하지 않습니다. 흐린 화면·복잡한 말풍선·작은 글자는 인식 오류가 있을 수 있습니다. 가린 텍스트를 전송 전에 검토하고 발화자는 AI가 정리한 뒤 다시 확인합니다.

마스킹은 한국 전화번호와 도로명·지번 주소의 규칙 기반 탐지입니다. 모든 개인정보·외국 주소·비정형 표기·OCR 오류를 탐지하지 않습니다. 새 상담과 추가 메시지는 가린 텍스트로 저장하며 복원하지 않습니다. 기존 DB의 원문은 자동 변경하지 않고, 기존 기록을 AI에 보낼 때 요청별로 가린 뒤 **로컬에서만** 알려진 표시를 복원해 정확한 원문 인용 검증을 유지합니다. 기존 기록과 그 내보내기에는 과거 개인정보가 남을 수 있습니다.

## 웹 AI 작업 API

- `POST /api/operations`: 클라이언트 UUID `id`, `kind` (`preflight`, `prepare`, `extract`, `analyze`, `draft`), `input`, 필요 시 `caseId`. 202로 접수하고 AI 작업과 상태 조회를 분리합니다. `prepare`는 로컬 읽기·마스킹만 수행하며 AI를 호출하지 않습니다.
- `GET /api/operations/:id`: `state`, 실제 `stage`·`events`, 서버 기준 `elapsedMs`와 완료 결과 또는 오류. 화면은 0.5초 간격으로 확인하며 경과 시간을 표시합니다. 추정 진행률은 사용하지 않습니다.
- `DELETE /api/operations/:id`: AbortController로 AI 요청·응답 읽기 또는 OCR 작업자를 중단합니다. 취소 승인 뒤 결과를 저장하지 않도록 서비스의 호출 전후·저장 전 검사를 적용합니다. 이미 완료됐다면 완료 결과를 반환하며 취소했다고 표시하지 않습니다. 공급자에 이미 전송한 요청의 비용 취소를 보장하지 않습니다.
- 동시 실행은 최대 2건, 전체 작업 제한은 5분, 개별 AI 요청은 90초, 캡처 읽기는 60초입니다. 작업 상태·결과는 메모리에 최대 100건, 완료 후 최대 10분간 보관합니다. 서버 재시작 시 사라지지만 DB 기록은 유지됩니다. 기존 동기 API는 호환성을 유지하며 새 웹 화면이 비동기 API를 사용합니다.
- 연결 장애 때 취소 승인을 받지 못하면 취소 완료로 표시하지 않습니다. 상태를 재확인하며 입력을 유지합니다. 다른 창에서 기록이 바뀌면 저장 시 기존 버전 검사가 적용됩니다.

데이터는 로컬 `data/replytrack.sqlite`에 저장됩니다. 백업할 때는 서버를 종료한 뒤 `data` 폴더를 복사합니다. 앱의 삭제는 원문·분석 기록을 삭제하며 복구 기능은 없습니다. Markdown 내보내기는 확인용 문서이며 복원 파일은 아닙니다. 초안 직접 편집 내용은 `편집 저장`을 눌러 DB에 보관합니다. 저장하지 않은 초안은 화면 이동·새로고침 전에 경고하며, 버전 충돌 시 화면의 편집 내용을 보존합니다.

## 웹 상담 관리 데이터

- `PATCH /api/cases/:id`: `version`과 수정할 `title`(1~100자), `company`(최대 60자), `archived`(불리언)를 받습니다. 보관은 `archivedAt`만 바꾸며 질문·약속·원문·초안을 유지합니다. 기존 레코드에서 필드가 없으면 진행 중으로 취급합니다.
- `PATCH /api/cases/:id/drafts/:kind`: `version`, `body`(공백만 입력 불가, 최대 8,000자)를 받습니다. 생성 결과 `body`와 근거를 보존하고 `editedBody`, `editedAt`을 저장합니다. 사용자 편집은 AI 검증 결과로 취급하지 않습니다.
- 목록 응답의 `deadlines`는 한국 날짜 기준 기한 지남·오늘·예정·미정 개수와 가장 이른 미확인 기한입니다. 원문과 전체 초안은 목록 응답에 포함하지 않습니다.
- 기한 분류·검색·정렬은 `public/workspace.js`의 순수 함수로 검증합니다. DB 목록과 화면은 같은 기한 계산을 공유합니다. 알림 발송이나 백그라운드 예약은 하지 않으며 오래 열린 목록은 `목록 새로고침`으로 갱신합니다.
- 보관·초안 편집 저장 API는 웹에서 사용합니다. 기존 Chrome 확장의 출처 허용 범위는 확대하지 않습니다.

## 검증

```powershell
node scripts/check.mjs
node --test
```

실제 API 검증은 서버를 실행하고 키를 등록한 뒤 **명시적으로** 실행합니다. 가상 상담만 사용하지만 API 사용료가 발생합니다.

```powershell
node scripts/live-check.mjs
```

이 검증은 실제 AI 모드의 가상 상담 한 건을 생성합니다. 화면에서 결과를 검토할 수 있고 상세 결과는 `.artifacts/live-text-result.json`에 기록합니다. Windows에서 `./scripts/make-demo-image.ps1`로 가상 캡처를 만든 뒤 `node scripts/live-check.mjs --image`로 이미지 검증을 실행할 수 있습니다. `.artifacts/synthetic-chat.png`를 화면에 직접 업로드해도 됩니다. 자동 테스트는 실제 API를 호출하지 않습니다.

## 문제 해결

- `node`를 찾지 못함: Node.js 24 이상을 설치하고 터미널을 다시 엽니다.
- `EADDRINUSE`: 해당 포트를 사용 중인 기존 개발 서버를 확인하거나 `.env`의 PORT를 변경합니다.
- API 인증 오류: 키를 연결 설정에서 다시 등록합니다.
- 사용량·결제 한도 오류: OpenAI 프로젝트의 사용량·결제 설정을 확인합니다. 예제는 API 없이 실행 가능합니다.
- API 응답 시간 초과: 90초 제한입니다. 입력을 줄이거나 다시 분석합니다.
- 질문 누락·오인식: 인식 검토 화면과 원문을 대조합니다. 검증은 문자열·출처 확인 수준이며 의미 해석의 정확도를 보장하지 않습니다.
