# ReplyTrack 시연 안내

최신 원본·실제 처리 시간·테스트는 [발표 전 최종 점검](FINAL-CHECK.md), 말할 내용은 [설명 4분 + 시연 30초 대본](PRESENTATION-4MIN-SCRIPT.md)을 사용합니다. 현재 원본의 실제 작업 합계는 150.2초입니다. 30초 구간에는 API 대기를 넣지 않습니다.

## 발표용 실제 AI 결과 30초

1. 서버를 실행한 뒤 **예제 · 도움 기능 → 실제 AI 결과 30초 보기**를 누릅니다. 새 탭의 `/presentation`에서 첫 장면을 준비합니다.
2. “가상 이메일로 사전 실행한 실제 AI 결과를 재생합니다”라고 소개하고, 문의 등록 → 설명과 할 일 → 영어 재문의 → 새 답변 비교를 순서대로 보여 줍니다. 아래 표의 0–6 / 6–14 / 14–21 / 21–30초 대본을 그대로 활용할 수 있습니다.
3. 시간 밖의 질문에는 원문 대조와 하단 실행 근거를 펼칩니다. 모델, 기록 시각, 작업 시간 합계, 원본 파일·해시와 결과 JSON이 있습니다.
4. 처음부터 버튼으로 다시 시작할 수 있습니다. 방향키와 버튼을 지원하며 재생 중 AI 호출·저장·자동 발송은 없습니다. 실제 문의 등록은 원래 상담 화면에서 진행합니다.

발표용 결과는 실제 API 입력·초기 할 일·초안·후속 분석·갱신된 할 일을 한 번의 검증된 기록에서 가져옵니다. 5분 전체 대본은 [PRESENTATION.md](PRESENTATION.md), 실행·브라우저 검사 근거는 [PRESENTATION-READINESS.md](PRESENTATION-READINESS.md)를 참고합니다.

아래 체험용 예제와 발표용 실제 AI 결과는 서로 구분합니다.

## 체험용 이메일 예제

서버 실행 후 **예제 · 도움 기능 → 이메일 예제 체험**을 누릅니다. 네 장면을 전용 화면에서 순서대로 보여 줍니다. 화면의 “준비된 결과 · AI API 호출 없음” 표시를 유지합니다. 새 답변은 한 번만 추가되며 앞 장면으로 돌아가도 중복 등록되지 않습니다.

| 시간 | 화면 조작 | 발표 대본 |
| --- | --- | --- |
| 0~6초 | 영어 문의·답변 | “바쁜 일상에 영어 답변까지 오면 필요한 자료와 남은 질문을 놓치기 쉽습니다.” |
| 6~14초 | 한국어 설명·할 일 보기 | “거래 번호를 보내야 하고, 비밀번호는 보내면 안 됩니다. 검토 기간은 아직 모릅니다.” |
| 14~21초 | 영어 재문의 보기 → 영어 초안 복사 | “남은 기간 질문만 영어로 다시 물을 수 있습니다.” |
| 21~30초 | 준비된 새 답변 반영 | “새 답변을 받자 기간 질문이 해결됐습니다. 하지만 답변을 받았다고 계정이 복구된 건 아닙니다.” |

처음에는 필요한 자료가 답변 받음, 검토 기간이 부분 답변입니다. 이후 거래 번호 수신과 검토 3영업일 안내가 추가되고 기간 질문만 답변 받음으로 바뀝니다. 제출 요청은 업체 수신 안내로 바뀌지만 사용자의 직접 수행·실제 복구 확인을 자동 체크하지 않습니다. 근거 원문을 클릭하면 해당 영어 답변을 열 수 있습니다. 마지막의 상담 전체 화면 보기로 기존 질문·약속·원문 화면도 확인할 수 있습니다.

30초는 발표 대본의 목표 시간입니다. 실제 모델 지연을 숨긴 기록이 아니며, 브라우저 화면 전환 시간도 AI 응답 시간으로 제시하지 않습니다. 실제 입력·생성 결과를 보여 주려면 발표 전에 새 상담으로 생성한 별도 기록을 준비하고, 준비된 결과임을 설명합니다.

### 실제 이메일 기능을 보여 줄 때

1. 새 상담 → 문의 유형 이메일 → 본문 붙여넣기 또는 캡처 업로드 → 개인정보·발신자·원문 검토 → 저장하고 질문 분석하기.
2. 한국어 설명 보기와 업체 요청 확인하기로 원문에 있는 요구·조건을 확인합니다.
3. 남은 질문을 선택하고 영어 재문의 초안을 생성·검토한 뒤 복사합니다. 앱이 이메일을 자동 발송하지 않습니다.
4. 새 답변을 붙여넣고 중복 인용·발신자를 확인합니다. 분석 전후 비교와 한국어 설명 갱신을 보여 줍니다.

실제 입력은 검토 단계와 API 대기 시간이 필요하므로 30초 발표 흐름과 분리합니다. [이메일 기능 검증](EMAIL-INQUIRIES-VALIDATION.md), [전체 회귀와 발표 화면 검증](EMAIL-REGRESSION-DEMO.md)에 테스트 범위를 기록합니다.

## 추가 환불 예제

첫 화면의 예제 상담 열기는 기존 환불 사례를 유지합니다. 사진 제출 요청 → 수행 표시 → 예제 답변 추가 → 질문·약속 비교 → 환불 안내와 실제 결과 직접 확인을 체험할 수 있습니다. 발표의 필수 네 장면에는 포함하지 않습니다.

## 실제 AI 시연

1. 최초 실행 전에 `npm ci`로 로컬 OCR을 설치합니다. API 키를 서버 메모리나 로컬 `.env`로 설정하고 `AI 연결 설정` → `저장하고 연결 점검`에서 통과를 확인합니다. 발표 화면에 키를 노출하지 않습니다.
2. `새 상담 시작하기`에서 아래 가상 대화를 붙여넣습니다.
3. `개인정보 가리고 확인`에서 전화번호·주소가 가려진 미리보기를 확인합니다. 캡처도 로컬에서 읽으며 이 단계까지 외부 AI에 보내지 않습니다. `확인한 내용으로 AI 대화 읽기` 뒤 발화자·원문을 확인합니다.
4. `저장하고 질문 분석하기`를 누릅니다. 실제 처리 단계·경과 시간 이후 질문별 근거와 상태를 확인합니다. 긴 작업에서 `작업 취소` 후 입력·기존 기록이 유지되고 재시도할 수 있음을 보여 줄 수 있습니다.
5. 질문 확인표 상단에서 `업체 요청 확인하기`를 눌러 사진 제출 요청·조건·수행 기한을 확인합니다. 별도 생성·검토 단계와 취소를 지원합니다. `이 질문 재문의`로 필요한 질문만 선택해 초안을 생성합니다.
6. `새 답변 / 질문 추가`로 후속 답변을 넣고 질문 상태·처리 약속을 확인합니다. 업체 요청은 이전 원문 기준이라고 표시되며 `업체 요청 다시 확인`으로 이후 수신·철회 안내를 반영합니다.

```text
나: 이어폰이 작동하지 않아 반품하고 싶습니다. 환불 금액은 얼마인가요? 반품 입고 후 환불은 며칠 걸리나요? 반품 배송비는 누가 부담하나요?
고객센터: 반품 입고 후 환불은 3~5영업일 정도 소요됩니다. 환불 금액은 검수 후 안내하겠습니다. 내일까지 불량 사진을 보내 주세요.
```

후속 답변:

```text
보내 주신 불량 사진을 확인했습니다. 반품 배송비는 업체에서 부담하며, 내일까지 환불 금액을 안내하겠습니다.
```

`내일까지`를 날짜로 보여 주려면 **실제 상담 날짜**를 입력합니다. 날짜를 입력하지 않으면 기한 미정으로 남는 것이 정상입니다. 실제 API는 응답 시간이 일정하지 않으므로 발표 직전에 한 번 실행하고, 대기 시간을 포함해 시연 길이를 조정합니다.

## 추가로 보여 줄 수 있는 차별점

- `내 문의함` → 제목·문의처 검색, 남은 질문·기한 확인 필터로 다음 할 일을 찾습니다.
- 초안을 편집하고 `편집 저장` → 새로고침 → `답장 작성`에서 저장한 문장이 남아 있는 것을 보여 줍니다. 편집 전 생성 결과도 펼쳐 볼 수 있습니다.
- `문의 관리` → 보관함으로 이동 → 내 문의함의 보관함에서 열고 복원합니다. 질문·약속 상태는 바뀌지 않습니다.

편집한 초안이 있는 상태에서 새 답변 추가·질문 상태 수정 등으로 넘어가면 안내가 나옵니다. 추가 답변 분석을 취소하거나 실패하면 이전 초안과 편집 중인 내용도 남습니다. 새 분석이 성공하면 이전 초안이 초기화되므로 필요한 문장을 먼저 복사하거나 내려받습니다.

- 질문 판정을 직접 수정한 후 새 답변 추가 → 사용자 수정은 유지되고 새 AI 제안은 별도로 표시됩니다.
- 업체의 “안내 완료” 답변 → 사용자가 실제로 확인하기 전까지 처리 확인 필요로 남습니다.
- 변경 이력 → `반영 전후 비교 보기`를 펼쳐 이전 답변의 질문 상태와 약속 변경을 다시 확인합니다. 최신 비교와 과거 비교는 각각의 분석 당시 기록입니다.
- 모바일 원문/확인표 전환 → 작은 화면에서도 근거를 읽을 수 있습니다.
- 캡처 업로드 → 이미지 인식 결과를 저장 전에 확인·수정합니다.
