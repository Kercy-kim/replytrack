# 이메일 문의 구현·검증 기록

2026-11-15. 가상 계정 복구·결제 문의를 사용했다. 실제 사용자의 메일함·계정에 접근하거나 메일을 발송하지 않았다.

## 구현

- 신규 상담의 `이메일 문의` 유형: 본문 붙여넣기 또는 PNG/JPEG/WebP 캡처 한 장(4MB 이하), 전송 전 가림과 원문 검토.
- 캡처 언어 선택: 영어 또는 한국어·영어 혼합. 실제 로컬 Tesseract OCR이며 이미지 원본은 AI에 보내지 않는다.
- 헤더·발신자·날짜·인용 대화 정리. 확실하지 않은 발신자는 사용자가 지정하며, 시간대가 불명확하면 날짜를 추정하지 않는다. 동일 발언 중복은 정리하고 서로 다른 명시적 날짜의 발언은 보존한다.
- `한국어 설명 보기`: 각 고객센터 답변의 원문과 한국어 설명. 원문 전체 일치 검사와 별도 AI 의미 검토를 통과한 결과만 저장한다.
- 재문의 언어 선택: 이메일 기본 영어, 한국어 선택 가능. 기존 선택 질문·원문 근거·생성 후 의미 검토·최대 한 번 수정 절차를 유지한다. 직접 수정·저장·복사하며 자동 발송하지 않는다.
- 같은 기록에 새 이메일을 검토 후 일괄 저장하고 기존 질문·약속 분석 및 전후 비교에 연결한다. 한국어 설명과 업체 요청은 이전 답변 기준임을 표시하고 각각 다시 확인할 수 있다.

## 자동·브라우저 검증

- 전체 자동 테스트 **191개 통과**. 새 8개 테스트는 원문 변조·중복·발신 역할, 설명 누락·의미 검토 실패·취소·동시 수정, 이메일 일괄 저장의 원자성, 영어 생성/검토, HTTP 작업과 버전 검사, OCR 언어 전달을 검증한다.
- `node scripts/check.mjs`: JavaScript 문법 검사 통과. 최종 파일 수는 실행 결과를 기준으로 한다.
- `scripts/check-email-browser.mjs`: 실제 Chrome, 데스크톱 1440px·모바일 390px에서 본문 등록→한국어 설명→영어 초안→새 답변→상태 비교→이전 설명 표시→설명 갱신→새로고침 후 보존을 확인했다. 별도 이메일 캡처를 실제 로컬 OCR로 읽고 같은 등록·설명 흐름을 통과했다. 가로 넘침·페이지 오류가 없었다. AI 응답은 이 브라우저 검사에 한해 결정적 테스트 응답이다.
- 기존 `scripts/check-web-operations.mjs`의 5개 브라우저 시나리오도 통과했다. 기존 입력·연결·취소·편집 초안 보존·한국어/영어 OCR·개인정보 가림을 포함한다.
- 화면은 기존 DESIGN.md의 색·입력·버튼·패널 구성을 사용했다. 데스크톱·모바일 스크린샷을 직접 확인했으며 새로운 디자인 시스템이나 이미지 자산은 추가하지 않았다. 실행 산출물은 `.artifacts/email-browser/`와 `.artifacts/web-operations/`에 둔다.

## 실제 OpenAI API 검증

모델은 로컬 설정의 `gpt-5-mini`이며 평가 응답에는 실제 모델 식별자와 사용량을 기록했다. 재현 도구는 `scripts/evaluate-email.mjs`, `scripts/evaluate-email-reviews.mjs`, `scripts/evaluate-email-boundaries.mjs`, `scripts/recheck-email-actions.mjs`다. `--run`으로 명시적으로 실행하고 키는 로컬 `.env`에서 읽으며 출력·커밋하지 않는다. 보고서에는 가상 원문과 AI 응답만 포함한다.

| 사례 | 최초 상태 | 새 답변 이후 | 확인한 내용 |
| --- | --- | --- | --- |
| 계정 복구 | 제출 자료: 답변 받음 / 검토 기간: 부분 답변 | 두 질문 모두 답변 받음 | 거래 번호 요청, 비밀번호·인증 코드 제출 금지, 검토 후 안내, 수신 안내와 실제 복구 미완료 구분 |
| 결제 중복 문의 | 환불 대상: 부분 답변 / 캡처 필요 여부: 답변 받음 | 두 질문 모두 답변 받음 | 중복 청구 확인 조건, 선택적 캡처, 카드 번호 제외, 거래 번호 확인 후 환불이라는 조건 보존 |

핵심 흐름 결과는 [계정 복구](../evals/results/email-inquiries/account-complete.json)와 [결제 문의](../evals/results/email-inquiries/billing-final.json)에 있다. 결제 문의 보고서는 마지막 할 일 검토 단계에서 실패한 중간 기록도 포함한다. 해당 단계의 수정 후 [할 일 재평가 2/2건](../evals/results/email-inquiries/actions-final.json)은 별도로 보존한다. 앞선 흐름을 다시 호출한 결과로 바꾸어 표현하지 않는다.

[최종 경계 대조 5/5건](../evals/results/email-inquiries/boundaries-final.json)은 제출 대상 안내를 답변 받음으로 판정하고, 일부 자료의 필요 여부가 미정이면 미해결을 유지하는지 확인했다. 대상 수식어·업체 처리 조건을 사용자 선행 조건으로 오인하지 않으면서 실제 사용자 선행 조건이 빠진 목록은 거절하는 것도 통과했다. 따라서 두 핵심 흐름과 수정한 할 일 단계, 한국어 설명 대조 4건, 판정·조건 대조 5건이 최종 통과했다.

[한국어 설명 대조 검증](../evals/results/email-inquiries/review-controls.json)은 정상 설명 1개 승인, 부정 반전·근거 없는 복구 완료·기한 추가 3개 거절을 확인했다. 같은 도구에서 실제 영어 캡처의 로컬 OCR 결과를 실제 AI로 읽고 발신자와 영어 원문 보존을 확인했다.

## 발견한 문제와 수정

1. **영어 캡처 인식 오류:** 기존 `kor+eng` 설정이 영어 캡처의 글자를 심하게 오인했다. 사용자가 캡처 언어를 선택하고 이메일에서 영어를 기본값으로 사용하도록 수정했다. 기존 일반 상담의 혼합 언어 경로도 브라우저 회귀로 확인했다.
2. **근거 없는 추가 서류 추정:** 구체적인 제출 자료를 안내했는데 “다른 서류가 있는지 모른다”는 이유로 부분 답변으로 낮추는 응답이 있었다. 이메일 분석 지침에 질문에서 요구한 범위만 판정하고 원문에 없는 누락을 추가하지 않도록 명시했다.
3. **제출 대상과 조건 혼동:** 영수증의 번호라는 대상 설명을 선행 조건으로 오인하거나, 사용자가 번호를 확인하면 업체가 처리한다는 문장에서 업체 처리 조건을 사용자 행동의 조건으로 뒤집어 정상 목록을 거절했다. 이메일 생성·검토에 대상·행동 주체·실제 선행 조건의 구분을 함께 적용했다. 실제 조건을 빠뜨린 목록은 계속 거절하도록 대조 평가한다.

처음 정답표에는 계정 복구 검토 기간을 미답변으로 둔 오류가 있었다. “거래 번호 확인 후 검토”라는 관련 절차 안내가 있으므로 기존 기준에 따라 부분 답변으로 바로잡았으며, 추가 자료를 안내받은 질문은 답변 받음으로 정했다. [초기 기록](../evals/results/email-inquiries/initial.json), [중간 검토 실패](../evals/results/email-inquiries/account-final.json), [중간 판정·발신자 결과](../evals/results/email-inquiries/final.json)를 보존했다. 발신자 `unknown`은 잘못된 확정 판정이 아니라 사용자 검토가 필요한 정상 결과이므로 평가도 검토 단계에서 정답 발신자를 선택하도록 보완했다.

## 범위와 한계

두 개의 가상 이메일과 제한된 대조 사례는 전체 이메일·계정 복구 정확도를 입증하지 않는다. 정답표·설명·영어 초안 대조와 화면 확인은 개발 에이전트가 수행했으며 외부 사람 검수나 실제 사용자 평가는 아니다. 기존 일반 상담 프롬프트는 유지했으며 이번에 기존 배송·환불·구독 48건의 유료 전체 재평가를 반복하지 않았다.

사진·복잡한 이메일 화면·저해상도 캡처는 OCR 오류가 남을 수 있다. 캡처는 한 번에 한 장이며 읽은 원문을 수정하거나 본문 붙여넣기를 사용할 수 있다. 메일함 자동 연동·첨부 내용 분석·임의 답장 의도 입력·자동 전송은 없다. 영어 답장은 현재 선택한 미해결 질문의 재문의이며 모든 질문에 답변받은 뒤 자유 형식의 답장을 생성하는 기능은 아니다. 계정 복구 자체를 실행하거나 실제 전달·로그인 성공을 자동 확인하지 않는다.
