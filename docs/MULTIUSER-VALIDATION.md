# 개인 계정·PostgreSQL 검증

2026-11-17. 기존 AI 프롬프트·스키마·판정 로직을 바꾸지 않고 저장소·인증·작업 스케줄링을 변경했다.

이 문서는 개인 계정 도입 당시의 검증 기록이다. 이후 사용자 요청으로 일일 AI 횟수 제한을 제거했다. 현재 동작과 제한 제거 후 테스트는 [최종 운영 점검](FINAL-PILOT-CHECK.md)을 따른다.

## 자동 검증

- 전체 자동 테스트 283개와 JavaScript 149개 파일 문법 검사 통과.
- 기존 테스트 277개 통과. 비동기 저장소 조회 뒤 모델 호출이 시작되는 시점에 맞춰 취소/충돌 테스트 4개의 대기만 보완했다.
- PostgreSQL WASM 엔진(PGlite)에서 운영 SQL을 실행해 가입 10명 제한, 초대 코드 중복 사용 차단, 서로 다른 비밀번호 솔트, 세션 해시·만료·로그아웃, 계정 초기화 재실행 후 기존 암호 보존을 확인했다.
- 서로 다른 계정의 문의 조회·수정·삭제·질문·약속·할 일·초안·공식 안내 접근은 404. 설정 변경·초대 코드 발급·예제 생성은 참여자에게 403. 외부/누락 Origin의 변경 요청을 차단했다.
- 같은 버전의 수정 2개 중 1개만 성공. 초기 일일 제한 검증에서는 병렬 사용량 예약 10개 중 허용량 2개만 성공했다. 이 횟수 제한은 후속 변경에서 제거했다.
- 10개 계정의 HTTP 작업을 동시에 접수해 전체 실행 작업 최대 2개, 결과 10개 분리, 다른 계정의 진행 조회·취소 차단을 확인했다. OCR은 동시에 하나만 실행한다.
- 비동기 DB 저장을 시작한 뒤 취소가 도착하면 취소 완료라고 잘못 표시하지 않고 실제 저장 결과를 반환한다.
- 공식 안내 3개가 동시에 접수될 때 실행한 2개만 사용량에 포함하고, 동시 처리 한도로 생략한 1개와 캐시 재조회는 차감하지 않는 HTTP 회귀를 추가했다(PGlite 실행).
- PGlite는 단일 연결을 직렬화한다. 실제 PostgreSQL 네트워크·다중 연결 검증과 구분한다.

## 실제 Render PostgreSQL

Singapore Free PostgreSQL 18의 별도 임시 스키마에서 위 신규 테스트 6개를 실제 `pg.Pool` 연결로 재실행해 통과했다. 시험 스키마는 종료 시 제거했으며 운영 `public` 영역에 시험 계정이나 문의를 만들지 않았다. 첫 실행의 고정 35ms AI 응답은 DB 왕복 시간보다 짧아 실행 겹침을 재현하지 못했다. 두 요청이 도착할 때까지 응답을 기다리도록 시험을 보완한 뒤 동시 실행 최대 2개를 확인했다.

DB는 2026-11-17 생성됐으며 Render 화면에 표시된 만료일은 2026-12-17이다.

## 실제 OpenAI API

3개 계정의 배송·환불·구독 상담을 동시에 실행했다. 개인정보 가림 → 본문 발화자 추출 → 문의 생성 → 최초 분석 → 새 답변 저장·분석 → 재문의 생성 전체 흐름을 확인했다. `gpt-5-mini` 사용. 아래 시간은 대기열과 0.6초 간격의 상태 확인을 포함한다.

| 사례 | 본문 정리 | 최초 분석 | 새 답변 분석 | 재문의 초안 |
| --- | ---: | ---: | ---: | ---: |
| 배송 날짜·추가 배송비 | 12.2초 | 15.8초 | 32.1초 | 12.1초 |
| 환불 금액·입금일 | 7.3초 | 9.7초 | 19.4초 | 12.7초 |
| 구독 해지·다음 청구 | 9.7초 | 15.8초 | 11.5초 | 23.6초 |

도착 날짜·환불 금액·해지 완료는 새 답변 이후 답변 받음으로 바뀌었다. 아직 답변이 부족한 배송비·입금일·다음 달 청구만 초안에 포함됐다. 이미 답변받은 항목을 다시 묻지 않았다. 각 계정 목록에는 자기 문의 1개만 저장됐다.

이 결과는 가상 상담 3건의 연결·저장 회귀 확인이며 전체 AI 정확도, 10명 실제 동시 AI 응답 시간이나 비용의 보증은 아니다. 10명 동시 요청 시험은 별도의 고정 AI 응답을 사용했다.

## 운영 사이트 검증

PR #44의 main `7d4fe92`를 Render에 배포해 2026-11-17 01:07 KST Live를 확인했다. 웹 서비스는 무료, PostgreSQL은 Singapore Free 1GB다. DB 외부 접근 차단은 별도 사용자 승인 후 적용했으며, 외부 허용 IP 0개와 내부 DB 연결을 확인했다. 임시 외부 연결 파일은 제거했다.

https://replytrack.onrender.com 에서 기존 관리자 비밀번호로 새 HTML 로그인에 성공했다. 운영 UI에서 가상 환불 문의 등록 → 개인정보 가림 검토 → 실제 OpenAI 본문 정리·최초 분석 → 새 답변 저장·분석 → 재문의 생성을 직접 실행했다. 두 질문이 미답변인 상태에서 42,000원 답변을 추가하자 금액 질문만 답변 받음으로 바뀌었으며 입금 시점은 미답변으로 유지됐다. 초안은 “환불금의 입금 예정일을 알려주시겠습니까?”로 저장됐다. 관리자 계정에 `[운영 점검] 환불 금액과 입금일`이라는 가상 문의 1건을 남겼다.

비로그인 `/api/cases`는 401, `/api/auth/me`는 개인 로그인 사용 여부와 `user:null`, `/api/health`는 200으로 응답했다. 이 운영 흐름은 실제 Render PostgreSQL과 OpenAI를 함께 사용한다. 최종 재배포 후 로그인 세션·저장 기록 유지 여부도 별도 확인한다.
