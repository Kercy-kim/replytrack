# 등록·분석과 새 답변 반영 재점검

2026-11-16. 기준 main: `e0850338787af69cea001b6222bbf8eaba72d03a`.
모델: `gpt-5-mini-2025-08-07`. 사용자 기록 대신 가상 상담과 별도 메모리 DB를 사용했다.

## 느린 부분과 변경

기준 웹 흐름에서 환불 문의의 분석은 23.611초, 새 답변 분석은 29.966초였다. 본문 읽기·연결 점검·브라우저 대기를 포함한 등록은 29.846초였다. 같은 API 요청도 반복 실행에서 시간이 달라지므로 단일 측정만으로 원인을 공급자 대기·추론·네트워크 중 하나로 확정하지 않았다.

- 실제 재문의 화면이 사용하지 않는 질문별 `followUp`을 일반 상담 분석과 답변 추가 출력에서 제외했다. 재문의 생성·독립 검토 기능은 유지한다.
- 업체 답변만 추가되면 일반 상담도 질문 제목·질문 원문·ID를 그대로 보존하고 변경되는 상태·설명·근거·약속만 출력하도록 했다. 원문 대화나 기존 약속을 입력에서 잘라내지는 않는다.
- 짧은 첫 상담과 단순 답변 추가에 빠른 추론을 사용한다. 정정·철회·조건·긴 대화는 정밀 추론을 유지한다.
- 빠른 결과에서 향후 안내 약속을 이미 받은 답으로 취급할 가능성이 있으면 기존 한 번의 정밀 재검토를 사용한다. 완료된 과거 약속을 함께 인용했다는 이유만으로 재검토하지 않는다.
- 초기 이메일에서 “다른 자료가 더 필요할 수 있다”는 원문 밖 추정으로 부분 답변이 되는 기존 변동을 발견했다. 이런 누락 사유만 정밀 재검토한다. 실제로 요청한 정보가 빠졌다면 미해결로 유지한다. 첫 이메일 요청의 스키마·프롬프트·입력·추론량은 기준 main과 동일함을 오프라인 캡처로 확인했다.
- 실제 웹 출력의 직접 검토에서 일반 심사 기간을 독립 약속으로 만든 오류가 남아 있었다. 기간 안내만인 경우와 별도 업무 확약이 있는 경우를 정밀 재검토하도록 보완하고, 웹 테스트도 자료 수신 통보 1개·기한 없음·정확한 원문을 확인하도록 강화했다.

적용 경계와 오류·취소·버전 보호는 [ADR 0025](adr/0025-compact-analysis-with-selective-review.md)를 따른다. 모델 교체, 검증 생략, 재문의 기능 제거는 하지 않았다.

## 측정 방법

`scripts/benchmark-registration.mjs`는 기준 main의 별도 고정 worktree와 현재 코드를 같은 프로세스에서 비교한다. 정정(S06), 기한 철회(R03), 배송 위치(NS03), 불명확한 구독 상태(NU02), 환불 세 질문, 영어 계정 복구의 6사례를 각 2회 실행한다. 사례·반복별 전후 순서를 번갈아 배치하고 작업자 2개를 사용한다. 각 버전은 초기 분석 12회·답변 추가 분석 10회다.

분석 시간은 서비스 호출부터 근거 검사·필요한 수정/의미 검토·저장까지다. 이미 나뉜 메시지를 입력하므로 붙여넣은 본문 읽기와 연결 점검은 이 수치에 포함하지 않는다. 실제 Chrome 흐름은 별도 측정한다. 이 작은 표본의 중앙값·최댓값은 운영 환경의 지연 보증이나 p95가 아니다.

**대표적인 대기 시간은 줄었지만 긴 지연의 상한은 개선했다고 말할 수 없다.** 정정·기한 철회와 재검토 사례는 여전히 느릴 수 있다. 확인된 토큰 합계는 기준 153,679, 후보 157,037이며 후보의 보조 요청 2개는 사용량 미확인이다. 출력 축소가 총비용 절감을 입증한 것은 아니며, 총토큰·비용 절감률을 제시하지 않는다.

48건의 상태·설명·약속 출력도 직접 읽었다. 위 수치는 고정된 가상 사례의 결과이며 실제 사용자 정확도를 뜻하지 않는다. 48건 실행은 분석 전용이며 재문의는 별도 실제 웹 흐름에서 확인한다. 공식 안내의 실시간 외부 페이지·실제 메일함 연동·새 OCR 품질 평가는 이번 속도 작업의 범위가 아니다.

마지막 코드 점검에서 `번복`, `changed`, `retract`, `incorrect` 등 정정 표현도 빠른 경로를 타지 않도록 조건을 보강했다. 실제 API 평가의 원본 코드 해시는 그대로 보존한다. 보강 전후로 회귀·비교 측정 입력 117개의 추론량·적용 여부·출력 스키마·지시가 동일함을 확인한 결과는 `routing-parity.json`에 있다. 추가 표현 대조와 전체 로컬 검사는 보강 후 다시 실행했다.

최종 웹 검토 뒤 추가한 이메일 기간 약속 재검토는 위 교차 측정 후보의 모든 첫 분석·수정 원본에서 발동하지 않음을 `duration-guard-audit.json`으로 확인했다. 배송·환불·구독 48건은 이메일 전용 조건의 대상이 아니다. 이 마지막 보완 뒤 영어 20건과 실제 웹을 재실행해 통과했고, 관측 오판 재생/실제 개별 확약 2개 대조도 통과했다. 비교 측정 코드 해시를 최종 코드 해시로 덮어쓰지 않는다.

## 실패 후보와 채점 보정 기록

- `paired.json`: 출력 축소만으로는 중앙값이 개선되지 않았다. 전후 초기 분석 14.221→15.610초, 답변 반영 17.374→21.212초. 채택하지 않았다.
- `paired-routed.json`: 일반 상담의 저장 유형이 생략되는 구조를 빠른 경로가 처리하지 못했다. 이를 실제 저장 형태의 테스트와 함께 수정했다. 전후 답변 중앙값 15.694→22.697초였으며 개선 근거로 사용하지 않는다.
- `paired-guarded.json`: 빠른 첫 분석과 정밀 재검토 후보. 완료된 과거 안내 인용 때문에 불필요하게 재검토했고, 기존 초기 이메일의 추가 서류 추정도 남아 있었다. 최종 후보에서 이 두 범위를 보완했다. 해당 실행 후반은 별도 품질 평가와 겹쳤으므로 최종 성능 수치로 사용하지 않는다.
- 실험 중 기준 main에서도 필요한 자료를 부분 답변/미답변으로 낮추거나 일반 심사 기간을 별도 약속으로 만드는 변동이 관측됐다. 실패 원본은 삭제하거나 성공 결과로 덮어쓰지 않는다.
- 새 벤치마크의 채점에서 새 수신 통보에도 기존 약속 ID를 요구한 부분, 내용과 기한이 그대로 반복된 약속의 인용 위치, 동일 질문 제목의 동의어를 보정했다. 기존 48건의 기대 상태·근거·약속은 변경하지 않았다. `*-summary.json`은 원본 SHA와 보정 내역을 기록하며 실제 의미 오류는 계속 실패로 남긴다.
- 이메일 복구 대조는 처음에 합쳐진 한 질문의 partial만 허용했지만, 전체 재분석이 거래 ID answered와 신분증 사진 unanswered로 정확히 분리했다. 원본 실패와 두 출력이 남아 있으며 `email-scope-repair-review.json`에 이 채점 범위 보정을 별도로 기록했다. 이 실험은 첫 결과를 재생한 복구 검사이지 처음부터 실제 AI가 처리한 정확도나 속도 측정이 아니다.
- `browser-after.json`의 당시 기능 검사는 통과했지만 출력 직접 검토에서 심사 기간의 추가 약속을 발견했다. `browser-after-review.json`에 의미 오류를 기록했으며 이 실행을 최종 품질 통과로 계산하지 않는다. 수정 후 강화한 웹 검사는 별도 결과로 보존한다.

## 증거와 재실행

원본과 요약은 [평가 결과 폴더](../evals/results/registration-latency/)에 보존한다. 실제 API 재실행은 로컬 `.env`가 필요하며 비용이 발생한다.

```powershell
git worktree add --detach .artifacts/registration-baseline-e085033 e085033
node --env-file=.env scripts/benchmark-registration.mjs --run --out=.artifacts/registration-repeat.json --repeats=2
node scripts/summarize-registration.mjs .artifacts/registration-repeat.json .artifacts/registration-repeat-summary.json
node --env-file=.env scripts/evaluate-ai.mjs --suite full --analysis-only --out .artifacts/registration-quality-repeat.json
npm test
npm run check
npm run test:web
```

기존 경로에 결과 파일이 있으면 새 경로를 지정한다. Chrome 검사는 설치된 Playwright 모듈과 Chrome 경로 환경변수가 필요하다. 취소된 지연 보조 요청도 과금될 수 있어 사용량을 알 수 없는 요청이 있으면 전체 토큰·비용 절감률을 계산하지 않는다. 검사·수정이 추가되는 사례는 느려질 수 있으며 모든 요청의 최대 완료 시간을 보장하지 않는다.
