# 과제 발표 준비 검증

날짜: 2026-11-15. 기준 main: `72ed49a`. 사용자 자료의 요구사항은 최대 5분 발표(30초 시연 포함), 핵심 기능·구현 결과 중심, 문제·목적·사용자·핵심 기능 3개 이상·AI 역할·입력→처리→출력이다.

이 문서는 최초 시연의 역사적 기록이다. 2026-11-16 갱신한 시연 원본·최신 테스트·발표 전 준비는 [마무리 점검](FINAL-CHECK.md)을 따른다. 아래 160.4초와 202개는 최초 기록의 수치이며 최신 결과와 섞지 않는다.

## 보완한 내용

- README의 핵심 기능을 질문별 상태 / 지금 내가 할 일 / 한국어 설명·영어 재문의 / 새 답변 비교의 네 가지로 정리했다. 이메일·계정 복구는 경로·활용 사례로 설명하고, SSG·인계·확장 프로그램은 보조 기능으로 남겼다.
- [5분 발표 대본](PRESENTATION.md)에 사진의 각 요구 항목과 실제 구현을 대응시켰다. 4분 40초 설명·시연에 20초 여유를 배정했다. 30초 시연은 이 시간 안에 포함된다. 발표자 말속도는 실제 리허설이 필요하다.
- `/presentation`에 사전 실행한 **실제 OpenAI 결과 재생**을 추가했다. 원문, AI 한국어 설명, 실제 업체 요청, 실제 영어 초안, 질문 상태·자료 수신 변화를 한 기록에서 가져온다. 기존 준비된 예제는 `이메일 예제 체험`으로 구분한다.
- 모든 장면에 가상 입력·사전 실행·현재 API 호출 없음 표시를 유지한다. 실제 모델·기록 시각·작업 시간·원본 파일·SHA-256과 결과 JSON을 제공한다.
- 1280×720 화면에서 다음 버튼이 밀리던 영어 초안 영역의 높이를 조정했다. 화면을 다시 열거나 처음부터를 눌러도 API 호출·상담 데이터 생성이 없다.

## 실제 API 실행

원본: [recording.json](../evals/results/presentation/recording.json). 입력은 기존 합성 계정 복구 이메일이며 실제 개인정보나 서비스 정책이 아니다. 모델은 `gpt-5-mini-2025-08-07`이다.

| 단계 | 확인 결과 |
| --- | --- |
| 본문 추출·발신자 검토 | 질문·답변 내용 보존. 발신 역할은 가상 자료에 맞게 사용자 검토 단계에서 확정 |
| 초기 질문 분석 | 자료 질문 답변 받음, 검토 기간 부분 답변 |
| 한국어 설명 | 영수증의 거래 ID, 비밀번호·인증 코드 금지, 거래 ID 확인 후 검토를 보존 |
| 초기 업체 요청 | 구매 영수증의 거래 ID 제출 1건, 조건·기한 추측 없음, 직접 수행 미확인 |
| 영어 재문의 | 검토 기간만 묻는 영어 초안 생성·검토 통과 |
| 후속 이메일·재분석 | 같은 질문 ID 유지, 검토 기간이 부분 답변→답변 받음 |
| 설명 갱신·업체 요청 갱신 | 3영업일, 아직 복구 전, 검토 후 연락을 보존. 자료 제출 요청은 업체 수신 안내로 변경 |
| 실제 결과 확인 | AI가 직접 수행·계정 복구 확인 완료를 설정하지 않음 |

API 14회, 위 작업 시간 합계 **160,441ms(약 160.4초)**였다. 30초는 결과를 설명하는 재생 시간이며 이 처리 시간을 숨겨 실시간 성능으로 주장하지 않는다. 비교 자체는 기존 일반 코드로 계산한다. 설명·초안 원문은 다듬거나 다른 실행의 좋은 문장으로 교체하지 않았다. 한국어 설명의 문장 길이·표현 편차는 남을 수 있다.

## 원본과 표시 결과의 일치

`scripts/build-presentation.mjs`는 검증을 통과한 지정 합성 사례만 내보낸다. 입력 전체, 질문 ID·상태, 초기·후속 요청 상태, 실제 원문 인용, 한국어 설명, 초안, 변경 비교를 검사한다. 완료 표시가 없는지도 확인한다. 원본 질문·설명·초안 텍스트를 그대로 `public/presentation-data.json`에 저장한다.

`tests/presentation.test.mjs`는 배포되는 JSON이 검증된 원본에서 생성한 결과와 완전히 같은지 확인한다. 미완료·비합성·다른 입력·변조한 ID·거짓 비교·존재하지 않는 인용은 내보내기를 거절한다. 화면은 AI 출력과 원본 경로를 HTML escape한다. 원본 파일의 바이트 해시 보존을 위해 해당 JSON의 줄바꿈은 LF로 고정한다.

## 자동·브라우저 검사

| 검사 | 결과 |
| --- | --- |
| 전체 Node 테스트 | **202개 통과** |
| JavaScript 문법 검사 | **105개 파일 통과** |
| 실제 결과 재생 Chrome | **통과**: 1280×720 네 장면·원문·복사·키보드·처음부터·새로고침·오류 후 재시도 |
| 모바일 Chrome | **통과**: 390px 네 장면, 가로 넘침 없음 |
| 재생 부작용 검사 | **통과**: AI 호출 0회, 상담 기록 생성 0건 |
| 기존 이메일 예제 | **통과**: 네 장면, 중복 답변 방지, 원문, 전체 보기 |
| 기존 실제 입력 UI | **통과**: 본문·실제 로컬 OCR, 한국어 설명, 영어 초안, 후속 답변, 갱신·새로고침·모바일. AI 전송은 테스트 응답 |
| 기존 48건 평가 | 저장된 실제 API 출력을 **오프라인 재채점**해 48/48, 질문 71/71, 약속·기한 22/22 확인 |

이번에는 공통 분석·영어·업체 요청·검토 프롬프트와 실제 상담 서비스 코드를 변경하지 않았다. 따라서 기존 48건을 새 API 호출로 재실행했다고 표시하지 않는다. 새 실제 API 검증은 위 발표 사례 한 건의 전체 흐름이다. 기존 48건의 실제 평가 결과와 중간 실패는 [이메일 추가 후 회귀](EMAIL-REGRESSION-DEMO.md)에 있다.

브라우저 스크린샷·로그는 gitignored `.artifacts/presentation/`에 생성된다. 실제 서비스 서버는 테스트에서 메모리 SQLite로 실행해 사용자의 저장 상담을 수정하지 않았다. 외부 배포·실제 사용자 만족도·시간 절감·경진대회 성과는 검증하지 않았다.

## 실행·재현

```powershell
node --test
node scripts/check.mjs
node scripts/build-presentation.mjs
node scripts/check-presentation.mjs
node scripts/check-email-demo.mjs
node scripts/check-email-browser.mjs
```

브라우저 스크립트는 Playwright와 Chrome 경로를 `REPLYTRACK_PLAYWRIGHT_MODULE`, `REPLYTRACK_CHROMIUM`으로 지정할 수 있다. 실제 API 재기록은 아래와 같이 **새 파일**로 저장한다. 기존 평가를 덮어쓰지 않는다. `.env`의 로컬 API 설정을 사용하며 키를 출력하거나 저장소에 추가하지 않는다.

```powershell
node --env-file=.env scripts/record-presentation.mjs --run --out evals/results/presentation/new-recording.json
node scripts/build-presentation.mjs evals/results/presentation/new-recording.json
```

새 기록을 발표에 채택할 때에는 전체 의미를 원문과 대조한 뒤 원본 경로를 지정해 빌드하고 테스트한다. 빌드의 기본 경로와 테스트는 배포된 JSON의 `provenance.source`를 따르므로 원본 경로를 따로 중복 수정하지 않는다. 반복 실행은 결과가 달라질 수 있으며 통과한 한 기록을 전체 정확도로 확대 해석하지 않는다.
