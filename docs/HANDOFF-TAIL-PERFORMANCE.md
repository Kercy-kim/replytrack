## 변경

- 미해결 질문을 '답변을 기다리고 있습니다'로 전달하도록 예시를 수정했다. 확인 중인 정보를 실제 일정·처리의 부재로 확정하지 않는다.
- 인계 수정은 기존 초안에서 지적된 부분을 고치되 시간 순서·담당자 추정도 원문에 대조하도록 별도 지침을 적용한다. 맞는 사실·남은 질문·근거를 유지하며 의미 수정은 medium이다.
- 현재 상담의 내부 메시지 ID만 들어 있는 `(ID)`·`[ID]` 표기는 코드로 정리한다. 사실이나 문장 순서는 바꾸지 않고 원문에 실제 등장한 식별자·알 수 없는 ID·혼합된 본문은 제거하지 않는다. 정리된 초안도 기존 서버 검증과 실제 AI 의미 검토를 받는다.
- 모든 의미 검토는 기존 medium이며 지침도 동일하다. 분석·재문의 생성·재문의 수정·출처 검증·수정 한도는 유지했다. 내부 ID 오류도 서버가 계속 차단하며 최종 검토 전에 저장하지 않는다.
- low 수정 후보는 품질 문제로 제외했고 [ADR 0010](adr/0010-focused-handoff-repair.md)에서 이전 인계 수정 medium 결정을 유지했다.

## 비교 방법

[고정 자료](../evals/handoff-tail-cases.json)는 첫 API 호출 전에 준비했다. 기존 12개 분석 기록을 그대로 사용하고, 느린 원인이 확인된 R03을 6회, NR05를 4회, 나머지 10개 기록은 한 번씩 실행한다. 총 전후 20쌍이며 새로운 상담 20개나 분석 정확도 검사가 아니다. 기대 기준은 모델에 전달하지 않는다.

별도로 실제 실패 초안 4개(R03 단정, NR05 내부 ID, U06 상충 확정, H02 소비자 관점)와 이전 검토 피드백을 고정해 두 번씩 재생한다. 첫 실패 생성과 검토는 메모리에서 재생하고, **수정과 최종 검토 경로만 실제로 실행**한다. NR05는 기준 구현의 서버 검증이 ID 오류를 발견하고 다시 생성하지만, 개선안은 코드로 표기만 정리한 뒤 곧바로 실제 AI 검토를 받는다. 서버에서 이미 거절했던 초안에 가짜 의미 검토 실패를 추가하지 않는다. 총 8쌍의 이 측정은 수정 비용을 분리한 것으로 전체 인계 20쌍과 섞지 않는다.

양쪽 모델은 `gpt-5-mini-2025-08-07`, 원문·질문·약속·ID가 같고 기준 소스를 Git에서 고정한다. 쌍마다 전후 순서를 번갈아 실행하며 작업자는 두 개다. 실패 대기 시간도 기록한다. 중앙값은 기존 도구와 동일하게 가운데 관측값 중 큰 값, p95는 nearest-rank다. 20회 p95는 두 번째로 큰 관측값이므로 최댓값과 50초 초과 횟수도 함께 확인한다. UI·OCR·분석 시간은 제외한다.

## 재실행

Node.js 24 이상, 실제 API 호출. 키는 환경변수 또는 숨겨진 stdin으로만 제공하며 결과 파일은 덮어쓰지 않는다.

```powershell
node scripts/prepare-handoff-tail-eval.mjs
node --env-file=.env scripts/evaluate-handoff.mjs --suite tail --out .artifacts/eval/tail-new.json
node scripts/compare-handoff.mjs .artifacts/eval/tail-new.json
node --env-file=.env scripts/evaluate-handoff.mjs --suite tail --only repair-probes --out .artifacts/eval/repair-new.json
node scripts/compare-handoff.mjs .artifacts/eval/repair-new.json
node --test
node scripts/check.mjs
```

전체 생성과 수정 재생을 같은 비교에 넣으면 도구가 거절한다. 실패 호출의 사용량이 없으면 전체 절감률을 계산하지 않고, 양쪽 성공·사용량 확인 가능한 짝의 토큰을 보조 집계한다. 반복한 합성 자료, 같은 자료로 개선한 회귀 평가, 공급자·캐시·네트워크 변동의 한계가 있다. 모든 실제 인계가 50초 안에 끝난다는 보장은 아니다. 외부 사람의 독립 검수는 아니며 원문 확인·사용자 편집을 유지한다.

참고: [OpenAI 지연 최적화 가이드](https://developers.openai.com/api/docs/guides/latency-optimization)의 전체 완료 시간·재시도·토큰을 함께 측정하고 검증 후 결과를 표시하는 원칙을 적용했다.
