# MVP 검증 기록

검증일: 2026-11-14 (Asia/Seoul). Windows, Node.js v24.22.1. 테스트 입력은 가상 A/S 상담이며 실제 소비자 자료를 사용하지 않았습니다.

## 자동 테스트

`node --test` **14개 통과**. `node scripts/check.mjs`로 JavaScript 파일 14개의 문법 검사를 통과했습니다.

| 범위 | 확인한 동작 |
| --- | --- |
| 원문 검증 | 존재하지 않는 인용문·잘못된 발화자의 답변을 확인 필요로 변경, 근거 없는 약속 제외 |
| 분석 병합 | 누락된 기존 질문·약속 보존, 사용자 판정과 실제 확인을 새 답변 뒤에도 유지 |
| 처리 상태 | 업체가 완료를 안내해도 사용자 확인 시각을 만들지 않음 |
| 날짜 | 한국 시간의 날짜 경계, 오늘·내일·모레, 잘못된 절대 날짜와 불명확한 기한 처리 |
| 초안 검증 | 없는 메시지 ID와 원문에 없는 숫자·금액 거절 |
| 장애·동시 수정 | 분석 실패 시 새 원문과 이전 결과 유지, 늦은 AI 응답과 오래된 버전의 덮어쓰기 방지 |
| 저장 | SQLite를 종료하고 다시 열어도 원문·질문 유지 |
| HTTP | 예제 생성 → 초안 → 후속 답변 → 직접 확인 → 인계 → 삭제 흐름 |
| 로컬 접근 | 다른 Origin의 쓰기 요청·잘못된 Content-Type 거절, .env·DB 정적 접근 차단 |
| API 클라이언트 | strict JSON 스키마·store:false 요청, 인증 오류·미완성 출력 처리 |
| 입력 검토 | 불명확한 발화자와 빈 입력 거절, 빈 입력에서 AI 호출하지 않음 |

## 실제 OpenAI API 확인

기본 모델 `gpt-5-mini`로 실제 호출했으며, 응답 모델 식별자는 `gpt-5-mini-2025-08-07`이었습니다. 키는 실행 중인 서버 메모리에만 등록했습니다.

- 텍스트에서 소비자·고객센터 메시지 2개 추출.
- 수리비 / 수리 기간 / 왕복 배송비를 3개 질문으로 분리하고, 답변 대기 / 답변 받음 / 미답변으로 표시. 이 사례에서 근거 검증 경고는 없었음.
- 선택한 미해결 질문에 대한 재문의 초안 생성.
- 후속 답변을 추가했을 때 기존 질문 ID를 유지하고 배송비 질문을 답변 받음으로 갱신.
- 상담 날짜가 2026-11-14인 “내일까지 견적 안내”를 2026-11-15로 계산. 사용자 확인 완료는 생성하지 않음.
- 기존 사실과 남은 질문을 포함한 인계 요약 생성.
- PNG 가상 상담의 이미지 인식으로 발화자 2명과 비용·기간·배송비 내용 추출. 날짜가 없는 캡처의 시각은 null로 유지.

상세 검증 출력은 로컬 `.artifacts/live-text-result.json`, `.artifacts/live-vision-result.json`에 있으며 Git에서는 제외합니다. 실제 API 검증은 재실행 시 사용료가 발생하며 결과가 완전히 같지는 않을 수 있습니다.

## 브라우저 확인

데스크톱 1440px과 모바일 390px 뷰포트에서 확인했습니다.

- 예제 상담 생성, 상태별 카드, 초안 생성과 복사 성공 안내.
- 후속 답변과 견적 도착에 따른 질문·약속 갱신.
- 질문 판정을 직접 수정한 뒤 새 답변을 추가해도 수정 상태 유지, 최신 AI 제안 별도 표시.
- 확인 대화상자에서 실제 처리 확인 후 사용자 확인 완료 및 확인할 약속 수 갱신.
- 가상 PNG를 파일 선택기로 업로드 → 원문 검토 화면 → 저장 → 실제 AI 질문 분석까지 연결.
- 재문의 초안을 직접 편집한 뒤 인계 요약을 생성해도 편집 내용 유지.
- 기록 저장으로 Markdown 파일 다운로드 및 편집한 초안 포함 확인.
- 모바일 문서 너비가 뷰포트를 넘지 않음. 관찰한 브라우저 오류·경고 로그 없음.

## 검증의 한계와 다음 평가

이 결과는 **기능 연결과 대표 사례 확인**이며 모델의 일반 정확도·시장 우위·비용 절감률에 대한 평가가 아닙니다. 20~30건의 사람이 정답을 지정한 가상 상담 평가, 조건부 답변·모순·복잡한 캡처의 인식률 비교, 여러 모델의 품질·비용 비교는 아직 수행하지 않았습니다.

원문 존재 검증은 잘못된 인용을 줄이지만, 실제 존재하는 문장을 의미상 잘못 연결하는 오류까지 막지는 못합니다. 초안 숫자 대조 역시 모든 사실·약속의 의미를 검증하지는 않습니다. 따라서 근거 확인과 사용자 수정 단계를 유지합니다.
