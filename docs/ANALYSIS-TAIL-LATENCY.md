# 긴 분석 지연 개선과 검증

2026-11-15. 기준 main: `7f58605f6c93f14f6642eddecd4e11123722bdb4`. 실제 API 모델은 전후 모두 `gpt-5-mini-2025-08-07`로 고정했다. 모든 상담은 가상 자료이며 결과 원본은 `evals/results/analysis-tail/`에 보존한다.

## 82.5초 사례에서 확인된 사실

이전 `analysis-latency/optimized.json`의 NU02는 첫 분석 **75.019초**, 경계 검토 **7.482초**, 전체 **82.501초**였다. 첫 분석 출력은 770토큰, 이 중 추론은 448토큰이다. 동일 코드·입력의 후속 실행은 19.716초와 13.799초였다.

병목은 첫 API 호출이며, 출력량만으로 긴 시간을 설명하기 어렵다. 그러나 당시에는 헤더·본문 시간을 따로 수집하지 않아 공급자 대기, 생성, 네트워크 중 정확한 원인을 확정할 수 없다. 이번에는 헤더까지의 시간과 본문 읽기 시간을 분리했다. 실제 정상 평가의 최장 호출 R03은 헤더까지 19.821초, 본문 읽기 1ms였다. 이는 응답을 기다리는 구간이 길다는 증거이며, 공급자 내부 대기와 추론을 분리한 측정은 아니다.

## 변경

첫 분석이 **25초** 동안 완료되지 않으면 같은 원문·모델·추론량·스키마·출력 한도로 보조 요청을 한 번 실행한다. 먼저 완성된 결과를 기존 원문 검증·필요한 medium 수정과 의미 검토에 전달한다. 검증 전 결과를 화면에 확정하지 않는다. 등록과 새 답변 반영에 적용하며 수정·검토·초안·연결 점검에는 적용하지 않는다.

서버의 공유 클라이언트당 보조 요청은 동시에 하나다. 원래 요청도 먼저 끝날 수 있으며 보조 요청이 실패해도 원래 요청을 기다릴 수 있다. 두 요청은 원래 90초 제한을 공유한다. 취소·한도·인증·거절 처리, 버전 충돌 검사, 저장 한 번 원칙은 유지한다. 자세한 결정은 [ADR 0021](adr/0021-analysis-tail-latency.md)에 있다.

## 75초 지연을 동일하게 주입한 전후 비교

`scripts/check-analysis-tail.mjs`는 실제 API가 생성한 응답을 첫 요청 시작부터 75초가 될 때까지 전달하지 않는다. 보조 요청에는 지연을 넣지 않는다. `before`는 같은 클라이언트에서 보조 요청만 끄고, `after`는 제품 기본 25초 기준을 사용한다. 네 실행은 순차 실행했으며 원문·모델·추론량·검증 기준을 유지했다. 이 방식은 **응답 전달 정체에 대한 통제 실험**이며, 과거 공급자 지연을 그대로 재현하거나 자연 발생 지연의 개선율을 측정한 것은 아니다.

| 대상 작업 | 보조 요청 없음 | 개선 후 | 최종 판정 |
| --- | ---: | ---: | --- |
| NU02 최초 분석 + 경계 검토 | 85.70초 | 41.98초 | 최대 인원 답변 받음, 실제 수락 여부 확인 필요 |
| NR05 새 답변 반영 | 75.01초 | 41.73초 | 상충 안내 확인 필요 → 명시적 정정 뒤 카드 환불 답변 받음 |

두 후보 모두 실제 보조 요청이 먼저 완성됐으며 원문 근거·판정·설명 검사를 통과했다. NU02는 medium 경계 검토까지 수행한 시간이다. NR05는 최초 분석 이후 새 답변 분석 구간만 비교했다. 각 조건 한 번씩의 측정이므로 분포나 SLA로 해석하지 않는다.

실험용 전달 계층은 보류한 원래 응답을 먼저 읽기 때문에 취소된 원래 요청의 사용량도 따로 확인할 수 있다. **NU02 작업 전체 토큰은 8,682→13,907, NR05 새 답변 구간은 6,542→12,429**였다. 제품 클라이언트가 보지 못한 원래 요청은 실제 화면·분석 기록에서 사용량 미확인 1건으로 남았다. 원래 요청의 과금까지 없어졌다고 주장하지 않는다. 각 원본은 `stall-NU02-before/after.json`, `stall-NR05-before/after.json`이다.

## 추가 품질·웹·자동 테스트

- 설명 범위 대조 4건: 실제로 물은 상세 경로·시각·조건을 보존하고 추가 요구를 만들지 않는 검사 통과 (`reasons.json`).
- 영어 이메일 2건: 최초 분석·새 답변 반영 4단계에서 상태, 원문 근거, 질문 ID, 한국어 제목, 사용자 실제 확인 분리 검사 통과 (`email.json`).
- 실제 OpenAI + Chrome: 환불과 영어 계정 복구 모두 등록→새 답변 반영·비교→재문의 생성→편집·저장·복사→새로고침 보존 통과. 모바일 390px·데스크톱 1280px, 브라우저 오류 0건 (`browser.json`). 별도 한국어 설명·업체 요청 생성은 이 핵심 흐름 검사에서 실행하지 않았다.
- 자동 테스트 **216/216**, JavaScript **110개** 구문 검사 통과. 보조 성공/실패, 원래 요청의 승리, 늦은 응답 무시, fetch/본문 지연, 두 요청 동시 취소, 공유 시간 제한, 슬롯 상한, 한도·인증·거절, 잘못된 인용의 수정 및 실패 시 기록 보존, 미확인 사용량의 절감률 제외를 검사했다.

자연 발생 지연에서도 추가 비용 위험이 확인됐다. 이메일 평가의 새 답변 분석은 28.64초·44.21초에 **원래 요청이 먼저 완료**됐고 각각 보조 요청이 취소됐다. 웹 이메일 분석도 32.13초에 원래 요청이 이겼다. 이 세 호출에는 속도 개선을 주장할 수 없고 취소된 요청의 추가 사용량은 알 수 없다. 모바일 화면에서 `tokens 이상 · 일부 요청 사용량 미확인` 표시의 줄바꿈도 확인했다. 보조 요청은 반드시 이기는 방식이 아니며 이 비용과 지연의 교환 관계를 숨기지 않는다.

웹 단계 시간은 환불 등록 17.87초·새 답변 12.74초·재문의 편집 확인 14.42초, 이메일 등록 25.09초·새 답변 37.79초·재문의 편집 확인 13.92초였다. 이는 현재 버전의 기능 확인 기록이며 같은 조건의 전후 웹 비교는 아니다.

## 재현

로컬 `.env`에 키를 설정하고 기존 결과와 겹치지 않는 출력 경로를 지정한다. 실제 API 호출에는 비용이 발생한다.

```powershell
node --env-file=.env scripts/evaluate-ai.mjs --suite full --analysis-only --model gpt-5-mini-2025-08-07 --out .artifacts/tail-new.json
node --env-file=.env scripts/check-analysis-tail.mjs --run --mode before --case NU02 --stage initial --out .artifacts/stall-before-new.json
node --env-file=.env scripts/check-analysis-tail.mjs --run --mode after --case NU02 --stage initial --out .artifacts/stall-after-new.json
node --test
node scripts/check.mjs
```

새 답변 지연 실험은 `--case NR05 --stage reply`로 실행한다. 원본 보고서에는 소스 해시와 입력·출력·채점·사용량을 남겼다. 제품 프롬프트·스키마·추론 분기는 변경하지 않았다.

## 사용량과 남은 한계

보조 요청은 추가 비용을 낼 수 있다. HTTP 취소는 공급자의 생성·과금 취소를 보장하지 않는다. 성공 응답과 이미 읽은 실패 응답의 확인된 사용량을 합산하고, 확인하지 못한 요청 수는 `unobserved_requests`에 남긴다. 해당 경우 화면에는 토큰 수가 하한임을 표시하고 평가 도구는 토큰 절감률을 계산하지 않는다. 전체 실패 시 진단에도 시도별 사용량을 보존한다.

두 요청이 모두 느린 경우, 보조 요청 슬롯이 사용 중인 경우, 후속 의미 검토·수정 자체가 느린 경우에는 오래 걸릴 수 있다. **모든 요청의 82초 이내 완료를 보장하지 않는다.** 현재 표본은 고정된 소수 가상 상담이다. 실제 장기 운영의 발동률·추가 과금·최장 지연은 추가 관찰이 필요하다.
