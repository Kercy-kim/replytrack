# 신규 기능 실제 AI 품질 평가

평가일: 2026-11-15. 기준 main: `f0d4ddf`(PR #17). 실제 Responses API의 `gpt-5-mini-2025-08-07`을 사용했다. 기존 질문 분석·재문의·인계 평가의 점수를 새 기능에 가져오지 않았다.

## 범위와 판정 방법

- 업체 요청 추출 20건: 조건·소비자 기한과 업체 일정, 요청 없음, 수신 확인, 미래 계획·거절, 철회·대체, 재제출, 직접 수행 보존, 영업일·기준일 미정, 프롬프트 주입, 수행 안내 정정. 재제출·수행 보존 2건은 각각 2단계이므로 총 22단계다.
- SSG 안내 20건: 준비 중/배송 중 취소, 기간 초과·불량·세탁·신선식품, 수령일 모름, 카드 당일 전체/부분/이후 취소, 요청만 한 상태, 다른 결제수단, 입력 충돌, 지원 범위 밖, 악성 지시, 순차 질문, 화면 접수 불가, 검색 실패.
- 정상/오류 대조: 생성 결과와 독립적으로 검토기에 올바른 답변과 일부러 잘못 고친 답변을 넣는다. 최초 12쌍, 추가 회귀를 포함한 최종 14쌍이다.
- 실제 서비스의 생성·구조 검사·의미 검토·저장 경로와 격리된 SQLite를 사용한다. 전화번호·주소 가림과 실제 OpenAI 직렬화도 운영 코드와 같다. 사용자 상담 데이터는 사용하지 않는다.
- 자동 판정은 상태·기한·조건·직접 수행·핵심 문구·지원 범위·자료 모드·질문 순서를 확인한다. 별도로 이 작업을 수행한 개발 에이전트가 생성 문장과 원문 인용을 대조했다. 독립된 사람 평가나 일반적인 정확도 측정은 아니다.

초기 비교에는 같은 시점에 실제 SSG에서 확보한 FAQ 본문을 사용했다. 검색 장애 4건은 네트워크 실패를 주입하되 안내 생성·검토는 실제 API로 수행한다. 마지막에는 현재 공식 검색을 연결한 전체 안내 평가로 다시 확인한다. `live`와 날짜가 있는 대체 자료를 구분하고, 대체 자료를 실시간 검색 성공으로 계산하지 않는다.

안내 의미 검토가 실패하면 피드백으로 **한 번만** 수정하고 다시 검토한다. 일반 안내는 의도 해석 포함 3회, 수정 시 최대 5회다. 상황 질문 턴과 연결 사전 점검은 별도다. 공급자 오류·취소·구조 검증 실패는 이 수정 경로에 넣지 않는다. 재검토 실패 시 이전 결과를 유지한다. 할 일은 생성 1회·검토 1회이며 자동 수정 반복을 추가하지 않았다.

승인 전 카드 환불은 의도 해석·의미 검토 **2회**다. 출처의 조건별 기간을 그대로 보존하며 한 기간을 추측하는 자유 문구 생성을 하지 않는다. 이 경로의 검토 실패에도 기존 결과를 유지한다.

## 평가 기준의 수정 공개

사용자 원문·기본 선택값은 첫 실행 전에 준비했다. 다음 기대값 변경은 결과를 설명하기 위해 명시한다. 동일 채점기를 사용한 통제 실험으로 주장하지 않는다.

1. A10 수행 근거는 소비자가 보냈다는 발언과 업체가 받았다는 발언 모두 유효하다. 처음에는 소비자 발언만 허용해 정상 결과를 실패로 표시했다. 두 경우를 허용하되 요청 이전/관련 없는 근거는 계속 실패시킨다.
2. G03의 ‘7일 이내면 가능’이라는 일반 정책 설명을 ‘12일 지난 이 주문도 가능’이라는 개인 보장과 구분했다. G06/G07에도 같은 기준을 적용했다. 현재 상황의 제한은 별도로 반드시 안내해야 한다.
3. G13은 충돌 정보를 두고 일반 안내를 내는 대신 재확인 문답을 도입했다. 초기 입력은 유지하고 `received=older`로 바로잡는 후속 응답과 질문 순서 검사를 추가했다.
4. 마지막 전체 안내 실행에서 G13은 “7일이 지났으니”라고 올바르게 기간 초과를 설명했지만 채점 정규식이 `지난/지나`만 허용해 실패했다. `지났`을 추가하고 저장된 모든 최종 안내를 오프라인 재채점했다. 유효한 표현·잘못된 7일 이내 보장·재질문 누락을 구분하는 테스트를 추가했으며 원래의 19/20 로그는 수정하지 않았다.

채점기 회귀 테스트에서 잘못된 완료·기한·조건·근거·개인 가능 보장·불확실성 누락이 계속 실패하는지 확인한다. 자동 문자열 검사는 모든 의미 오류를 잡지 못하며, 카드 표 오류도 자동 통과 뒤 원문 대조에서 발견했다.

## 기록과 재실행

입력과 기대값은 [평가 사례](../evals/new-feature-cases.mjs), 정상/오류 쌍은 [검토 대조 사례](../evals/new-feature-review-controls.mjs)에 있다. 최종 출력·원문 인용·출처 URL/본문 해시·호출 사용량·중간 실행 목록은 [결과 자료](../evals/results/new-features/verification.json)에 공개한다. 자동 통과 뒤 원문 대조에서 발견한 중간 오류도 `manualFindings`에 출력과 함께 남긴다. 전체 원시 로그와 당시 FAQ 본문은 Git 제외 경로 `.artifacts/new-feature-eval/`에 보존한다. 비밀키·개인 상담·실제 주문 조회는 포함하지 않는다.

각 실행 파일은 기존 결과를 덮어쓰지 않는다. 아래 예시의 새 디렉터리 이름을 매 실행마다 바꾼다. 실제 API 비용이 발생한다.

```powershell
node --env-file=.env scripts/evaluate-new-feature-reviews.mjs .artifacts/recheck/controls.json

```

호출·토큰 집계는 완료된 사례의 기록이며 사전 연결 점검을 제외한다. 문제가 확인되어 중단한 실행은 미완료로 남긴다. 중단 순간 진행 중이던 요청은 사례 기록에 저장되지 않았을 수 있어 총 사용 비용의 정확한 합산 자료가 아니다.

## 한계

고정된 가상 사례를 반복하며 개선했으므로 새 입력에 대한 독립 검증 점수로 볼 수 없다. 검토 모델도 오판하며 한 번의 대조 시험 통과가 오승인 가능성 제거를 뜻하지 않는다. 생성 행동의 설명 반복·표현 차이까지 완전히 제거했다는 의미도 아니다. 공식 원문과 개별 상품 조건 확인을 유지한다.

SSG 본문 구조나 정책이 바뀌면 새 검증이 필요하다. 확인된 대체 자료는 2026-11-15 기준이며 자동 갱신되지 않는다. 개별 주문 조회·취소/반품 신청·입금 확인을 실행하지 않는다. 실제 사용자 평가와 배포는 별도 과제다.
