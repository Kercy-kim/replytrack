# 실제 OpenAI API 전체 흐름 검증

- 검증일: 2026-11-14
- 시작 코드: main `b767ad0`
- 모델: `gpt-5-mini` → 응답 모델 `gpt-5-mini-2025-08-07`
- 가상 상담만 사용했으며 별도 SQLite 디렉터리에서 실행했다. 예제 모드나 응답 대체 서버를 사용하지 않았다. 키는 서버 메모리에만 설정했다.

## 발견한 문제와 수정

1. **월·일 약속이 기한 미정으로 남음.** 2026-11-14 상담에 있는 “11월 16일 오후 3시까지”가 날짜로 변환되지 않았다. 원문 메시지의 한국 날짜에서 연도를 가져오도록 수정했다. 같은 해의 당일·미래 월일만 계산하며, 기준 날짜가 없거나 연도가 모호하거나 유효하지 않은 날짜는 미정으로 남긴다. 분석 실행일을 기준으로 삼거나 연말 기한을 자동으로 다음 해로 넘기지 않는다. 시간은 원문에 보존하고 기한 정렬은 기존처럼 날짜 단위다. 기존 저장 기록은 재분석할 때 반영된다.
2. **추가 안내를 정정으로 표현.** 처음에는 “출고 지연”, 이후 처음 제시된 “11월 18일 도착 예정”을 인계에서 “정정받았다”고 서술했다. 구체적 기존 값을 바꾸거나 오류를 바로잡은 근거가 있을 때만 정정이라고 표현하도록 인계 지침을 보완했다.
3. **해지 약속을 자동 결제 질문에 연결.** 구독 해지 처리·결과 안내만 약속했는데, 별도로 물은 다음 달 자동 결제 중단 여부도 답변 대기로 분류했다. 두 행동의 관계가 원문에 명시되지 않았다면 자동 결제 질문에는 근거나 연결 약속을 만들지 않고 미답변으로 남기도록 분석 지침을 보완했다.

## 실행 범위

- 웹 직접 조작: 배송·환불 복합 상담의 입력, 전송 전 확인, 실제 AI 대화 추출, 발화자·날짜 확인, 저장·분석, 새 답변 추가, 전후 비교, 재문의·인계 생성.
- 웹과 같은 작업 API: 별도 환불·구독 상담의 위 전체 데이터 흐름, 작업 완료·소요 시간, 원문 인용, 질문 ID 유지, 변경 비교, 실제 확인과 업체 안내 구분, 저장 결과 재조회.
- 인계 대조군: 기존 NR05의 카드→계좌→카드 정정 사례를 2회 실행해 새 지침이 실제 정정을 지우지 않는지 원문과 대조.

## 결과

| 사례 | 초기 상태 | 새 답변 반영 | 재문의·인계 |
|---|---|---|---|
| 배송·환불 복합 / 웹 직접 조작 | 배송일·환불 기간 대기, 전액 환불 답변 받음 | 배송일만 답변 받음으로 변경, 기한 2026-11-16 유지 | 환불 기간만 재문의, 인계에서 추가 배송 안내를 정정으로 표현하지 않음 |
| 환불 / 작업 API | 금액 답변 받음, 환불수단 미답변, 예정일 대기 | 카드 안내 후 환불수단만 답변 받음 | 예정일만 재문의, 79,000원·카드·안내 약속을 인계에 유지 |
| 구독 / 작업 API | 해지 결과 대기, 자동 결제 미답변, 환불 불가 답변 받음 | 자동 결제 중단 안내 후 해당 질문만 답변 받음 | 해지 결과만 재문의, 업체 완료 안내와 실제 확인을 구분 |

모든 사례에서 기존 질문 ID, 원문 인용, 직접 확인 전 상태가 유지됐다. 웹에서는 초안을 편집·저장하고 새로고침한 뒤 편집 내용과 인계가 유지되는 것도 확인했다. 복사 성공 안내를 확인했으며 브라우저 콘솔 오류·경고는 없었다. 외부 앱 붙여넣기까지 검증한 것은 아니다.

서버 작업 시작부터 검증·저장까지의 관측 시간은 다음과 같다. 사람의 입력·검토 시간은 제외했다.

| 사례 | AI 추출 | 첫 분석 | 새 답변 분석 | 재문의 | 인계 |
|---|---:|---:|---:|---:|---:|
| 배송·환불 / 웹 | 6.4초 | 25.3초 | 32.6초 | 9.7초 | 16.2초 |
| 환불 / 작업 API | 5.0초 | 21.4초 | 30.0초 | 13.4초 | 12.3초 |
| 구독 / 작업 API | 5.2초 | 23.0초 | 21.2초 | 16.6초 | 17.9초 |

각 사례 1회 관측으로 응답 시간 상한을 보장하지 않는다. 서로 다른 사례가 일부 동시에 실행됐으므로 독립 성능 비교도 아니다. 웹의 첫 분석은 날짜·인계 수정 후 실행했고, 이후 새 답변 분석과 초안은 구독 지침까지 포함한 최종 코드에서 실행했다.

실제 정정 대조군 NR05도 2/2회 저장 및 원문 대조를 통과했다. 최종 자동 테스트는 **114/114 통과**, 문법 검사는 **63개 파일 통과**다. [실패·수정 후 결과와 코드 해시](../evals/results/live-web-flow.json)에 최초 웹 결과, 중간 구독 실패, 최종 사례별 원문·판정·초안·작업 시간, 정정 대조군을 보관했다. 이는 기존 대규모 품질 평가 전체를 다시 실행했다는 뜻은 아니다.

## 재현

별도 터미널에서 테스트용 서버를 시작하고 웹 설정에서 실제 API 키를 연결한다. 테스트 자료는 서버에 새 상담으로 저장되며 OpenAI 사용량이 발생한다.

```powershell
$env:PORT='3194'
$env:REPLYTRACK_DATA_DIR='.artifacts/live-flow-data'
node server.mjs
```

```powershell
$env:REPLYTRACK_URL='http://127.0.0.1:3194'
$env:REPLYTRACK_FLOW_REPORT='.artifacts/live-flow-result.json'
node scripts/check-live-flow.mjs --run
node --test
node scripts/check.mjs
```

`check-live-flow.mjs`는 로컬 서버만 허용하고 실행 동의용 `--run`이 없으면 호출하지 않는다. 단계별 시간과 합성 상담 결과를 기록하며, 실패 결과를 성공으로 덮어쓰지 않는다. 재실행은 다른 보고서 경로를 지정해 이전 관측을 보존한다.

이 검증은 소수 합성 사례의 기능·회귀 검사다. 모든 상담의 정확도, 응답 시간 상한 또는 캡처 OCR 품질을 입증하지 않는다. 초안은 자동 전송하지 않았고 실제 고객센터에는 연락하지 않았다.
