점검일: 2026-11-16. 최신 main `1f18c78`에서 전체 로컬 테스트와 발표 화면을 다시 점검했다. 아래의 이메일 판정 보완·시연 원본 갱신은 앞선 `29e2c16` 기준 작업이며, 이번에는 최신 구현과 검증 근거의 일치 및 발표 문서를 확인했다. **검사한 범위에서 발표를 막는 오류는 해결했다. 30초 시연은 사전 실행 결과 재생으로 진행한다.** 실제 AI 작업 전체가 30초 안에 끝나는 서비스라는 뜻은 아니다.

- 발표 원본의 분석 코드 해시 8개와 화면 데이터의 원본 해시가 일치한다. 재생은 네 장면, 1280×720·390px에서 통과했으며 AI 호출·상담 생성은 0회다.

- Gmail·NoReply 비교 설명은 공식 자료를 다시 확인했다. 요약·할 일·답장 기능 자체를 독자 기능으로 소개하지 않고, 질문별 근거·후속 변화·사용자 직접 해결 확인을 연결한 사용 흐름을 개선점으로 설명한다.

## 발견하고 수정한 내용

1. **관련 절차가 있는데 기간 질문을 미답변으로 분류:** 첫 실제 API 기록에서 심사 약속을 기간 질문에 연결하면서도 관련 안내가 없다고 판정했다. 이메일 지침에 절차·기간·향후 답변 약속의 차이를 명시했다. 미답변 질문에 연결된 약속이 있으면 AI가 관련성을 다시 검토한다. 잘못 연결된 다른 업무라면 연결만 제거하고 미답변을 유지할 수 있으며, 코드가 상태를 강제로 바꾸지 않는다. 재검토까지 모순이면 이전 기록을 보존한다.
2. **발표 자료의 오래된 숫자:** 테스트 202/259개, 과거 시연 160.4/214.4초와 최신 결과가 섞이지 않도록 이 문서와 5분·4분 대본을 갱신했다. 기존 실패 기록과 과거 원본은 보존했다.
3. **README 비교 표의 끊어진 행:** 표 내부의 빈 줄을 정리해 기존 서비스 비교를 한 표로 읽을 수 있게 했다.

실패한 첫 시연은 [원본](../evals/results/presentation/recording-2026-11-16-readiness.json)에 남겼다. 수정 후 전체 흐름을 새 파일로 실행했으며 실패 출력을 편집해 성공으로 바꾸지 않았다. 대조는 절차만 안내 / 기간 미정 / 인사 / 구체 기간 / 나중에 기간 안내 / 자료만 요청의 여섯 경우이고, 캡처한 실패 출력을 실제 AI가 복구하는 검사도 통과했다.

## 발표 진행

[설명 4분 + 시연 30초 대본](PRESENTATION-4MIN-SCRIPT.md)을 기본으로 사용하고, [5분 구성·예상 질문](PRESENTATION.md)은 보충 자료로 둔다.

1. 프로젝트 폴더에서 `node --version`으로 Node.js 24 이상을 확인한다. 처음 설치할 때만 `npm ci`로 OCR 의존성을 설치한다.
2. `node server.mjs`를 실행하고 `http://127.0.0.1:3100/presentation`을 연다. 기본적으로 이 컴퓨터에서만 접속하는 로컬 서비스다.
3. 확대율 100%, 첫 장면을 준비한다. “가상 문의로 사전 실행한 실제 AI 결과를 보여드립니다”라고 소개한다.
4. 0–6초 문의, 6–14초 설명·할 일, 14–21초 영어 초안, 21–30초 새 답변 비교를 보여 준다. 다음 버튼은 총 세 번 누른다.
5. 발표에서는 핵심 네 기능과 구현 결과를 설명하고 공식 안내·상세 코드·추가 기능은 질문을 받으면 보여 준다.
6. 설명·브라우저 전환까지 포함해 발표자 기준으로 한 번 리허설한다. 4분 30초를 목표로 하고 5분 제한의 남은 30초는 전환 여유로 둔다.

서버가 꺼지면 다시 실행한다. 재생 데이터 오류에는 다시 불러오기를 사용한다. 인터넷·API 문제 때는 이미 준비한 결과 재생을 사용한다. 체험용 이메일 예제를 대신 보여 주면 API 호출 없는 준비된 예제임을 밝힌다. 화면 캡처를 사용할 때도 실제 실행을 기다리는 장면처럼 소개하지 않는다.
