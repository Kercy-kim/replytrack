# ReplyTrack 마무리 점검

기준: 2026-11-16, main `b677de7` 이후 마무리 변경. 핵심 기능 네 가지를 중심으로 발표하고, 보조 기능은 질문이 있을 때만 설명한다.

## 발표에서 보여 줄 네 가지

| 사용자에게 필요한 기능 | 입력 → AI 처리 → 결과 |
|---|---|
| 질문별 답변 확인 | 문의·답변 원문 → 질문과 답변의 의미·조건 연결 → 질문별 상태와 근거 |
| 지금 내가 할 일 | 업체의 요청 → 소비자 행동과 업체 처리를 구분 → 제출·회신할 일과 조건 |
| 한국어 설명·재문의 | 영어 답변·선택한 남은 질문 → 의미 설명·초안 생성 및 검토 → 한국어 설명과 편집·복사할 답장 |
| 새 답변 전후 비교 | 후속 답변 → 기존 질문·약속 갱신 → 무엇이 답변됐고 무엇이 남았는지 비교 |

이번 재문의 보완은 이미 받은 답을 다시 묻지 않고 실제 남은 정보만 요청하게 하는 개선이다. AI가 판정·작성하고, 일반 코드가 원문 참조·기록 버전·저장·전후 차이를 관리한다. 사용자가 실제 수행·해결을 확인한다. 상세 검증은 [재문의 평가](FOLLOWUP-FOCUS-VALIDATION.md)를 참고한다.

## 발표 직전 준비

1. 프로젝트 폴더에서 `node --version`으로 Node.js 24 이상인지 확인한다. 처음 받은 폴더라면 인터넷이 연결된 환경에서 `npm ci`로 OCR 의존성을 설치한다.
2. `node server.mjs`로 서버를 실행하고 `http://127.0.0.1:3100`을 연다. 터미널은 발표가 끝날 때까지 유지한다. npm이 설치된 환경에서는 `npm start`도 같다.
3. **예제 · 도움 기능 → 실제 AI 결과 30초 보기**를 열거나 `http://127.0.0.1:3100/presentation`으로 이동한다. 첫 장면에 두고 브라우저 확대율 100%를 확인한다.
4. 다음 버튼 세 번으로 문의 → 설명·할 일 → 영어 초안 → 새 답변 비교를 보여 준다. “가상 이메일을 사전 실행한 실제 AI 결과입니다”라고 소개한다.
5. 실시간 입력이 필요할 때만 본 화면으로 돌아가 **AI 연결 설정 → 저장하고 연결 점검**을 실행한다. API 응답 대기는 30초 결과 시연과 구분한다.

발표자 리허설은 설명·시연·브라우저 전환을 모두 포함해 5분 안에 맞춘다. 이 점검은 발표자의 실제 말하기 시간을 대신 측정한 결과가 아니다. 이미 설치된 앱의 준비된 예제와 결과 재생에는 API 키가 필요하지 않다.

### 문제가 생겼을 때

- 서버가 꺼졌다면 같은 폴더에서 `node server.mjs`로 다시 실행한다. 포트가 사용 중이면 기존 ReplyTrack 서버인지 확인하고 그 화면을 사용한다.
- 결과를 불러오지 못하면 서버 연결을 확인한 뒤 **다시 불러오기**를 누른다. 직접 찍어 둔 결과 화면으로 설명할 때도 사전 실행 결과임을 밝힌다.
- API 지연·사용량 제한이 있으면 사전 실행 결과나 **이메일 예제 체험**을 사용한다. 예제 화면은 실제 API 결과와 구분해 소개한다.

## 이번 정리

- 제거된 인계 기능과 예전 메뉴명을 시연 문서에서 정리했다.
- 날짜·시간대가 모두 확인된 이메일은 코드에서 과거→최근으로 정렬한다. 날짜가 불분명한 메시지가 섞이면 순서를 추측하지 않는다. 원문 본문은 바꾸지 않는다.
- 시연 빌드와 무결성 테스트가 배포된 결과의 원본 경로를 함께 사용하도록 정리했다.
- 기존 시연 원본과 실패 기록을 보존하고, 최신 코드로 실제 API 시연 기록을 새로 생성했다. 실제 모델 문장은 발표용으로 고쳐 쓰지 않았다.

## 검증 결과

### 실제 API 시연

원본은 [최신 기록](../evals/results/presentation/recording-2026-11-16-final.json), 화면 데이터는 [presentation-data.json](../public/presentation-data.json)이다. 모델은 `gpt-5-mini-2025-08-07`이며 공개 합성 계정 복구 문의만 사용했다. 원문·상태·인용·영어 초안·한국어 설명·업체 요청을 확인하고 같은 실행의 전후 기록을 사용했다.

| 단계 | 실제 작업 시간 |
|---|---:|
| 초기 이메일 읽기 | 6.2초 |
| 초기 질문 분석 | 24.8초 |
| 한국어 설명·검토 | 18.5초 |
| 초기 업체 요청·검토 | 20.4초 |
| 영어 초안·검토 | 11.3초 |
| 새 답변 읽기 | 4.6초 |
| 새 답변 분석·재검토 | 84.3초 |
| 한국어 설명 갱신·검토 | 24.1초 |
| 업체 요청 갱신·검토 | 20.2초 |

전체 **15회 API 호출, 작업 합계 214.4초**였다. 새 답변 분석은 첫 호출 55.7초와 재검토 28.6초가 포함된다. 이번 작업으로 긴 AI 지연까지 해결했다고 주장하지 않는다. **30초는 이 결과를 설명하는 재생 시간**이며 실시간 처리 시간이 아니다. 과거 기록의 160.4초를 최신 기록의 시간으로 소개하지 않는다.

기간 질문은 부분 답변→답변 받음으로 바뀌고 거래 ID 요청은 업체 수신 안내로 바뀌었다. 사용자의 직접 수행·실제 복구 확인은 자동 체크하지 않았다. 영어 초안은 거래 ID 확인 이후 소요 기간만 묻고 이미 받은 서류를 다시 요구하지 않았다.

최초 재기록은 날짜가 명시된 이메일의 순서 오류로 중단됐다([실패 원본](../evals/results/presentation/recording-2026-11-16.json)). 이 결과를 편집해 성공으로 바꾸지 않고 정렬 보완 후 새 파일로 전체 흐름을 재실행했다.

### 자동·브라우저 검사

- 단위 테스트 **259/259**, JavaScript 문법 검사 **136개 파일**, Chrome 회귀 **9종** 통과.
- 발표 네 장면을 1280px 데스크톱과 390px 모바일에서 확인했다. 키보드 이동·처음부터·원문 펼치기·복사·새로고침·결과 다운로드 실패 후 재시도를 검사했다. 재생 중 AI 호출·상담 저장·브라우저 오류는 **0건**이었다.
- 실제 모델 문장·상태·원본 SHA-256과 배포 JSON의 일치를 검사했고 데스크톱 결과 화면을 직접 확인했다. 날짜 정렬은 시간대 차이·같은 시각의 순서 보존·날짜 없음·잘못된 날짜 형식·시간대 누락을 대조했다.
- 문서의 로컬 링크와 원본 기록 경로를 점검했다. 검증 근거는 [마무리 검사 기록](../evals/results/presentation/final-checks-2026-11-16.json)에 보관한다.

기존 배송·환불·구독 48건을 이번 마무리에서 다시 실행한 것은 아니다. 이번 기능 변경은 이메일 전사의 날짜 정렬이며 분석·초안 프롬프트는 변경하지 않았다.

Node.js `v24.22.1`과 설치된 OCR 엔진·한국어·영어 모델을 확인했다. 현재 점검 터미널에는 npm 명령이 없어 신규 의존성 설치를 재실행하지 않았으며, `node server.mjs`와 설치된 의존성으로 검증한다.

## 완료 범위

로컬 웹 시제품의 핵심 기능과 발표용 결과 재생이 대상이다. 메일함 연결·자동 발송·외부 배포·사용자별 계정 분리·실제 사용자 효과 평가는 완료 범위에 포함하지 않는다. 공식 참고 안내는 지원하는 문의처에서 근거·조건 검토를 통과할 때만 표시하는 보조 기능이다. 추가 기능을 발표의 핵심 네 가지와 혼동하지 않는다.

별도로 사용 중인 PPT·개인 발표 대본의 테스트 개수와 시연 처리 시간도 이 문서의 최신 결과와 맞춰 발표 전에 확인한다.
