# 개별 문의 중심 정리 화면

2026-11-15. 사용자의 방향: 개별 문의를 중심으로 쉽고 깔끔하게 정리하고, 여러 문의도 관리할 수 있게 한다.

## 구현

- 상세 상단 숫자 카드 네 개를 `문의 진행 요약`으로 바꿨다. 확인할 질문 / 업체 답변·처리 대기 / 내가 할 일·결과 확인을 구분하고 각 영역으로 이동한다.
- 질문 보기는 미답변·부분 답변·확인 필요를, 대기 보기는 답변 대기 질문과 업체 처리 약속을 연결한다. 비어 있는 필터를 모든 질문의 답변 완료로 표현하지 않는다.
- 새 메시지가 분석되지 않았다면 이전 질문·약속을 현재 요약에 집계하지 않는다. 업체 요청은 별도의 최신성 검사로 오래된 수행 요청을 구분한다. 사용자가 직접 확인하기 전 처리 안내를 해결 완료로 만들지 않는다.
- 여러 문의를 찾는 보조 화면은 `내 문의함`으로 표기한다. 첫 고객 메시지 180자 미리보기, 이메일/대화 유형, 남은 항목을 표시한다. 검색은 제목·문의처·해당 미리보기 범위다. 확인할 문의와 업체 답변·처리 대기는 겹칠 수 있으며 보관한 문의는 기본 목록에서 제외한다.
- 시작 문구와 탐색을 문의 정리 중심으로 다듬고, 미분석 문의에 완료 체크가 표시되지 않게 했다. 개별 문의를 여는 기존 주소·이전 문의 재개 동작은 유지한다.

추가 AI 호출, 프롬프트 변경, 알림·추가 메모·자동 발송·전체 해결 상태는 도입하지 않았다. 저장된 질문·약속·업체 요청에서 표시용 요약을 계산한다. 원문과 AI 결과 저장 형식은 변경하지 않고 목록 응답에 미리보기·유형·표시용 요약을 추가한다.

## 검증

- `node --test`: 220/220 통과. 새 메시지 이후 오래된 요약 제외, 업체 요청의 독립적인 최신성, 처리 안내와 사용자 확인 분리, 겹치는 필터·보관함·미리보기 검색을 추가 검사했다.
- `node scripts/check.mjs`: JavaScript 113개 구문 검사 통과.
- `scripts/check-inquiry-workspace.mjs`: 실제 Chrome, 격리된 메모리 저장소와 가상 문의. 320/390/768/1280px에서 개별 요약, 키보드 이동·포커스, 질문/대기 구분, 예제 새 답변 반영, 검색, 텍스트 이스케이프, 보관함, 미분석 표시, 가로 넘침을 검사했다.
- `scripts/check-ui-refinement.mjs`: 기존 320/390/768/1280/1440px UI 회귀 통과. 초기 320px 탐색 높이 검사 실패는 주요 버튼을 `문의 추가`로 짧게 바꾼 뒤 통과했다. 초안 편집 보존, 삭제 취소, 입력 복원 등 기존 흐름도 검사했다.
- 화면 확인: 모바일 개별 문의의 세 행 요약과 데스크톱 문의 목록을 확인했다. 기록은 `.artifacts/inquiry-workspace/`, `.artifacts/ux-refinement/`에 있다.

이번 검사는 표시·탐색·분류 동작을 대상으로 하며 실제 AI 재평가나 사용자 사용성 실험으로 해석하지 않는다. 테스트 중 외부 AI 호출은 0회다.
