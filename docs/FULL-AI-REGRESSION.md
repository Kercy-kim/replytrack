# 프롬프트 수정 후 전체 AI 품질 회귀 평가

## 범위와 기준

- 기준 main: `264512a` (PR #13, 기한 계산·질문별 약속 연결·인계 정정 표현 수정)
- 실행일: 2026-11-14
- 모델: 기존과 동일한 고정 버전 `gpt-5-mini-2025-08-07`
- 기존 자료: 배송 17·환불 17·구독 14, 합계 48건. 최초 20건·경계 8건·추가 20건의 원문과 기대값을 변경하지 않는다.
- 분석 55회: 초기 48회, 기존 후속 답변 7회. 지정 초안 13건: 재문의 7·인계 6건.
- 인계 전용 자료: 기존 12개 기록을 정해진 반복 수대로 18회 생성한다. 이 중 6개는 위 상담과 겹치고 H01~H06 6개는 별도 기록이다. 18건의 새로운 상담으로 세지 않는다.

실제 OpenAI Responses API와 제품의 분석·추가 답변·초안 생성·검토 경로를 사용한다. DB는 평가별 메모리 SQLite로 격리하고 API 키는 숨겨진 stdin과 프로세스 메모리에서만 전달한다. 기존 사용자 상담은 읽거나 변경하지 않는다. 각 실행은 입력, 정답, 제품 소스와 평가 코드의 해시, 원본 응답, 실패 및 사용량을 보존한다.

자동 기준은 질문 일대일 대응·정확한 상태·필수 답변 근거·약속 상태와 기한·후속 답변의 ID 유지·원문 부분 문자열 일치다. 초안은 제품 내부 검토와 별도로 개발 에이전트가 원문과 대조한다. 실제 완료나 담당자를 추정하지 않는지, 정정·기한 철회가 맞는지, 남은 질문에 집중하는지 확인한다. 외부 사람의 독립 검수는 아니다.

## 평가 중 발견한 문제와 보완

1. **R05 기간 원문 손상:** 주소 탐지기가 “일반적으로 3~5영업일” 중 “일반적으로 3”을 도로명 주소로 오인해 가렸다. 질문 상태는 맞아 기존 자동 채점에서는 드러나지 않았다. 수량·기간 단위 앞의 범위 표현과 `영업일`을 구분해 보존하도록 수정했다. 실제 주소와 전화번호를 함께 넣은 테스트로 개인정보 가림이 계속 동작하는지 확인했다.
2. **H03 남은 질문 확대와 검토 오인:** 할인 조건과 다음 청구액을 물었는데 인계에 별도로 묻지 않은 할인 적용 여부까지 “답변을 기다립니다”에 포함했다. 기존 제품 검토도 이를 허용했고, 문구만 강조한 첫 수정 후에도 재발했다. 서버가 현재 미해결 질문 목록을 생성·검토·수정에 명시적으로 전달하게 했다. 이후 대조 시험에서는 올바른 배경 설명까지 새 질문으로 오인한 1건을 발견해, 업체의 과거 안내와 소비자의 현재 대기·요청 문장을 먼저 구별하도록 검토 지침을 보완했다.
3. **U06 담당자 수 추정:** “상담원 중 한 쪽은 … 다른 쪽은 …”이라는 표현이 서로 다른 실제 상담원을 추측했지만 기존 검증을 통과했다. 두 안내 절의 내용은 유지하면서 근거 없는 주체만 “한 답변에서는/다른 답변에서는”으로 정리하고 전체 원문 의미 검토를 거치게 했다. 실제 담당자 정보·행동·요청은 이 규칙으로 고치지 않는다. 처리하지 못한 추정 표현은 서버가 차단해 기존 수정 경로를 따른다.
4. **U02 부분 답변을 미답변으로 낮춤:** 중간 전체 재시험에서 실제 해지 여부 질문에 해지 방법을 안내한 답변을 미답변으로 판정했다. 첫 출력에는 방법 근거가 있었지만 상태·근거 모순 수정 중 그 근거를 삭제했다. 같은 처리의 실행 방법은 유용한 부분 답변이라는 기존 기준을 분석과 수정 지침에서 명확히 하고, 미답변 형식만 맞추려고 관련 근거를 지우지 않게 했다. 정답과 상태 정의는 바꾸지 않았다.
5. **분석 설명의 근거 없는 추론:** 상태·근거가 맞는 S05 요약에 “상담원들이”라는 인원수 추정이 있었고, R07·NR06 판정 이유에는 물은 금액·입금 여부 외의 승인 상태·일정·거래내역까지 부족한 정보로 나열했다. 분석 요약에도 발화자 추정을 금지하고, 최초 분석과 경계 검토의 reason을 실제 질문 대상에 한정하도록 보완했다. 이후 B05 미답변 이유에 원문 없는 주문번호 제출 요건이 발생해, 서버가 검증한 미답변의 표시 이유는 “관련 안내가 아직 없음”으로 고정했다. AI 상태·근거·질문은 바꾸지 않으며 근거가 있는 모순 출력의 확인 필요 전환과 수동 상태는 보존한다. 질문 상태 자동 점수와 설명의 의미 품질을 구별한다.

첫 실행의 48건 결과와 인계 18회 결과는 `baseline.json`, `handoff-baseline.json`에 그대로 보존한다. 정답을 변경하지 않고 제품 코드·지침을 수정한다. 최종 전체 회귀에는 고정된 합성 자료의 원문이 가림 단계에서 바뀌지 않는지도 검사하도록 평가 도구를 보강했다. 실제 개인정보가 없는 이 자료에 한정된 검사이며 일반 사용자 원문을 가리지 말라는 정책이 아니다.

인계 검토 대조는 기존 정상·오류 9개에 이번 실패 문장과 올바른 배경 설명 2개를 더한 별도 [11개 자료](../evals/full-regression-review-probes.json)를 호출 전에 고정했다. 이 자료의 통과는 새로운 상담 11건의 생성 성공으로 세지 않는다. 제품 소스 해시에는 `privacy.mjs`도 추가했다.

설계와 제한 조건은 [ADR 0013](adr/0013-pending-handoff-scope.md)에 기록했다. 분석·인계 프로세스는 각각 최대 2개 요청, 별도 검토 대조는 순차 요청으로 실행했다(겹칠 때 최대 5개). 이 실행의 시간은 품질 확인 중 관측값이며 이전 지연 평가와 통제된 성능 비교를 한 것은 아니다.

설명 지침 보완 전의 생성·수정·검토 지침 5개를 [원문 그대로 보존](../evals/results/full-regression/draft-instructions.json)했고, 해당 지침이 바뀌지 않은 것도 확인했다. 다만 이후 서버의 미답변 표시 이유까지 바뀌었으므로, 최종 채택 실행은 분석·인계·검토 대조 모두 현재 소스 해시로 다시 실행해 확인한다. 중간 통과 결과를 최종 결과 대신 합산하지 않는다.

## 해석의 한계

고정된 합성 자료의 회귀 검사이며 실제 사용자 전체의 정확도를 보장하지 않는다. 같은 자료로 수정·재시험한 결과는 미사용 자료의 성능으로 해석하지 않는다. 실패가 발생해도 이전 프롬프트와의 동일 조건 반복 비교 없이는 이번 수정만을 원인으로 단정하지 않는다. 성공한 부분 실행만 골라 전체 통과로 합치지 않는다.

자유 생성하는 판정 이유의 표현까지 완벽하다는 뜻은 아니다. 최종 B06에는 제공되지 않은 화면별 경로를 부연했고, NR06에는 입금 여부 설명에 입금 시점까지 덧붙였다. 질문 상태·질문 목록·생성 초안의 요청 범위는 바뀌지 않았고 이 AI 설명은 초안의 사실 근거로 전달하지 않지만, 불필요한 부연을 줄일 문체 개선 여지는 남아 있다. 미답변의 원문 없는 제출 요건은 서버 표시 이유로 방지한다. 자연어 설명의 외부 검수와 미사용 자료 검증은 별도 후속 작업이다.
