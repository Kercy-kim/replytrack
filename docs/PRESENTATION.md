# ReplyTrack — 5분 발표 구성과 발표문

기준: 최대 5분, **30초 시연 결과 포함**, 핵심 기능과 구현 결과 중심. 아래는 4분 40초 분량의 배정안이며 20초를 전환·말속도 여유로 남긴다. 실제 말하는 시간은 발표자가 리허설로 확인한다. 프로젝트는 로컬 웹 시제품이며 배포·사용자 효과 검증까지 끝난 제품이라고 소개하지 않는다.

## 핵심 기능과 AI가 필요한 이유

| 기능 | 입력 | 처리·AI 역할 | 출력 |
| --- | --- | --- | --- |
| ① 질문별 답변 상태 | 여러 질문과 고객지원 답변 | AI가 질문별 대상·기간·조건을 비교한다. “접수했음”이 “완료됐는지”의 답인지처럼 표현의 의미를 구분한다. 서버가 인용을 검증한다. | 답변 받음·부분 답변·미답변·대기·확인 필요, 판단 이유, 원문 근거 |
| ② 지금 내가 할 일 | 업체 요청·후속 답변 | AI가 소비자 행동과 업체 약속, 조건·기한을 분리한다. 선택 자료와 필수 요청, 제출과 수신을 구분하고 검토한다. | 내가 보낼 자료·회신, 업체 처리 대기, 사용자 직접 수행 기록 |
| ③ 한국어 설명·영어 재문의 | 영어 원문·남은 질문 | AI가 조건·부정을 보존한 한국어 설명을 작성하고, 선택한 질문만 영어 초안으로 생성·검토한다. | 원문과 설명, 수정·복사 가능한 영어 답장. 자동 발송 없음 |
| ④ 새 답변 전후 비교 | 기존 기록·새 답변 | AI가 질문·약속을 갱신한다. **차이 계산은 일반 코드**가 이전·현재 상태와 동일 ID를 비교해 수행한다. | 이번에 답변받은 질문, 바뀐 약속, 남아 있는 실제 결과 확인 |

정형 키워드만으로는 같은 “확인”이 제출 요구인지, 업체의 처리 약속인지, 완료 통보인지 구별하기 어렵다. AI는 이 의미 해석과 문장 생성에 사용한다. OCR, 원문 문자열·발화자 검증, 저장, 날짜 계산, 상태 비교는 일반 코드가 담당한다. 실제 입금·계정 복구 여부는 사용자가 직접 확인한다.

## 시간 배분과 발표문

### 0:00–0:35 · 프로젝트와 문제

**화면에 둘 내용:** ReplyTrack / 바쁜 일상에서 끊긴 문의를 이어주는 AI 문의 관리 / 빠진 답변·할 일·진행 상황.

“ReplyTrack은 바쁜 일상에서 고객센터 문의를 이어가도록 돕는 AI 웹 서비스입니다. 며칠 뒤 답장을 열면 무엇을 물었는지 다시 읽어야 하고, 추가로 보내야 할 자료나 아직 답변받지 못한 질문을 놓치기 쉽습니다. 저희는 긴 대화를 질문, 내가 할 일, 상대방의 처리 약속으로 나누어 다음 행동을 찾도록 만들었습니다.”

### 0:35–1:05 · 사용자와 활용 상황

**화면에 둘 내용:** 반복 문의하는 일반 사용자 / 쇼핑·구독·계정 문제 / 영어 계정 복구 사례.

“예상 사용자는 배송이나 환불, 구독, 계정 문제로 여러 번 문의하는 일반인입니다. 오늘은 영어 계정 복구 문의를 예로 보여 드리겠습니다. 필요한 자료와 검토 기간을 함께 물었는데 자료만 안내받았다면, 받은 답과 남은 질문을 나눠 보여 주고 이후 답변까지 같은 기록으로 이어갑니다.”

### 1:05–2:25 · 핵심 기능 네 개

**화면에 둘 내용:** 위 입력→처리→출력 표를 네 행으로 압축. 각 기능의 실제 화면 캡처는 `.artifacts/presentation/desktop-0.png`~`desktop-3.png`에서 사용할 수 있다.

“첫째, 질문별 답변 상태를 분석합니다. AI가 단어의 유무뿐 아니라 질문한 대상과 조건을 비교하고, 각 판단에는 원문 근거를 붙입니다.

둘째, 지금 내가 할 일을 정리합니다. 내가 제출할 자료와 업체가 검토할 일을 분리합니다. 자료 수신 안내가 와도 실제 계정 복구를 완료로 바꾸지는 않습니다.

셋째, 영어 답변을 한국어로 설명하고 남은 질문만 영어로 다시 묻게 합니다. 조건과 금지 사항을 보존하고 생성된 초안을 다시 검토합니다. 발송은 사용자가 직접 합니다.

넷째, 새 답변을 반영했을 때 바뀐 질문과 약속을 보여 줍니다. AI가 상태를 분석한 뒤 일반 코드가 이전과 이후의 차이를 비교합니다.”

### 2:25–3:05 · AI 활용과 구현 구조

**화면에 둘 내용:** 원문 입력 → 사용자 검토 → AI 의미 분석·생성 → 원문·의미 검증 → 상태·할 일·초안 → 새 답변.

“이메일 본문이나 캡처를 입력하면, 캡처는 로컬 OCR로 읽고 사용자가 원문과 발신자를 확인합니다. OpenAI 모델은 질문과 답변의 의미를 분석하고 설명과 초안을 생성합니다. 서버는 인용이 원문에 있는지 검사하고 의미 검토도 수행합니다. 검증에 실패하면 기존 결과를 유지합니다. 화면은 웹으로 만들었고 Node.js 서버와 SQLite로 기록을 관리합니다.”

### 3:05–3:35 · 실제 AI 결과 30초 시연

발표 전에 앱의 **실제 AI 결과 30초 보기**를 열어 첫 장면에 둔다. 아래 문장과 함께 다음 버튼을 세 번 누른다. 실제 모델 응답을 기다리는 화면으로 오인되지 않도록 “사전 실행한 실제 AI 결과를 재생합니다”라고 소개한다.

| 구간 | 조작 | 말할 내용 |
| --- | --- | --- |
| 0–6초 | 문의 등록 | “필요한 자료와 검토 기간을 함께 물은 영어 문의입니다.” |
| 6–14초 | 설명과 할 일 | “거래 ID는 보내야 하고, 비밀번호는 보내면 안 됩니다. 기간은 아직 부분 답변입니다.” |
| 14–21초 | 영어 재문의 | “AI가 남은 기간 질문만 영어로 작성하고 검토했습니다.” |
| 21–30초 | 새 답변 비교 | “후속 답변에서 검토 기간을 받았고 자료도 접수됐습니다. 실제 계정은 아직 복구 전입니다.” |

시간이 남을 때만 원문 대조나 실행 근거를 펼친다. 화면 재생 중에는 추가 API 호출이나 사용자 기록 변경이 없다. 30초는 결과 설명 시간이며 실제 분석 작업의 응답 시간은 실행 근거에 따로 표시한다.

### 3:35–4:20 · 구현 결과와 테스트

**화면에 둘 내용:** 기존 배송·환불·구독 48건 / 상태 71회 / 약속·기한 22회 / 미해결을 답변 받음으로 오판 0회 / 최신 자동·브라우저 검사.

“기존 배송·환불·구독 48건을 실제 API로 평가했습니다. 처음에는 46건이 통과했고, 기간별 일부 정보 판정과 완료 통보 누락을 보완한 뒤 48건 모두 통과했습니다. 질문 상태는 71회, 약속과 기한은 22회를 확인했습니다. 오늘 시연한 이메일도 초기 요청부터 후속 답변까지 실제 API를 실행해 기록했습니다. 자동 테스트와 데스크톱·모바일 브라우저 검사로 원문 연결, 복사, 기록 보존과 결과 화면도 확인했습니다. 이 수치는 고정한 가상 사례의 평가이며 실제 사용자 전체의 정확도라는 뜻은 아닙니다.”

### 4:20–4:40 · 현재 범위와 다음 개발

“현재는 로컬 웹 시제품으로 핵심 흐름이 구현돼 있습니다. 메일함 자동 연동과 자동 발송, 외부 배포와 사용자별 계정 분리는 아직 구현하지 않았습니다. 다음에는 다양한 문의 사례와 실제 사용자 평가로 남은 질문을 찾는 시간과 다음 행동을 올바르게 이해하는지를 확인할 계획입니다.”

### 4:40–5:00 · 여유

전환·말속도 차이에 사용한다. 5분 제한을 맞추기 위해 SSG 안내, 확장 프로그램, 인계, 상세 코드 설명을 추가 시연하지 않는다. 질문이 들어오면 보조 기능이나 원본 평가 기록을 보여 준다.

## 예상 질문

- **그냥 번역·요약과 무엇이 다른가?** 질문별 남은 답, 행동의 주체, 새 답변 전후 상태를 원문과 연결한다. 업체 통보와 실제 결과 확인을 구분한다. 시장 유일성이나 경쟁사 기능 부재를 주장하지 않는다.
- **AI가 틀리면?** 원문 근거를 보여 주고 사용자가 수정할 수 있다. 인용·구조·의미 검토가 있으며 오류 시 이전 기록을 보존한다. 완전한 오류 차단을 보장하지 않는다.
- **실제 계정을 복구하는가?** 복구 절차에 관한 문의와 답변을 관리한다. 서비스 계정에 로그인하거나 복구를 대신 실행하지 않는다.
- **30초 안에 AI가 모두 끝나는가?** 사전 실행한 실제 결과를 30초 동안 설명한다. 원본 기록과 실제 작업 시간을 제공하며 실시간 실행이라고 소개하지 않는다.
- **앞으로 무엇을 평가하는가?** 다양한 이메일·서비스별 사례와 실제 사용자 10명 이상 평가를 계획한다. 평가 전부터 시간 절감이나 만족도가 입증됐다고 말하지 않는다.
