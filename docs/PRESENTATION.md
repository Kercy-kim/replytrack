# ReplyTrack — 5분 발표 구성과 발표문

기준: 최대 5분, **30초 시연 결과 포함**, 핵심 기능과 구현 결과 중심. 아래는 4분 40초 분량의 배정안이며 20초를 전환·말속도 여유로 남긴다. 실제 말하는 시간은 발표자가 리허설로 확인한다. 프로젝트는 로컬 웹 시제품이며 배포·사용자 효과 검증까지 끝난 제품이라고 소개하지 않는다.

## 핵심 기능과 AI가 필요한 이유

| 기능 | 입력 | 처리·AI 역할 | 출력 |
| --- | --- | --- | --- |
| ① 질문별 답변 상태 | 여러 질문과 고객지원 답변 | AI가 질문별 대상·기간·조건을 비교한다. “접수했음”이 “완료됐는지”의 답인지처럼 표현의 의미를 구분한다. 서버가 인용을 검증한다. | 답변 받음·부분 답변·미답변·대기·확인 필요, 판단 이유, 원문 근거 |
| ② 지금 내가 할 일 | 업체 요청·후속 답변 | AI가 소비자 행동과 업체 약속, 조건·기한을 분리한다. 선택 자료와 필수 요청, 제출과 수신을 구분하고 검토한다. | 내가 보낼 자료·회신, 업체 처리 대기, 사용자 직접 수행 기록 |
| ③ 한국어 설명·영어 재문의 | 영어 원문·남은 질문 | AI가 조건·부정을 보존한 한국어 설명을 작성하고, 선택한 질문만 영어 초안으로 생성·검토한다. | 원문과 설명, 수정·복사 가능한 영어 답장. 자동 발송 없음 |
| ④ 새 답변 전후 비교 | 기존 기록·새 답변 | AI가 질문·약속을 갱신한다. **차이 계산은 일반 코드**가 이전·현재 상태와 동일 ID를 비교해 수행한다. | 이번에 답변받은 질문, 바뀐 약속, 남아 있는 실제 결과 확인 |

정형 키워드만으로는 같은 “확인”이 제출 요구인지, 업체의 처리 약속인지, 완료 통보인지 구별하기 어렵다. AI는 이 의미 해석과 문장 생성에 사용한다. OCR, 원문 문자열·발화자 검증, 저장, 날짜 계산, 상태 비교는 일반 코드가 담당한다. 실제 입금·계정 복구 여부는 사용자가 직접 확인한다.

## 기존 서비스와 비교한 개선점

공식 공개 자료 확인 기준일은 **2026-11-15**이다. 아래는 기능 설명을 비교한 것으로, 경쟁 서비스의 전체 기능을 직접 시험하거나 같은 입력으로 성능을 비교한 결과가 아니다.

| 비교 대상·출처 | 공식 자료에서 확인한 기능 | ReplyTrack에서 강조할 구현 |
| --- | --- | --- |
| [Gmail의 Gemini](https://workspace.google.com/intl/en/products/gmail/ai/) | 이메일 대화 요약, 문맥에 맞는 답장 제안·작성 | 질문별 답변 충족 여부와 원문 근거를 기록하고, 후속 답변의 상태 변화를 표시 |
| [NoReply의 사건별 AI 대화](https://usenoreply.com/changelog/ai-chat-on-cases) | 업체·증거·진행 단계 맥락을 이용한 AI 대화, 다음 대응 안내, 대화 기록 유지 | 질문·행동·약속을 구분하고, 업체의 처리 안내와 사용자 직접 해결 확인을 별도 관리 |

[Gmail AI Inbox](https://support.google.com/mail/answer/16845247?hl=en)의 할 일·관련 원문, [NoReply의 진행 단계와 발송 전 확인](https://usenoreply.com/changelog), [Resolver의 개인 문의 기록](https://www.resolver.co.uk/resolver-for-businesses-frequently-asked-questions)도 참고했다. **할 일 추출·문의 관리 자체가 유일한 기능은 아니다.** 다음 행동을 알아보기 쉽게 하고 작성 결과를 확인하는 원칙을 반영해, 초안 생성에 사용한 질문과 선택·언어 변경 안내를 추가했다. 자세한 범위와 실제 공식 안내 검증은 [검증 기록](OFFICIAL-WEB-CORE.md)을 따른다. 인계 요약 생성은 제거하고 위 네 핵심 기능에 집중한다.

**발표 화면에 넣을 세 가지 개선점:** 질문별 답변 충족 여부 / 새 답변 전후 비교 / 업체 안내와 실제 해결 확인 분리. 모두 현재 로컬 시제품에 구현된 흐름이다. 요약·번역·답장 생성만을 독자 기능으로 소개하지 않는다. 경쟁사에 이 기능들이 없다는 주장이나 시간 절감·만족도가 입증됐다는 주장은 하지 않는다.

**시연과 연결할 예:** 필요한 자료와 심사 기간을 함께 물었을 때 자료만 구체적으로 안내받으면 자료 질문은 ‘답변 받음’, 기간 질문은 ‘부분 답변’이다. 후속 메일에서 영업일 3일이라는 기간을 받으면 기간 질문의 ‘부분 답변 → 답변 받음’을 보여 준다. 거래 ID 수신 안내는 업체 요청 재확인으로 표시하며, 이는 사용자의 직접 수행 확인과 구분한다. 질문에 모두 답변받아도 실제 계정 복구가 완료된 것은 아니다. 시연은 [실제 API 실행 기록](PRESENTATION-READINESS.md)을 재생하며 경쟁 서비스와의 비교 실험은 아니다.

**발표용 한 문장:** “ReplyTrack은 질문별 답변 충족 여부와 새 답변에 따른 변화를 원문 근거와 함께 추적하고, 업체의 처리 안내와 사용자의 실제 해결 확인을 구분하도록 개선한 문의 관리 서비스입니다.”

## 시간 배분과 발표문

### 0:00–0:35 · 프로젝트와 문제

**화면에 둘 내용:** ReplyTrack / 바쁜 일상에서 끊긴 문의를 이어주는 AI 문의 관리 / 빠진 답변·할 일·진행 상황.

“ReplyTrack은 바쁜 일상에서 고객센터 문의를 이어가도록 돕는 AI 웹 서비스입니다. 며칠 뒤 답장을 열면 무엇을 물었는지 다시 읽어야 하고, 추가로 보내야 할 자료나 아직 답변받지 못한 질문을 놓치기 쉽습니다. 저희는 긴 대화를 질문, 내가 할 일, 상대방의 처리 약속으로 나누어 다음 행동을 찾도록 만들었습니다.”

### 0:35–0:55 · 사용자와 활용 상황

**화면에 둘 내용:** 반복 문의하는 일반 사용자 / 쇼핑·구독·계정 문제 / 영어 계정 복구 사례.

“예상 사용자는 배송·환불·구독·계정 문제로 여러 번 문의하는 일반인입니다. 오늘은 필요한 자료와 심사 기간을 함께 물은 영어 계정 복구 문의를 예로 보여 드리겠습니다.”

### 0:55–1:25 · 기존 서비스와 개선점

**화면에 둘 내용:** 위 비교 표를 두 행으로 압축하고 공식 출처 링크를 유지한다. 아래에 질문별 답변 추적 → 전후 비교 → 실제 해결 확인을 표시한다. ‘공개 기능 설명 기준 · 경쟁사 전체 기능·성능 비교 아님’을 함께 표기한다.

“Gmail의 Gemini는 이메일 요약과 답장 작성을, NoReply는 사례 맥락을 활용한 AI 대화와 다음 대응 안내를 제공합니다. 저희는 질문마다 충분히 답변받았는지와 새 답변으로 바뀐 부분을 원문 근거와 연결했습니다. 또 업체의 처리 안내와 사용자의 실제 해결 확인을 분리했습니다. 시장 유일성보다는 문의를 이어가는 사용 흐름의 개선점입니다.”

### 1:25–2:35 · 핵심 기능 네 개

**화면에 둘 내용:** 위 입력→처리→출력 표를 네 행으로 압축. 각 기능의 실제 화면 캡처는 `.artifacts/presentation/desktop-0.png`~`desktop-3.png`에서 사용할 수 있다.

“첫째, 질문별 답변 상태를 분석합니다. AI가 단어의 유무뿐 아니라 질문한 대상과 조건을 비교하고, 각 판단에는 원문 근거를 붙입니다.

둘째, 지금 내가 할 일을 정리합니다. 내가 제출할 자료와 업체가 검토할 일을 분리합니다. 자료 수신 안내가 와도 실제 계정 복구를 완료로 바꾸지는 않습니다.

셋째, 영어 답변을 한국어로 설명하고 남은 질문만 영어로 다시 묻게 합니다. 조건과 금지 사항을 보존하고 생성된 초안을 다시 검토합니다. 발송은 사용자가 직접 합니다.

넷째, 새 답변을 반영했을 때 바뀐 질문과 약속을 보여 줍니다. AI가 상태를 분석한 뒤 일반 코드가 이전과 이후의 차이를 비교합니다.”

### 2:35–3:05 · AI 활용과 구현 구조

**화면에 둘 내용:** 원문 입력 → 사용자 검토 → AI 의미 분석·생성 → 원문·의미 검증 → 상태·할 일·초안 → 새 답변.

“본문이나 캡처를 입력하면 로컬 OCR과 사용자 검토를 거칩니다. OpenAI 모델이 의미를 분석하고 설명과 초안을 만듭니다. 서버가 원문 인용을 검사하고 AI 의미 검토도 수행하며, 검증 실패 시 기존 결과를 유지합니다. Node.js 서버와 SQLite를 사용하는 웹 시제품입니다.”

### 3:05–3:35 · 실제 AI 결과 30초 시연

발표 전에 앱의 **예제 · 도움 기능 → 실제 AI 결과 30초 보기**를 열어 첫 장면에 둔다. 아래 문장과 함께 다음 버튼을 세 번 누른다. 실제 모델 응답을 기다리는 화면으로 오인되지 않도록 “사전 실행한 실제 AI 결과를 재생합니다”라고 소개한다.

| 구간 | 조작 | 말할 내용 |
| --- | --- | --- |
| 0–6초 | 문의 등록 | “필요한 자료와 검토 기간을 함께 물은 영어 문의입니다.” |
| 6–14초 | 설명과 할 일 | “거래 ID는 보내야 하고, 비밀번호는 보내면 안 됩니다. 기간은 아직 부분 답변입니다.” |
| 14–21초 | 영어 재문의 | “AI가 남은 기간 질문만 영어로 작성하고 검토했습니다.” |
| 21–30초 | 새 답변 비교 | “후속 답변에서 검토 기간을 받았고 자료도 접수됐습니다. 실제 계정은 아직 복구 전입니다.” |

시간이 남을 때만 원문 대조나 실행 근거를 펼친다. 화면 재생 중에는 추가 API 호출이나 사용자 기록 변경이 없다. 30초는 결과 설명 시간이며 실제 분석 작업의 응답 시간은 실행 근거에 따로 표시한다.

### 3:35–4:20 · 구현 결과와 테스트

**화면에 둘 내용:** 과거 배송·환불·구독 48건 평가 / 최신 재문의 20건 원문 대조·검토 대조 30개 / 최신 자동·브라우저 검사. 각 평가 시점·범위는 [마무리 점검](FINAL-CHECK.md)과 연결된 기록을 따른다. 서로 다른 평가의 개수를 합쳐 하나의 정확도로 제시하지 않는다.

## 예상 질문

- **기존 서비스도 있는데 개선점은 무엇인가?** Gmail의 Gemini와 NoReply에도 요약·답장 작성 또는 사례별 대응 안내가 있다. ReplyTrack은 질문별 답변 충족 여부, 새 답변 전후 비교, 업체 안내와 실제 해결 확인의 분리를 원문 근거와 연결한 흐름에 집중한다. 이는 현재 구현한 개선 방향이며 시장 유일성이나 경쟁사 기능 부재·성능 우위를 검증한 결과는 아니다. 구체적인 사용 시간·누락 감소 효과는 실제 사용자 평가가 남아 있다.
- **AI가 틀리면?** 원문 근거를 보여 주고 사용자가 수정할 수 있다. 인용·구조·의미 검토가 있으며 오류 시 이전 기록을 보존한다. 완전한 오류 차단을 보장하지 않는다.
- **실제 계정을 복구하는가?** 복구 절차에 관한 문의와 답변을 관리한다. 서비스 계정에 로그인하거나 복구를 대신 실행하지 않는다.
- **30초 안에 AI가 모두 끝나는가?** 사전 실행한 실제 결과를 30초 동안 설명한다. 원본 기록과 실제 작업 시간을 제공하며 실시간 실행이라고 소개하지 않는다.
- **앞으로 무엇을 평가하는가?** 다양한 이메일·서비스별 사례와 실제 사용자 10명 이상 평가를 계획한다. 평가 전부터 시간 절감이나 만족도가 입증됐다고 말하지 않는다.

## 개발 우선순위 고정

앞으로도 문제·목적·예상 사용자와 사용 상황을 먼저 설명하고, 핵심 기능 네 개마다 사용자 필요·AI 역할·입력→처리→출력을 연결한다. 30초 시연은 질문 상태 → 설명과 할 일 → 남은 질문의 영어 재문의 → 새 답변 변화에 집중한다. Chrome 확장은 제거했다. 공식 참고 안내는 지원하는 문의처에서 원문·조건 검토를 통과할 때만 자동 표시하는 보조 기능이며 시연 시간을 늘리지 않는다. 최신 시연·검증 범위는 [마무리 점검](FINAL-CHECK.md)을 따른다.
