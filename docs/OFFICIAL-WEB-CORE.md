## 공식 안내 실검증 방법

`scripts/check-official-live.mjs --run`은 실제 Chrome에서 문의를 열고 제품의 POST·폴링·공식 안내 렌더링을 사용한다. 공식 사이트의 현재 본문 조회와 생성·독립 검토는 실제 OpenAI `gpt-5-mini-2025-08-07` 호출이다. 문의 원문은 아래 고정 가상 사례다. **이 검사는 저장된 분석 결과를 fixture로 준비**하므로 등록·분석의 정확도 평가로 계산하지 않는다. 등록부터 재문의까지는 별도 실제 API 웹 흐름으로 확인한다.

각 문의에서 편집 중인 답장을 넣은 뒤 공식 결과를 기다렸다. 390px·1280px 화면 넘침, 출처 링크, 오류, 편집 보존, DB 질문·약속·초안 무변경을 검사한다. 조회에 실패하거나 확실하지 않으면 빈 공식 안내 영역으로 남는다. 모든 사이트를 자동 검색하는 기능이 아니며 지원 범위는 SSG 일반 상품, Google·Microsoft·Apple 계정 복구다.

## 반복 검증에서 발견하고 수정한 문제

동일 main 동작의 두 번째 [검증 기록](../evals/results/email-reply/official-web-final.json)은 8/10이었다. 파일명의 `final`은 당시 실행 이름이며 최종 통과본이 아니다. 정상 Microsoft 문의는 검토기가 선택적 기기·장소·전체 절차 설명까지 요구해 생략됐고, 개인 Apple 완료일을 확정하라는 질문에는 일반 상태 조회 방법을 대신 표시했다. Apple 완료를 확정한 오답은 아니었지만 질문에 직접 답하지 않는 안내였다.

- 필수 이용 제한과 선택 권고를 구분했다. 복구 양식의 2단계 인증 관련 제한은 보존하며, 질문하지 않은 전체 절차를 요약에 강제하지 않는다.
- 검토 스키마에 `answersQuestion`을 추가했다. 개인별 결과를 알 수 없는 질문에 일반 조회 방법으로 대체하면 즉시 생략한다. 근거·조건 검토가 실패한 경우의 한 차례 수정과 60초 제한은 유지한다.
- Microsoft 반복 출력에서 `working email`을 ‘작업용 이메일’로 옮긴 사례도 확인했다. 수신 가능한 연락용 이메일이라는 뜻과, 서비스별 자료는 해당 서비스를 사용한 경우에만 적용한다는 지침을 생성·검토 양쪽에 추가했다. 이전 [반복 기록](../evals/results/email-reply/official-web-repeat-ms.json)의 `passed`는 표시·UI 검사 통과이며 이 표현 문제까지 합격했다는 뜻이 아니다.

중간 [조건 구분 수정본](../evals/results/email-reply/official-web-repaired.json)도 보존했다. 모든 실패·중간 출력은 삭제하거나 성공 실행에 합산하지 않았다.
