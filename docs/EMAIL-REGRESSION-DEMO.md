# 이메일 추가 후 전체 AI 회귀와 30초 시연

평가일: 2026-11-15. 이메일 기능이 병합된 main `305d4b7`에서 시작했다. 모델은 실제 OpenAI Responses API의 `gpt-5-mini-2025-08-07`이다. 준비된 발표 화면의 결과를 AI 품질 점수에 포함하지 않는다.

## 평가 범위

기존 고정 자료를 변경하지 않고 배송 17건·환불 17건·구독 14건, 총 48건을 실행한다. 초기·후속 분석 55회, 질문 상태 71회, 기대 처리 약속·기한 22회, 미해결 질문 37회와 지정된 초안 13건을 확인한다. 초안은 재문의 7건·인계 6건이다. 정답·채점기·대화·모델은 고정하며, 원문 인용과 근거 메시지, 약속 상태·기한, 후속 질문 ID 유지도 검사한다.

## 발견한 문제와 수정

최초 전체 실행은 **46/48건**, 질문 상태 **70/71회**, 약속·기한 **21/22회** 통과였다. 미해결 질문을 답변 받음으로 처리한 오류는 없었다.

1. **U03: 기간별 요금의 부분 정보 누락.** 다음 달 요금 9,900원과 이번 달 금액 미정을 함께 안내했지만 확인 필요로 분류하고 다음 달 금액을 설명에서 지웠다. 미정 표현만 보고 판정을 끝내지 않고, 같은 요금의 다른 기간 정보를 먼저 확인하도록 분석·경계 검토 지침을 보완했다. 별도 질문의 답이나 무관한 요금을 가져오지는 않는다.
2. **NR06: 환불 승인 완료 통보 누락.** 질문은 답변 받음으로 맞게 판정했지만 처리 약속 목록에서 승인이 빠졌다. 미래 행동 약속뿐 아니라 이미 수행한 업무도 `reported`로 추출하도록 문구를 명확히 했다.
3. **U01: 문구 수정만으로 해제 통보 누락이 재현됨.** 완료 표현이 있는데 생성된 약속 목록이 비어 있을 때만 별도 의미 검토를 추가했다. 단어 검출은 AI 재검토를 시작하는 조건이며 자동 완료 판정이 아니다. 일반 정책·부정·가정·단순 값 안내에는 빈 배열을 허용한다. 근거 인용·질문 연결·기한을 검증하고 실패·취소 시 저장하지 않는다. 기존 ID와 사용자 직접 확인은 유지한다.

별도 검토를 개발하면서 질문 ID 제약이 제목·기한까지 공유되는 스키마 오류, 단순 이용 종료일 안내를 처리 완료 항목으로 만드는 오류도 발견해 수정했다. 스키마 객체 분리 회귀 테스트와 실제 양성·음성 대조 평가를 추가했다. 원래 누락된 NR06·U01 출력과 일반 기간 안내 R05를 재생한 최종 검토는 **3/3건 통과**했다. 최초 분석은 저장 출력 재생이고, 추가 검토는 실제 API라는 점을 구분한다.

이메일 병합 전후의 공통 `src/prompts.mjs`는 동일했다(`4e292df` → `305d4b7`). 따라서 최초 실패를 이메일 기능의 인과 효과로 단정하지 않는다. 이번 평가에서 재현된 기존 경계·누락 문제를 수정한 것이다. [ADR 0018](adr/0018-email-regression-and-presentation.md)에 공통 지침 수정과 조건부 추가 호출의 이유를 기록했다.

이메일 평가기의 본문 동등성 비교는 줄바꿈·연속 공백만 하나의 공백으로 정규화하도록 수정했다. 단어·문장 순서·문장부호 검사는 유지하며 48건의 자료나 채점기는 변경하지 않았다. 선택 자료를 실제 제출 요청으로 만들지 않는 검사와 직접 수행 자동 확인 방지 검사는 강화했다.

이메일 전체 흐름 재검증에서 선택 사항인 스크린샷을 제출 요청으로 생성한 결과가 의미 검토에서 차단되었다. 잘못 저장되지는 않았지만 작업 실패를 줄이기 위해 이메일 전용 지침에 선택 가능성만으로 할 일을 만들지 않는 기준을 추가했다. 일반 상담 48건에는 이메일 지침이 적용되지 않는다.

## 최종 결과

최종 전체 실행은 **48/48건 통과**했다. 원본을 다시 채점해 같은 결과를 확인했고, 기록된 전체 평가 소스 해시가 현재 코드와 일치한다. 고정 자료와 채점기의 해시도 최초 실행과 같다.

| 항목 | 최초 | 최종 |
| --- | --- | --- |
| 전체 상담 | 46/48 | 48/48 |
| 초기·후속 분석 | 53/55 | 55/55 |
| 질문 상태 | 70/71 | 71/71 |
| 기대 약속·기한 | 21/22 | 22/22 |
| 질문 근거 메시지 | 71/71 | 71/71 |
| 원문 인용·참조 | 165/165 | 166/166 |
| 미해결을 답변 받음으로 오판 | 0/37 | 0/37 |
| 지정 초안 생성·검토 | 13/13 | 13/13 |

판정 이유 71개와 초안 13건을 개발 에이전트가 원문에 대조했다. 선택 질문 누락, 근거 없는 완료·담당자 주장, 정정·상충 순서 오류를 발견하지 않았다. 일부 조사·시제 표현은 다듬을 여지가 있으며 세부 대조 기록은 [semantic-review.json](../evals/results/email-regression/semantic-review.json)에 보존한다. 원본 초안의 pending 표시는 수정하지 않고 이 별도 대조 기록으로 검토 여부를 남긴다.

실제 이메일은 계정 복구와 중복 청구의 **2/2건 전체 흐름 통과**다. 최종 근거는 계정 복구의 email-final-v3.json 내 해당 사례와 청구의 email-billing-final-v4.json이다. 본문 추출·초기 분석·한국어 설명·영어 초안·새 답변 추출·재분석·설명 갱신·업체 요청을 확인했다. 선택 스크린샷을 할 일로 추가하지 않았고 수신·검토·실제 결과 확인도 구분했다.

전체 48건 실행의 API 호출은 94→92회, 입력+출력 토큰은 416,248→409,073개였다. 최종 분석 중앙값 13.99초·p95 23.73초, 초안 중앙값 9.74초·p95 14.94초였다. 모델 변동과 캐시·동시 실행의 영향을 받는 단회 비교로, 비용·속도 개선의 인과 효과라고 주장하지 않는다. 조건부 완료 검토는 최종 전체 실행에서 R05의 일반 안내를 빈 목록으로 확인하는 1회(약 2.02초)였으며 실제 누락 보완은 별도 고정 출력 재생 3건으로 검증했다.

## 원본 기록과 중간 실행

모든 파일은 [평가 원본 폴더](../evals/results/email-regression/)에 보존한다. 이름에 `final`이 있어도 완료 여부와 아래 설명을 함께 확인한다.

| 파일 | 성격 |
| --- | --- |
| `baseline.json` | 이메일 추가 main의 최초 전체 48건. 46건 통과, U03·NR06 실패 |
| `boundary-targeted.json` | 기간별 부분 정보 수정 후 U03·B02·B05, 3/3 통과 |
| `final.json` | 첫 지침 수정만 적용한 중간 실행. 추가 문제 발견으로 13건에서 중단. R03 후속의 대기→부분 답변 오류도 보존 |
| `final-v2.json` | 완료 통보 문구 보완 후 30건에서 중단. U01 처리 통보 누락으로 추가 검토 필요 확인 |
| `final-v3.json` | 새 검토 경로의 스키마 오류 발견 후 8건에서 중단. 전체 통과 자료로 사용하지 않음 |
| `completion-controls.json` | 실제 누락 출력과 음성 대조의 검토. 스키마 공유 오류가 있던 첫 실행 |
| `completion-controls-final.json` | 스키마 수정 후 단순 종료일을 처리로 추출한 실패 보존 |
| `completion-controls-v3.json` | 최종 조건부 검토 대조, 3/3 통과 |
| `email-after-fix.json` | 문구 수정 단계의 실제 이메일 전체 흐름, 2/2 통과 |

중간에 중단한 실행도 비용은 발생했으며 최종 수치에 섞거나 숨기지 않는다. 각 전체 평가에는 시작 시 소스·정답 파일 SHA-256, 실제 응답과 사용량, 호출 시간, 분석 기록을 보존한다. API 키·실제 개인 상담은 기록하지 않는다.

## 30초 발표 구현

왼쪽 **이메일 30초 시연**에서 영어 계정 복구 문의를 네 장면으로 보여 준다.

| 구간 | 시연 기능 |
| --- | --- |
| 0–6초 | 내가 보낸 문의와 고객지원 영어 답변 |
| 6–14초 | 한국어 설명, 거래 번호 제출 요청, 보내지 말라는 정보, 아직 모르는 검토 기간 |
| 14–21초 | 검토 기간만 묻는 영어 재문의 초안·복사 |
| 21–30초 | 준비된 후속 답변 반영, 기간 질문의 부분 답변→답변 받음 비교, 실제 계정 복구 전 상태 |

기존 비교·질문·업체 요청 도메인 함수를 재사용한다. 새 답변은 한 번만 추가하며, 이전 장면 이동·새로고침 후에도 중복 반영하지 않는다. 근거 원문 열기와 상담 전체 보기도 제공한다. 모든 장면은 **준비된 결과·API 호출 없음**을 표시한다. 실제 이메일 입력·분석을 30초 안에 끝낸다는 의미가 아니며 발표 대본은 [시연 안내](DEMO.md)에 있다.

## 자동·브라우저 검증

- 자동 테스트 199개 통과. 누락 보완, 일반 안내의 빈 결과, 불필요한 추가 호출 방지, 원문·상태·질문 연결·기한 오류의 저장 차단, 취소, 사용자 확인·기존 ID 유지, 공유 스키마 불변성 포함.
- 문법 검사 98개 JavaScript 파일 통과.
- Chrome 발표 화면: 1366×900에서 네 장면의 다음 버튼을 화면 안에서 확인, 영어 초안 복사·근거 모달·뒤로 이동·중복 답변 방지·전체 보기·새로고침·390px 모바일 가로 넘침 검사 통과. API 호출 0회 확인.
- 기존 이메일 Chrome 흐름: 본문 입력, **실제 로컬 Tesseract OCR**, 발신자·원문 검토, 한국어 설명, 영어 초안, 새 답변 비교, 설명 갱신, 새로고침, 모바일 통과. 이 브라우저 검사의 AI 전송은 결정적 테스트 응답이며 실제 API 품질 평가는 위 별도 결과다.
- 브라우저 중간 검사에서 새 검토 응답 형식이 빠진 테스트용 AI 응답을 발견해 보완한 뒤 재통과했다. 스크린샷·검사 로그는 gitignored `.artifacts/email-demo`, `.artifacts/email-browser`에 생성한다.

```powershell
node --test
node scripts/check.mjs
node scripts/evaluate-ai.mjs --rescore evals/results/email-regression/final-v4.json
# 실제 API를 다시 실행할 때는 .env를 로드하고 새 --out 파일명을 사용한다.
node --env-file=.env scripts/evaluate-ai.mjs --suite full --model gpt-5-mini-2025-08-07 --out .artifacts/new-full-eval.json
```

기존 이메일·캡처 기능, 일반 상담, 환불·A/S 예제는 유지한다. 메일함 연결·자동 발송·별도 메모·리마인더를 추가하지 않았다. 고정 합성 사례는 개발 에이전트가 원문과 대조했으며 외부 사람의 독립 품질 평가가 아니다. 모델 출력 변동, 미관측 표현의 누락, 실제 사용자 사용성은 남은 검증 범위다. 추가 검토는 목록이 비었을 때만 발동하므로 이미 일부 항목이 있는 목록의 모든 누락을 보장하지 않는다.
