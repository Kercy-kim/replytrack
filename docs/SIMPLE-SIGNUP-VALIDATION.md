# 초대 코드 없는 가입 검증

2026-11-17. 링크 접속 후 아이디·비밀번호로 가입하도록 변경했다. 가입 즉시 로그인하며 사용자별 문의 기록은 계속 분리한다. AI 프롬프트·모델·분석 로직은 변경하지 않았다.

## 자동 테스트 — 실제 OpenAI 호출 없음

- 전체 **285개 테스트 통과**, JavaScript **149개 파일 문법 검사 통과**.
- 코드 없이 가입하고 발급받은 세션으로 `/api/auth/me`와 문의 API에 즉시 접근한다.
- 동시 가입 12건 중 기존 정원에 맞춰 10건만 성공한다. 같은 아이디의 대소문자·공백 변형을 동시에 등록하면 하나만 성공한다.
- 잘못된 아이디·짧은 비밀번호·관리자 아이디 중복을 거부한다. 클라이언트가 관리자 역할·소유자 ID를 보내도 서버가 생성한 ID의 참여자로만 가입한다.
- 중복 가입으로 기존 암호를 덮어쓰지 못한다. 가입 시도 제한·세션 만료·로그아웃·초기화 후 기존 암호 보존·사용량 집계를 확인했다.
- 다른 계정 문의의 조회·수정·삭제·원문·초안·공식 안내·작업 진행 조회/취소는 차단한다. 타 사이트나 Origin 없는 가입 요청도 차단한다.
- 제거한 초대 코드 발급 API는 로그인 관리자에게도 404를 반환한다. 이전 초대 테이블을 삭제하거나 운영 자료를 변경하지 않는다.
- 10명 동시 작업 시험은 고정 AI 응답을 사용하며 최대 실행 2개와 사용자별 결과 분리를 검증한다. SQL 검증은 PGlite PostgreSQL 엔진을 사용했다.

## 웹 확인

API 호출을 차단한 로컬 서버에서 가입·로그인 화면 전환을 확인했다. 가입 화면에는 아이디·비밀번호·비밀번호 확인만 있고 초대 입력은 없다. 초대 코드 없이 등록한 두 계정으로 차례로 로그인해 각자의 문의 1개만 보이는지 확인했다. 참여자 메뉴에는 관리자 설정·초대 기능이 없고, AI 작업 수는 0회다.

## 유료 API와 배포 확인 범위

이 변경은 인증 흐름만 수정하므로 배송·환불·구독 전체 유료 평가를 반복하지 않는다. 운영 배포 후 짧은 실제 OpenAI 연결 점검 1회로 기존 API 연결만 확인하며, 운영 화면·기존 문의 보존·가입 화면과 배포 커밋은 별도로 확인해 PR에 결과를 기록한다.

이전 실제 평가에서 발견한 의미 판정 2건은 [최종 운영 점검](FINAL-PILOT-CHECK.md)에 남아 있으며 이번 가입 변경으로 수정됐다고 주장하지 않는다. 참여자 최대 10명과 비밀번호 12자 이상, 계정별 문의 30개, 동시 실행 제한은 유지한다.
