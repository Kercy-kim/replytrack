# ADR 0015 — 환불·교환 상담과 지금 내가 할 일

- 상태: 채택
- 날짜: 2026-11-15

## 목적과 범위

주 사용자를 환불·교환을 위해 반복 문의하는 소비자로 좁힌다. 이전 A/S·배송·구독 기록과 기존 분석·초안 동작은 유지한다. README의 5주 기획 일정에 배포·사용자 평가 목표를 포함하되 완료로 주장하지 않는다. Google 로그인·Gmail 수집·번역은 이번 범위가 아니다.

## 결정

- `nextActions`는 선택적 상담 속성이다. 기존 DB 마이그레이션 없이 이전 기록을 열 수 있다.
- 업체가 소비자에게 명시한 행동만 AI로 추출한다. 일반 안내·소비자의 계획·업체의 처리 약속을 소비자 할 일로 옮기지 않는다. 원문에 없는 행동을 권고하지 않는다.
- 요청은 `requested`, 대화의 수행 안내는 `reported_done`, 업체의 철회는 `withdrawn`이다. 원래 요청은 agent 근거가 필요하고 수행·철회 안내는 요청 이후의 원문을 요구한다. 철회 근거도 agent여야 한다. 원문에서 누락된 이전 요청은 `review`로 보존한다.
- 선행 조건과 수행 기한은 요청 원문의 부분 문자열로 제한한다. 날짜는 기존 제한된 한국 시간 계산기로 처리하고 영업일·기준 불명은 미정으로 남긴다. 업체 처리 기한을 소비자 기한으로 바꾸지 않는다.
- 생성 1회와 의미 검토 1회, 최대 2회의 AI 요청을 한다(연결 사전 점검은 필요 시 별도). 자동 수정을 반복하지 않는다. 검증·검토 실패 시 기존 기록을 유지하고 재시도할 수 있다. 기존 질문 분석·초안·인계 경로의 모델·프롬프트·호출 수는 변경하지 않는다.
- 사용자가 `업체 요청 확인하기`로 실행한다. 실제 단계·경과 시간·취소와 낙관적 버전 검사를 재사용한다. 새 메시지 뒤에는 이전 기록임을 표시하고 갱신 전 직접 수행 표시를 거절한다.
- 직접 수행 시각 `completedAt`은 사용자의 조작으로만 기록한다. 업체의 수신 안내만으로 직접 완료하지 않는다. 동일 요청의 재추출 때 직접 수행 표시를 유지하고, 명시적인 재제출은 새 요청으로 다룬다. 수행·취소는 질문 상태, 처리 약속, 생성·편집 초안을 바꾸지 않는다.
- AI 제안은 최신 질문·약속 분석의 파생 표시다. 미답변·부분 답변·확인 필요 질문은 재문의로 연결하고, 업체 처리 안내는 실제 결과 확인으로 연결한다. 답변 대기와 처리 예정 약속은 업체 대기로 별도 표시한다. 제안은 업체 요청으로 저장하지 않는다.
- 웹 예제는 환불 시나리오로 바꾼다. `/api/demo`에서 `scenario: refund`를 선택하며 기존 기본 A/S API·저장 예제도 지원한다. 예제는 유료 AI 호출이 없는 가상 자료임을 표시한다.

## 검증과 한계

서버의 인용·발화자 검증만으로 의미 오류를 전부 방지할 수 없어 별도 AI 검토와 원문 확인을 유지한다. 자동 검사·격리된 HTTP/브라우저 검증은 실제 모델의 정답률이나 사용자 만족도를 입증하지 않는다. 현재 로컬 실행 환경에 API 키가 설정되어 있지 않아 이번 새 추출 프롬프트의 실제 공급자 품질 평가는 수행하지 않았다. 검증 범위는 `docs/NEXT-ACTIONS-VALIDATION.md`에 기록한다.
