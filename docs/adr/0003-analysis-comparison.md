# ADR 0003 — 검증 후 상태의 분석 전후 비교

- 상태: 채택
- 날짜: 2026-11-14

## 결정

전후 비교는 추가 LLM 요청 없이 서버에서 계산한다. `applyAnalysis`의 원문 근거 검증·사용자 지정 상태 보존·기한 계산·기존 항목 보존을 모두 마친 뒤, 적용 직전 상태와 적용할 상태를 같은 ID로 비교한다. 잘못된 근거의 AI 원시 출력을 비교 결과로 노출하지 않는다.

- 질문의 실제 상태 변경과 새 질문을 기록한다. 사용자 지정 상태가 유지될 때 바뀐 AI 제안은 별도로 기록한다.
- 약속의 추가·내용·업체 안내 상태·기한을 기록한다. 같은 확정 날짜를 다른 문구로 표현한 것은 기한 변경으로 보지 않는다. 날짜가 미정이면 원문 기한 표현의 변경을 보존한다.
- 실제 처리 확인은 사용자가 정한다. 업체의 처리 안내를 사용자 확인 완료로 해석하지 않는다.
- 첫 분석, 새 업체 답변, 추가 대화, 같은 원문 재분석을 구분한다. 성공한 이전 분석의 메시지 개수로 이번에 반영한 메시지를 식별한다.

최신 비교는 `analysis.comparison`, 과거 비교는 해당 `history` 항목의 `comparison`에 저장한다. 저장하는 것은 변경된 항목의 작은 스냅샷과 원문 메시지 ID이며, 전체 상담 원문을 복제하지 않는다. 이후 수동 수정이 과거 스냅샷을 바꾸지 않는다. 현재 상태와 차이가 생길 수 있다는 안내를 화면에 표시한다. 기존 이력의 최근 150개 이벤트 제한을 따른다.

질문·약속·비교·이력은 기존 SQLite 레코드 버전 검사로 함께 저장한다. 분석 실패나 충돌 시 이전 비교를 덮어쓰지 않는다. 새 원문이 미분석 상태라면 마지막 성공한 비교임을 명시한다.

## 호환성과 화면

기존 JSON 레코드에 필드를 추가하므로 SQL 스키마 변경이 없다. 비교가 없는 예전 기록은 정상적으로 열리고 다음 성공한 분석부터 비교를 저장한다. 과거 상태를 추측해서 소급 생성하지 않는다.

웹 상세 화면에서 질문과 약속의 변경을 나란히 표시하고 원문으로 연결한다. 성공 직후 비교 제목으로 포커스·스크롤을 이동한다. 좁은 화면에서는 두 묶음을 세로로 배치한다. `변경 이력`에서 각 분석의 비교를 펼쳐 볼 수 있다. 확장 프로그램에서는 기존 `웹에서 기록·수정`으로 같은 상담의 전후 비교를 확인한다.
