# ADR 0024 — 재문의 검토와 수정의 원문 경계

- 상태: 채택
- 날짜: 2026-11-16

## 문제

실제 평가 S04에서 정상적인 배송비 재문의에 검토 AI가 배송지 추가를 요구했다. 생성기는 정책 예시의 제주도를 사용자 주소로 바꿨고 다음 검토도 승인했다. 문장을 직접 읽어 발견했으며 질문 상태 채점만으로는 검출되지 않았다. 프롬프트 보강 후에도 잘못된 피드백을 주입하면 불필요한 새 질문이 추가됐고, 역할이 뒤바뀐 초안을 단일 승인값이 통과시키는 변동이 있었다.

## 결정

1. 재문의 검토를 소비자 관점·선택 질문 전체 포함·원문 사실·추가 요청 없음의 네 항목으로 나눈다. `valid=true`와 네 항목의 명시적인 `true`가 모두 있어야 저장한다. 누락·불일치는 거절한다. 기존 할 일 검토의 `featureReviewSchema`·`reviewPassed` 체계를 재사용한다.
2. 의미 검토 거절 뒤에는 검토기의 자유형 요구와 거절된 초안을 생성 입력으로 재전달하지 않는다. 원래 메시지와 선택 질문을 기준으로 고정된 안내에 따라 한 번 다시 작성하고 다시 검토한다. 검토 출력의 제안은 새로운 원문 사실이나 사용자 요구가 될 수 없다.
3. 서버의 형식·숫자·근거 검증 오류는 신뢰된 코드의 구체적인 수정 안내를 유지한다. AI의 자유형 제안과 구분한다.
4. 생성·검토 최대 두 쌍, 실패 시 기존 초안 보존, 취소·버전 충돌 검사는 유지한다. 새 API 단계나 별도 제품 기능을 추가하지 않는다.

## 검증과 한계

기존 재문의 7건, 오류·정상 대조, 잘못된 피드백 재현, 실제 질문 누락의 정상 수정, 영어 웹 흐름을 확인한다. 상세 결과와 실패 기록은 [종합 점검](../USABILITY-COMPLETENESS.md)에 보존한다. 항목별 검토도 모델 판단이므로 완전한 사실 보증은 아니다. 사용자의 원문 확인·편집·직접 발송은 유지한다.
