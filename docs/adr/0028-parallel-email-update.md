# ADR 0028 — 짧은 이메일 갱신의 질문·처리 약속 병렬 분석

- 상태: 채택
- 날짜: 2026-11-16
- 보완: ADR 0026의 첫 분석 분기. 초기 추출·정정·긴 대화는 기존 경로를 유지한다.

## 문제

실제 시연 기록에서 새 답변 반영은 84.308초였다. 첫 분석 55.719초 뒤 일반 심사 소요 기간을 개별 약속의 기한으로 연결한 결과를 28.586초 동안 재검토했다. 같은 작업에서 질문 판정과 여러 행동의 약속을 함께 출력하게 하는 후보는 자료 수신·심사·후속 통지를 합치거나 누락하기도 했다.

## 결정

1. 새 고객 질문 없이 업체 답변만 추가된 짧은 이메일 중 기존 처리 약속이 있는 경우 질문 판정과 약속·요약 분석을 병렬 요청한다. 질문 4개 이하, 메시지 6개 이하, 총 2,500자 이하이며 이메일 정정·기존 기한의 변경 단서가 없어야 한다. 이 범위를 벗어나면 기존 단일 분석을 유지한다.
2. 두 요청 모두 전체 원문과 기존 질문·약속을 받는다. 모델과 기존 low/medium 선택 규칙은 바꾸지 않는다. 질문에는 기존 전체 분석 지침을, 약속에는 기존 약속 전용 재검토 지침과 행동 구분 지침을 적용한다.
3. 약속 출력에서 기존 행동의 갱신과 새로운 행동을 구분한다. 기존 갱신 ID는 저장된 ID로 제한하고, 새 행동에 기존 ID를 재사용하면 재검토한다. 서버는 배열과 질문 원문 연결만 복원하며 의미·상태·기한을 대신 결정하지 않는다.
4. 자료 수신만을 근거로 기존 검증·심사 약속이 이행됐다고 바뀌면 같은 한 번의 medium 재검토로 보낸다. 재검토에서도 같은 오류가 남으면 이전 기록을 보존한다. 이 검사는 제한적인 영어 단서 검사이며 모든 의미 오류를 찾는 규칙이 아니다.
5. 두 요청이 모두 끝난 뒤 합친 결과에 기존 인용·역할·상태·의미 검사를 적용한다. 한 요청 실패 시 다른 요청을 취소하고 모두 정리한 뒤 실패를 반환한다. 사용자 취소·버전 검사도 유지한다. 부분 결과를 먼저 저장하지 않는다.
6. 두 요청의 관측 사용량을 모두 합산한다. 기존 첫 분석 지연 보조 요청의 동시 제한은 유지한다. 논리 분석·검토 호출은 기존 최대 4회에서 이 경로에 한해 최대 5회가 될 수 있다. 취소된 보조 요청의 비용은 확인되지 않을 수 있다.

## 검증과 한계

[성능·품질 기록](../EMAIL-UPDATE-TAIL-LATENCY.md)에 같은 기준 main과 교차 반복한 완료 시간, 전체 사용량, 중간 실패 후보와 최종 회귀 결과를 기록한다. 출력 지침 축소만으로 충분하다는 가정은 채택하지 않았다. 병렬화는 모든 요청의 상한 시간을 보장하지 않으며 요청 수와 토큰이 늘 수 있다. 기존 문맥에 기반한 가상 자료 평가이며 실제 사용자 전체의 정확도를 뜻하지 않는다.
