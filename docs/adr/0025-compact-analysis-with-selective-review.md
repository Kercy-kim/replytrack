# ADR 0025 — 중복 분석 출력 축소와 선택적 정밀 재검토

- 상태: 채택
- 날짜: 2026-11-16
- 보완: ADR 0020·0022의 추론 분기와 이메일 답변 출력 범위를 일반 상담에도 확장한다. ADR 0021의 지연 보조 요청과 ADR 0024의 재문의 검토는 유지한다.

## 결정

1. 일반 상담 분석에서 화면이 사용하지 않는 질문별 `followUp` 출력을 제거한다. 실제 재문의는 선택 질문·원문을 기준으로 별도 생성·검토하므로 그대로 유지한다. 초기 이메일 요청은 기존 스키마·지시·medium 추론을 유지한다. 저장 모델은 없는 `followUp`을 빈 문자열로 받으며 기존 기록과 예제는 호환된다.
2. 고객의 새 질문 없이 업체 답변만 추가되면 일반 상담도 기존 이메일처럼 질문 제목·source·ID를 로컬에서 보존한다. 전체 메시지와 기존 질문·약속을 모델에 제공하고 상태·이유·근거·약속을 다시 판단한다. 출력에서 제목·source·followUp 중복만 제거한다. 질문 누락·추가·중복은 전체 스키마와 medium으로 한 번 재검토한다. 사용자의 제목·상태 수정은 유지한다.
3. 짧은 답변 추가(질문 4개 이하, 메시지 6개 이하, 총 2,500자 이하)에서 정정·조건 등의 단서가 없을 때만 low를 사용한다. 기존 일반 상담은 `channel` 필드를 생략해 저장하므로 생략된 유형도 일반 상담으로 처리한다. 새 고객 질문·불확실한 발화자·오래된 원문 연결은 전체 분석으로 돌아간다.
4. 최초 일반 상담 중 메시지 4개 이하·2,000자 이하이며 향후 안내 표현이 있고 정정·조건 등 복잡한 표현이 없는 경우 low를 시도한다. 날짜를 알아봐 줄 기한과 실제 처리 날짜를 혼동할 수 있으므로, low 결과의 answered 질문에 최신 향후 안내 근거나 연결된 미이행 안내 약속이 있으면 medium으로 전체 분석을 다시 수행한다. 이미 이행된 과거 안내 약속만으로 불필요한 재검토를 추가하지 않는다.
5. 이메일에서 partial 이유가 원문에 없는 다른 자료·추가 요건을 가정하는 것으로 의심되면 기존 한 번의 medium 재검토를 사용한다. 실제로 여러 자료를 물었거나 업체가 일부 목록만 제시한 경우 partial을 유지할 수 있다. 정규식은 재검토 필요성을 고를 뿐 상태를 자동 변경하지 않는다. 초기 이메일의 첫 요청은 변경하지 않는다.
6. 수정은 기존 최대 한 번 안에서 수행한다. 원문·발화자·상태 검증, 처리 통보·경계 의미 검토, 취소·버전 검사, 실패 시 기존 결과 보존은 유지한다. 모델 변경·대화 요약·원문 생략·검증 생략은 하지 않는다.
7. 영어 이메일에서 검토·처리 소요 기간 설명을 promised로 추출했을 때도 같은 정밀 재검토 범위를 사용한다. 일반 기간 안내만이면 독립 약속을 만들지 않고, 개별 건의 검토·결과 발송 확약이 별도로 있다면 유지한다. 자료 수신 통보를 보존하며 심사 기간을 수신 기한으로 옮기지 않는다. 코드가 약속을 자동 삭제하지 않는다.

## 검증과 한계

동일한 가상 상담으로 기준 main과 후보를 교차 실행하고 API 호출부터 검증·수정·저장까지 포함한 분석 시간을 측정한다. 등록의 본문 읽기·연결 점검은 실제 웹 측정으로 구분한다. 상태·약속·ID·원문 근거·이유 범위, 배송·환불·구독 48건, 이메일 답변, 실제 Chrome 흐름을 검증한다. 구체적인 수치와 실패 후보는 [측정 기록](../REGISTRATION-REPLY-LATENCY.md)에 남긴다.

추론 분기는 모든 어려운 문장을 식별하지 못하며 재검토 역시 AI 판단이다. 공급자 응답 변동이 크고 재검토가 필요한 개별 사례는 오히려 느려질 수 있다. 모든 요청의 최대 응답 시간을 보장하지 않는다. 취소된 보조 요청의 토큰을 확인할 수 없으면 총비용 절감률을 제시하지 않는다.
