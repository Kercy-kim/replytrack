# ADR 0021: 오래 지연된 첫 분석에 한 번만 보조 요청

상태: 채택. 2026-11-15. ADR 0020의 모델·추론 분기·원문 검증은 유지한다.

## 문제와 근거

이전 평가 NU02는 첫 분석 75.019초, 경계 검토 7.482초로 합계 82.501초였다. 첫 분석 출력은 770토큰(추론 448)이었고 같은 입력 재실행은 전체 19.716초·13.799초였다. 큰 출력이 유일한 원인이라고 보기 어렵지만, 이전 계측은 호출 전체 시간뿐이므로 공급자 대기·생성·네트워크 중 원인을 확정할 수 없다.

## 결정

- 등록과 새 답변 반영의 첫 `replytrack_analysis`가 25초 동안 완료되지 않을 때만 동일 요청을 한 번 더 실행한다. 이 값은 이전 정상 분석 p95 약 19초보다 여유 있게 정했다. 모든 요청에 중복 호출을 추가하지 않는다.
- 모델, 추론량, 원문, 개인정보 가림 결과, JSON 스키마, 출력 한도는 동일하다. 먼저 완성된 JSON 응답을 기존 서비스에 넘긴다. 서비스의 원문 근거 검사, 필요시 medium 수정·경계 검토·완료 통보 검토, 버전 검사 후 한 번 저장하는 절차를 유지한다. 빠른 응답이라는 이유로 정답으로 간주하지 않는다.
- 보조 요청 실패만으로 아직 실행 중인 원래 요청을 버리지 않는다. 원래 요청도 먼저 완료될 수 있다. 인증·한도·거절 오류는 즉시 중단한다. 두 요청이 모두 실패하면 오류를 반환한다. 오류 직후 자동 재시도나 재귀적 복제는 하지 않는다.
- 복구용 수정, 의미 검토, 초안, 연결 점검에는 보조 요청을 적용하지 않는다. 원래 호출의 90초 시간 제한을 공유하고 새로운 요청 때문에 연장하지 않는다. 사용자 취소와 승자 확정 시 실행 중인 나머지 HTTP 요청을 중단한다.
- 서버에서 공유하는 OpenAIClient 하나당 보조 요청은 동시에 최대 1개다. 기존 최대 2개 AI 작업과 합쳐 최대 3개 HTTP 요청이다. 보조 슬롯이 이미 사용 중이면 해당 호출은 기존 요청만 기다린다. 슬롯을 뒤늦게 기다려 추가 요청을 보내지 않는다.
- 헤더 도착·본문 읽기·전체 시간, 성공/실패/취소, 각 시도의 확인된 사용량을 기록한다. 이 시간만으로 공급자 내부 대기와 추론을 분리할 수는 없다. 키·원문은 전송 진단에 넣지 않는다.
- 취소된 요청도 과금될 수 있다. 확인된 사용량을 합산하고 사용량을 확인하지 못한 요청 수를 별도로 남긴다. 불완전한 사용량으로 절감률을 계산하지 않는다. 화면에는 확인된 토큰 수가 하한임을 표시한다.

## 검증과 한계

48건 실제 API 회귀, 이메일·설명 범위 대조, 실제 웹 흐름, 동일 지연을 주입한 전후 비교 및 자동 테스트를 수행한다. 결과는 [평가 기록](../ANALYSIS-TAIL-LATENCY.md)에 보존한다. 지연 주입은 실제 API 결과 전달을 늦추는 통제 실험이며 과거 75초의 원인을 재현했다고 주장하지 않는다.

보조 요청은 추가 비용을 발생시킬 수 있고 두 요청이 모두 느리거나 공급자가 전체적으로 혼잡하면 효과가 없다. 의미 검토·수정 등 다른 단계의 지연도 남는다. 모든 요청의 30초 또는 82초 이내 완료를 보장하지 않는다. 장기 운영에서 발동률·추가 비용·긴 지연 발생률을 관찰해 임계값과 사용 여부를 재검토한다.
