# ADR 0005 — 초안 검토와 한 번의 수정

- 상태: 채택
- 날짜: 2026-11-14
- 근거: 실제 AI 평가의 소비자/상담원 관점 혼동, 선택 질문 누락, 담당자 동일성 추정

## 결정

실제 AI 초안은 생성 → 형식·원문 ID·숫자·담당자 추정 표현 검증 → 의미 검토를 거쳐 저장한다. 의미 검토는 같은 `gpt-5-mini`를 별도의 지시와 호출로 사용하며 소비자 관점, 선택한 질문의 누락, 원문 사실, 최신 정정과 약속/완료 구분을 검사한다. 입력은 상담 원문, 선택 질문, 약속, 생성한 초안이다. 외부 자료나 평가 정답을 사용하지 않는다. 분석·초안 생성의 reasoning effort는 `low`, 의미 검토만 `medium`으로 설정한다. 초기 `low` 검토가 명백한 화자 오류를 통과시킨 부정 사례를 기록하고 변경했다.

메시지의 `agent` 역할만으로 담당자 동일성을 알 수 없다. 초안에 '동일 상담원/다른 한 상담원/두 명의 상담사' 같은 표현이 있고 인용한 원문에 그 표현이 없으면 `DRAFT_ACTOR`로 거절한다. 직접 인용한 근거에 같은 표현이 있으면 허용한다. 이는 보수적인 문자열 검사이며 사람 식별 전체를 해결하는 의미 분석은 아니다.

내부 메시지 UUID를 본문에 인용한 실패 사례에는 `DRAFT_REFERENCE`로 본문에서 제거하고 근거 ID 필드에만 넣으라는 피드백을 제공한다. 원문에 실제로 존재하는 UUID 형식의 접수번호는 허용한다. 기존 숫자 검증이 이런 오류를 모호한 숫자 오류로 처리하던 문제를 구별한 것이다.

검증 실패 시 피드백과 이전 초안을 첨부하여 한 번만 수정한다. 두 번째에도 통과하지 못하면 `DRAFT_REVIEW` 또는 기존 근거 검증 오류를 반환한다. 무한 수정이나 API 오류 자동 재시도는 하지 않는다. 검토 오류·API 장애·버전 충돌 시 기존 초안과 사용자 편집을 보존한다. 저장된 초안에는 검토 모델과 시도 횟수를 함께 기록한다. 예제 모드는 준비된 초안을 그대로 사용하며 실제 API를 호출하지 않는다.

## 비용과 한계

초안 한 건에 보통 생성 1회 + 검토 1회가 필요하며, 수정 시 최대 4회의 API 호출이 발생한다. 분석 자체는 기존 1회 호출을 유지한다. 의미 검토도 LLM이므로 오류를 놓치거나 정상 문장을 거절할 수 있으며, 사용자의 최종 확인과 편집을 대체하지 않는다. 평가 결과에서는 제품의 검토 통과 여부와 개발 에이전트의 별도 원문 대조를 구별한다.
