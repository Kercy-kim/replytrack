# ADR 0016 — 요청 시 SSG 공식 FAQ 검색과 대체 안내

- 상태: 채택
- 날짜: 2026-11-15

## 결정

- SSG 일반 상품의 취소·반품·교환·환불만 먼저 지원한다. AI가 자연어 의도를 구분하면 의도별 정해진 질문으로 필요한 상황을 한 가지씩 확인한다. 설명과 선택값이 명시적으로 충돌하면 의도 해석 응답의 제한된 필드 키로 해당 질문을 다시 확인하고, 확인 전 검색·안내 생성·기존 안내의 상담 전환을 막는다. 모름이나 단순 정보 부족은 충돌로 취급하지 않는다.
- 별도 검색 API를 쓰지 않고 SSG 공식 고객센터의 공개 검색 페이지를 직접 요청한다. 의도별 고정 주제어 1~3개만 보내고 개인 입력·전화번호·주소는 검색 URL에 보내지 않는다. 임의 URL, 로그인, 자동 주문 조작, 리다이렉트 추적을 지원하지 않는다.
- 전체 검색은 10초, 각 응답은 1.5MB로 제한한다. 질문/답변 구조가 확인되는 본문만 읽고 관련 자료 최대 6건·16,000자를 사용한다. 특수 서비스 FAQ는 제한적으로 제외한다. 전체 검색 결과와 개별 상품 정책을 수집했다는 의미가 아니다.
- 카드 환불 반영 시점 문의는 결제수단 정책 자료가 있으면 그 자료로 근거를 좁힌다. 요청만 한 상태는 `주문취소` 고정 검색어도 사용하고 취소 요청·승인 구분의 근거를 함께 제공한다. 관련 없는 반품 검수·추가 결제·교환 전환 및 디지털 교환권 자료를 일반 안내에 섞지 않는다. 금액 차이 문의를 시점 문의와 같은 기준으로 제한하지 않는다.
- 카드 환불 표는 조건과 기간을 함께 인용하는 별도 추출을 사용한다. 평문으로 연결된 카드·Alipay·계좌이체 열을 180자씩 자른 조각으로 안내하지 않는다. 숫자는 현재 출처에서 읽고 당일 전체·당일 부분·결제일 이후 조건을 유지한다. 취소 요청만 한 상태에서는 요청과 승인의 차이를 보여 주는 공식 조건을 필수로 보존한다.
- 승인 전 카드 환불은 단일 기간을 추정하지 않는다. 서버가 승인 확인·카드사 확인의 두 행동과 공식 출처의 조건별 기간을 조립하고 AI 의미 검토를 거친다. 이 경로는 의도 해석·검토 2회이며 자유로운 문구 생성과 자동 수정을 수행하지 않는다. 근거 누락·검토 실패는 이전 결과를 보존하는 오류로 처리한다. 같은 기간을 설명한 중복 근거는 한 번만 사용한다.
- 빈 결과·비HTML·HTTP 실패·응답 크기 초과·구조 변경·시간 초과는 사전 검토 요약으로 전환한다. 검색 실패 이유는 일반적인 설명으로 표시하고 원래 확인 날짜를 유지한다. 실시간 결과와 대체 자료를 섞거나 대체 자료를 최신이라고 표시하지 않는다. 취소 신호는 대체 성공으로 바꾸지 않는다.
- 서버가 본문에서 180자 이내의 연속 인용 후보를 만들고 AI는 제한된 evidence ID 중 하나를 선택한다. 짧은 절은 제목·조건·예외를 함께 유지한다. 배송 중 취소, 단순변심, 불량 등 알려준 상황으로 후보를 좁힌다. 생성에는 이 후보와 출처 제목만 제공하고 의미 검토에는 전체 출처 본문도 제공한다. 인용문·source ID는 서버가 복원하고 실제 연속 인용문인지 검사한다.
- 조건·예외(`conditions`)는 AI가 고른 근거 ID의 원문을 서버가 그대로 표시한다. 이 영역에는 AI가 정책을 바꿔 쓴 문장을 사용하지 않는다. 행동(`steps`)은 AI가 상황에 맞게 작성하고 계속 검토한다. 원문 선택 자체가 틀릴 가능성은 남으므로 사용자 상황과 핵심 예외 검토는 유지한다.
- 미확인 사항(`unknowns`)은 서버가 의도와 선택 응답으로 구성한다. 모르는 수령 날짜·사유·주문 상태·결제수단은 빠뜨리지 않고 개별 상품 조건·실제 처리 결과의 확인을 안내한다. AI에게 자유로운 질문 생성을 맡기지 않아 수취 거부·주문 더하기처럼 사용자가 말하지 않은 상황이 끼어들지 않도록 한다. 이 필드는 추가 문답을 수행하는 범용 챗봇이 아니다.
- 행동 안내는 지금 필요한 1~2개로 제한한다. 단순변심·환불 문의의 직접 접수 장애 FAQ는 사용자가 버튼·화면·접수 문제를 실제로 말했을 때 제공한다. 기간·품목 제한을 만난 소비자에게 일반적인 접수 도움을 예외 신청 경로처럼 권하거나, 이미 취소된 주문에 새 교환 접수를 권하지 않도록 근거 범위를 좁힌다.
- 의미 검토는 항목별 인용 근거, 사용자 상황, 조건·예외, 개인 처리 완료 단정, 미확인 질문의 관련성을 각각 판정한다. 하나라도 실패하거나 누락되면 전체 승인만으로 통과시키지 않는다. 미확인 질문에는 인용 필드를 요구하지 않으며, 사용자 진술은 사용자 입력에서 확인한다. 실제 안내의 조건과 현재 상황의 핵심 제한을 검사하되 무관한 선택 경로까지 모두 포함하도록 요구하지 않는다.
- **2026-11-15 품질 평가에 따른 변경:** 초기의 자동 수정 없음 결정을 바꾼다. 안내 생성·의미 검토를 `medium`으로 수행하고, 의미 검토가 거절한 경우에만 피드백으로 한 번 수정한 뒤 다시 검토한다. 일반 완료는 의도 해석 포함 3회, 수정 경로는 최대 5회(연결 점검과 상황 질문 턴은 별도)다. 공급자 오류·취소·구조 검증 실패는 자동 재시도하지 않는다. 재검토 실패 시 기존 결과를 보존한다. 기존 진행 단계·취소·전체 작업 시간 제한을 재사용하고 수정 단계도 표시한다. 속도와 토큰 증가를 품질 결과와 별도로 보고한다.
- 안내는 탭 메모리에 보관한다. 취소·실패 시 이전 결과와 입력을 보존하며 입력 변경 후 이전 안내를 명시한다. 상담 등록으로 넘길 때 마스킹된 사용자 요청·상황만 customer 원문으로 옮기고 FAQ나 AI 설명을 agent 원문으로 만들지 않는다. 작성 중인 등록 내용을 덮어쓰지 않는다.

## 한계

실제 SSG 검색 성공을 확인했지만 사이트 구조·정책은 바뀔 수 있다. 대체 자료는 수동으로 검토·갱신해야 한다. 검색 서비스의 정답률이나 AI 검토의 완전성을 보장하지 않는다. 공개 다중 사용자 서비스로 배포하기 전 검색 빈도 관리와 자료 이용 방식 검토가 필요하다. 모의 검증과 실제 OpenAI 기본 점검은 [검증 기록](../OFFICIAL-GUIDE-VALIDATION.md), 이후 확대 품질 평가와 성능 비용은 [신규 기능 AI 평가](../NEW-FEATURE-AI-EVALUATION.md)에 구분한다.
