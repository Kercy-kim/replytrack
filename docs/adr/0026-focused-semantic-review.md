# ADR 0026 — 기존 질문 갱신과 의미 재검토의 출력 범위 축소

- 상태: 채택
- 날짜: 2026-11-16
- 보완: ADR 0025. 초기 질문 추출, 원문 검증, 완료·경계 검토, 지연 보조 요청은 유지한다.

## 결정

1. 고객 질문이 추가되지 않은 짧은 일반 상담 갱신에서 조건이 없으면 상태·이유·근거·약속에 집중한 지침을 사용한다. 영어 이메일·조건부 답변·긴 대화의 첫 요청은 기존 전체 분석 지침을 유지한다. 전체 원문과 기존 질문·약속을 전달하며 대화를 요약하거나 잘라내지 않는다. 질문 제목·원문은 기존 연결에서 복원한다.
2. 짧은 기존 질문 갱신(질문 4개 이하, 메시지 6개 이하, 총 2,500자 이하)은 조건이 없을 때 low를 사용한다. 일반 상담의 단순 금액·사실 정정도 포함하되, 기존 날짜가 있는 약속의 변경·철회·정정·부정 표현과 이메일 정정은 medium을 유지한다. 기한 변경까지 low를 넓힌 후보에서 약속 중복이, 영어 정정의 low에서 거짓 충돌 판정이 발생했기 때문이다. 초기 추출과 긴 대화의 기존 추론 분기는 변경하지 않는다.
3. 원문 인용·구조 검사를 통과한 결과에 의미적 의심이 생기면, 의심되는 질문만 medium으로 다시 판단한다. 질문 ID·고객 원문·제목을 연결 정보로 전달하고 잘못된 초안의 상태·이유는 전달하지 않는다. 검토 대상 밖의 질문은 첫 결과를 유지하며, 전체 약속과 요약은 다시 판단한다. 대상 질문의 원문은 검증된 첫 결과에서 복원한다.
4. 일반 심사 기간을 독립 약속으로 만든 의심만 있다면 질문 출력 자체를 제외하고 약속·요약만 검토한다. 실제 자료 수신 통보와 개별 검토·결과 발송 확약은 유지한다. 기간을 코드로 삭제하거나 질문 상태를 코드로 바꾸지 않는다.
5. 범위 제한은 질문 1~8개이고 ID가 유효할 때만 적용한다. 인용·구조 오류나 범위 제한이 불가능한 경우 기존 전체 재검토를 사용한다. 의미 재검토와 모든 후속 검토는 medium, 재생성은 기존 최대 한 번이다.
6. 합쳐진 전체 결과를 원문과 다시 검증한다. ID 누락·중복·추가, 잘못된 인용, 취소·동시 변경은 저장 전에 차단한다. 사용자 제목·상태 수정, 실제 해결 확인, 기존 초안은 보존한다.
7. 추가 대조 검사에서 드러난 기존 경계도 보완한다. 이메일의 일부 목록·확인 중이라는 진행 설명만으로 미래 안내 약속을 만들지 않도록 명시한다. low 결과가 waiting인데 고객이 안내 시점 자체를 물었고 연결된 안내 약속의 기한이 있다면, 같은 한 번의 medium 재검토에서 시간 대상을 대조한다. 정규식으로 answered로 바꾸지 않는다.
8. 기한 삭제 표시가 있지만 인용에 철회·미정·정정 단서가 없으면 약속만 medium으로 재검토한다. 단순 완료 통보의 기한 이력을 지우지 않는다. 재검토도 같은 근거 없는 삭제를 반환하면 저장하지 않는다. 단서는 필요한 검토를 고르는 보수적 검사이며 철회의 의미를 모두 판별하는 규칙은 아니다.

## 검증과 한계

같은 원문과 저장 상태를 사용해 기준 main과 교차 반복한다. 실제 새 답변 분석 시간과, 관측한 오판을 재생한 뒤의 실제 API 재검토 시간을 구분한다. 후자는 첫 생성 시간을 포함하지 않는다. 기존 배송·환불·구독, 이메일, 새 정정 대조 사례 및 실제 Chrome 흐름을 확인한다. 결과와 실패 후보는 [측정 기록](../CORRECTION-REVIEW-LATENCY.md)에 남긴다.

범위 검사는 의미 오류 전체를 찾는 판정기가 아니다. 검토 대상 밖의 질문이 완벽하다는 보장도 없다. 반복 측정의 개선은 모든 요청의 최대 대기 시간 보장이 아니며, 공급자 지연과 재검토에 따라 30초를 넘을 수 있다.
