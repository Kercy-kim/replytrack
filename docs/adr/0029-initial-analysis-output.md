# ADR 0029 — 최초 분석의 불필요한 출력·저장 이력 지침 제거

- 상태: 채택 — 조건부 이메일의 출력 축소는 제외
- 날짜: 2026-11-16
- 보완: ADR 0026·0028. 최초 추출에서도 판정·근거·보안·설명 기준은 기존 전체 지침을 공유한다.

## 결정

1. 분석·질문·처리 약속이 아직 없고, 발화자가 확인된 4개 이하 메시지·2,000자 이하의 최초 분석에만 적용한다. 정정·철회·변경이 있는 대화와 긴 대화는 기존 전체 경로를 유지한다. 조건·선행 절차가 있는 이메일도 기존 지침·스키마·medium 경로 전체를 유지한다. 단순 이메일만 재문의 작성 지침·출력을 제외한다.
2. 최초 분석에서도 전체 고객 질문과 업체 처리 약속을 추출하고 title·source·status·reason·evidence·기한을 반환한다. 원문과 모델은 유지하고, 이 출력 축소를 이유로 추론 수준을 낮추지 않는다.
3. 일반 상담의 `INITIAL_ANALYSIS_PROMPT`는 `ANALYSIS_PROMPT`를 공유한다. 기존 저장 약속 ID와 기한을 갱신하는 세 줄 및 별도 기능인 재문의 문장 작성 지침을 제외하고 신규 행동 ID 지침을 유지한다. 질문 분리, 상태 판단, 원문 인용, 명령 주입 거부, 판정 이유 문체 등은 동일하다. 날짜·시각·기간과 단순 선행 조건을 구분하여, 기한이 없는 조건은 인용 근거에 보존하고 기한 칸은 비운다. 이메일은 `INITIAL_EMAIL_ANALYSIS_PROMPT`로 원래 약속 지침 전체를 유지하고 재문의 작성 지침만 제외한다.
4. 별도로 생성·검토하는 재문의 문장 `followUp`은 최초 출력에서 제외한다. 일반 상담에만 기존 기한 삭제용 `deadlineCleared`도 제외한다. 저장된 약속이 없을 때만 적용하므로 삭제할 과거 기한이 없다. 새 약속의 원문 기한은 `dueText`로 계속 추출한다. 이메일은 기존 약속 스키마·기한 지침을 그대로 유지한다. 제외한 필드는 기존 도메인의 빈 재문의·기한 삭제 기본값을 사용한다.
5. 원문 인용·형식 오류는 원래 전체 스키마와 medium으로 한 번 재검토한다. 의미·완료·경계 검토, 버전 검사, 취소·기존 기록 보존은 유지한다. 최초 출력은 복원 대상이 아니므로 `restore`가 있는 갱신·의미 검토 계획에만 복원 함수를 호출한다.
6. 향후 안내가 포함된 짧은 일반 상담의 low 우회 경로는 업체 메시지가 하나이고 고객 원문의 물음표 구간이 하나 이하일 때만 적용한다. 여러 업체 메시지에 실제 처리와 후속 안내가 따로 있거나, 여러 질문의 답을 넓게 인용해 후속 안내와 섞이는 경우 기본 medium 경로를 유지한다. 정규식은 복잡성이 명확한 입력의 추론 수준만 높이며 질문 상태나 약속을 결정하지 않는다. 물음표가 없는 모든 복합 질문을 알아내는 분류기는 아니다.

## 채택하지 않은 방향

기존 갱신용 집중 지침을 최초 분석에도 사용한 후보는 빠른 결과를 냈지만, 기존 48건에서 별개 환불 항목 구분·배송 약속·조건부 상태·인용된 명령·설명 범위의 회귀가 있었다. 이 후보는 채택하지 않는다. 실제 평가 결과를 보고 판정 규칙을 제거하는 범용 프롬프트 단축은 이번 최적화에서 제외했다.

전후 비교·품질·실제 웹 결과와 한계는 [최초 분석 지연 개선 기록](../INITIAL-ANALYSIS-LATENCY.md)에 기록한다.
