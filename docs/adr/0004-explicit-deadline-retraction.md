# ADR 0004 — 기한 생략과 명시적 철회 구분

- 상태: 채택
- 날짜: 2026-11-14
- 근거: 가상 상담 실제 API 평가 R03

## 문제

업체가 기존 안내 기한을 취소하고 안내 시점을 미정으로 바꿔도, AI가 반환한 빈 `dueText`가 이전 기한으로 대체됐다. 그 결과 철회한 날짜가 현재 약속과 전후 비교에 남았다. 한편 완료 통보에서 기한을 반복하지 않았다는 이유로 과거 약속 날짜를 지워서도 안 된다.

## 결정

분석 스키마에 `deadlineCleared` boolean을 추가한다. AI는 명시적인 기한 철회·미정 정정에만 true를 반환하고 그 문장을 약속의 원문 근거에 포함한다. 이 경우 `dueText`는 빈 문자열이어야 한다. 서버는 원문·발화자 검증을 통과한 새 업체 메시지가 기존 약속 근거보다 뒤에 있는지 확인한 후 기존 기한을 비운다. 최초 분석에는 이전 서버 약속이 없으므로 검증된 철회 근거로 빈 기한을 적용할 수 있다.

기한을 단순히 생략한 답변과 처리 완료 통보는 기존 기한을 유지한다. 약속 ID, 사용자 확인 상태는 바꾸지 않는다. 기존 전후 비교가 날짜 변경을 기록하고 과거 이력은 원래 기한을 보존한다. 기존 fixture/과거 AI 출력처럼 필드가 없으면 종전의 보존 동작을 적용한다. SQLite 스키마 변경은 없다.

철회의 의미 자체는 여전히 AI가 해석한다. 서버는 인용문의 실제 존재와 시간 순서를 검사하지만 문장 의미의 정확성을 보증하지 않는다. 단순 키워드만으로 기한을 삭제하지 않는다.

## 답변 대기와 약속의 일관성

같은 평가에서 향후 안내 약속 없이 미정이라는 이유만으로 `waiting`을 반환하는 사례가 확인됐다. `waiting`은 검증된 `promised` 약속이 같은 질문에 연결되고 그 약속 메시지가 질문의 답변 근거에도 있어야 적용한다. 연결이 없으면 AI 제안을 `review`로 낮추고 검증 경고를 남긴다. 수동으로 지정한 질문 상태는 유지한다. 이 검사는 의미상 약속의 진실성을 보증하지 않지만, 출력 내부의 모순을 그대로 적용하지 않도록 한다.
