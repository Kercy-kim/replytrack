# ADR 0008 — 원문을 보존하는 AI 요청 최적화

- 상태: 채택
- 날짜: 2026-11-14
- 이전 결정: [ADR 0007](0007-information-actions-and-rescheduling.md)

## 문제

품질 보완 후 분석·초안 생성·검토를 모두 medium으로 호출한다. 긴 내부 UUID가 원문·기존 질문·약속·출력 스키마에서 반복되고, 후속 분석에는 같은 원문을 설명하는 AI 판단 이유와 추천 질문까지 중복으로 들어간다. 품질 검증을 유지하면서 불필요한 입력·출력과 초안의 추론 비용을 줄인다.

## 결정

- API 전송 직전에 ID 필드의 UUID만 요청별 짧은 참조로 바꾸고 응답 직후 원래 ID로 복원한다. ID 목록을 제한하는 스키마도 같은 매핑을 사용한다. 원문·인용문·날짜·금액은 변환하지 않는다. 매핑은 요청마다 독립적이고 입력에 이미 있는 문자열과 충돌하지 않는다.
- 원문에 없던 짧은 내부 참조가 초안 본문으로 나오면 원래 UUID로 복원하여 기존 본문 참조 검증에서 거절한다. 변환이 근거 오류를 숨기거나 다른 상담의 ID를 연결하지 않게 한다.
- 생성된 판단 이유·요약·추천 문장·검토 피드백에 알려진 짧은 참조가 섞여도 원래 ID로 복원한다. 수정 피드백을 다음 요청에 넣을 때는 그 요청의 매핑으로 다시 변환하여 이전 요청의 참조를 잃지 않게 한다. 원문 text와 정확한 quote는 변환하지 않는다.
- 후속 분석은 모든 원문 메시지와 기존 질문의 ID·제목·source·이전 AI 상태·근거, 약속의 ID·제목·연결 질문·근거·원문 기한·상태를 받는다. 중복된 AI 설명·추천 재문의·UI 필드는 제외한다. 이전 기한과 사용자 수정·확인·이력은 저장 계층에서 그대로 보존한다. 질문의 이전 상태와 근거까지 제거한 후보는 채택하지 않는다.
- 분석 지침의 반복 설명을 정리하되 상태·약속·기한·정정의 의미 기준은 유지한다. 기존 기준에 따라 정보 미정을 답변 받음으로 보지 않고, 독립적으로 물은 승인 완료와 실제 입금 여부를 구분하며, 이미 수행한 업무도 추출한다. 경계 검토에는 원문과 질문 ID·제목·source 및 다른 질문의 주제를 제공한다. 이전 AI 상태나 넓게 묶인 evidence를 다시 정답처럼 전달하지 않으며, 다른 질문의 답을 먼저 제외한 뒤 부분 정보를 판단한다. 검토 대상 ID와 허용 상태는 계속 제한한다.
- 약속 추출의 상세 지침은 이전 main의 문장을 그대로 유지한다. 이 부분까지 축약한 후보에서 단순 번호 안내의 약속 오인과 완료 통보 누락이 발생했으므로 더 큰 토큰 절감 대신 기존 설명을 복원했다.
- 경계 검토에서 다른 질문의 답을 제외하는 규칙은 실제 `otherQuestions`에 있는 별도 질문에만 적용한다. 같은 항목의 다른 기간 정보까지 별도 질문으로 만들어 버리지 않는다. 단순히 결과가 미정·미확정이라는 말 자체를 유용한 처리 진행 단계로 세지 않는다. 이는 기존 partial/review 기준을 바꾸지 않고 검토 단계의 해석을 명확히 하는 보완이다.
- 안내 기한만 철회하고 계속 확인해서 안내하겠다는 행동 약속이 남으면 `waiting`을 유지한다. 날짜 취소를 행동 약속의 취소나 이행 완료로 바꾸지 않는다. 기존 상태 기준을 질문 단계에서도 명확히 한다.
- 인용 수정에는 오류 경로와 해당 메시지의 정확한 원문을 전달하며 같은 원문을 여러 번 반복하지 않는다. ADR 0007의 이전 전체 분석을 함께 보내던 방식은 제거한다. 잘못 바꿔 쓴 인용을 다시 복사하지 않게 하고 입력 토큰도 줄인다. 서버의 정확한 부분 문자열·발화자 검증은 바꾸지 않으며 인용을 임의로 고치지 않는다.
- 분석·경계 검토·인계 생성·초안 의미 검토·수정은 `medium`을 유지한다. ADR 0007의 모든 초안 생성 `medium` 결정 중 **재문의의 첫 생성만 `low`**로 변경한다. 모든 초안 첫 생성을 낮춘 후보에서는 인계가 검토를 통과하지 못했다. 서버 또는 의미 검토가 거절하면 기존 한 번의 수정 기회를 `medium`으로 수행한다. 검토를 생략하거나 최대 호출 수를 늘리지 않는다.
- 초안 출처 배열의 최대 길이를 해당 대화의 메시지 수로 제한하고 중복 없이 실제 쓴 메시지만 요구한다. 약속이 없는 상담에는 약속 항목을 억지로 만들지 않는다. 원문 ID enum·최소 한 개 출처·본문 검증은 유지한다.
- 모델, 출력 필드, 6,500토큰 한도, 실패 시 이전 기록 보존 규칙은 그대로 유지한다. 원문 일부 제거, 검토 생략, 실패 결과 재사용으로 속도를 높이지 않는다.

## 검증 방법

같은 고정 모델과 상담 20건으로 기존 main과 후보를 실제 API 평가한다. 원문·정답·채점기는 변경하지 않는다. 분석 작업은 수정·경계 검토를 포함한 완료 시간, 초안 작업은 생성·검토·수정을 포함한 완료 시간을 측정한다. 성공 호출만 골라 시간이나 토큰을 계산하지 않는다. 캐시 입력·추론 토큰을 별도로 표시한다.

기존 28건과 잘못된 초안/정상 초안 대조 검사를 추가 회귀 평가하고, 생성된 초안은 원문과 별도로 대조한다. 원문 및 ID 보존, 동시 요청 격리, 내부 참조 누출, 수동 상태·이력 유지, 수정 시 medium 전환을 자동 검사한다. 채택 여부와 실측 결과는 성능 평가 보고서에 기록한다.

수정에 사용한 자료는 독립적인 미사용 평가가 아니다. 최적화 전후를 순서대로 실행하므로 캐시 적중과 공급자 부하가 지연에 영향을 줄 수 있으며, 개별 변경의 인과 효과나 실제 청구액 절감률로 해석하지 않는다. 실패한 후보도 보관하고 최종 품질과 원문 대조를 통과한 구성만 채택한다.

참고: [OpenAI 지연 최적화 가이드](https://developers.openai.com/api/docs/guides/latency-optimization)의 입력·출력 토큰과 전체 작업 지연 측정 방식을 적용한다. 모델의 추론량을 낮추는 변경은 실제 품질 평가 후에만 채택한다.

## 검증 결과

최종 코드와 이전 main의 같은 20건 비교에서 분석 19/20→20/20, 초안 6/6을 확인했다. 총 토큰은 7.24%, 분석 완료 중앙값은 29.58%, 재문의 중앙값은 29.63% 감소했다. 인계 중앙값과 초안 p95는 증가했으며 절감 효과를 모든 작업에 일반화하지 않는다. 기존 28건 회귀의 남은 오류는 R03을 보완하고 최종 코드로 두 번 재검사했다. 전체 28건의 최종 코드 재실행으로 주장하지 않는다. 초안 검토 대조 7/7, 자동 테스트 78개와 문법 검사 42개를 통과했다. 원본·실패 후보·측정 한계는 [성능 보고서](../AI-PERFORMANCE.md)에 보존한다.
