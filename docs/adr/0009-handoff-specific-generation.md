# ADR 0009 — 인계 전용 생성 지침과 검토 유지

- 상태: 채택
- 날짜: 2026-11-14
- 이전 결정: [ADR 0008](0008-ai-request-efficiency.md)

## 문제

인계의 첫 생성에서 본문에 내부 ID를 쓰거나 안내 시점을 새 질문으로 추가하면서 수정·검토를 반복했다. 재문의 지침과 인계 지침을 함께 전달하고 매번 medium으로 생성하여 단순한 인계도 긴 추론을 사용했다. 이전 실측의 인계 중앙값은 58.09초였고, 최장 91.22초였다.

## 결정

인계용 지침을 별도 모듈로 분리한다. 원문 순서와 최신 정정, 약속과 실제 확인, 질문 범위를 지키면서 문의·유효한 안내·남은 질문을 간결하게 전달한다. 재문의에서 필요한 요청 확장 규칙을 인계 생성에 전달하지 않는다. 입력 원문·질문·약속 및 출처 스키마는 그대로 유지한다.

인계 검토는 기존 검토 기준을 모두 포함하고, 원래 없던 안내 시점 질문·정정 없는 상충의 확정·허위 작성 지시의 사실 오인·소비자를 고객님으로 서술하는 관점 오류를 추가로 거절한다. 원문 직접 인용에 들어 있는 고객 호칭은 허용한다. 재문의의 생성·검토 지침은 바꾸지 않는다.

ADR 0008의 인계 첫 생성 medium 결정을 재평가하여, 전용 지침의 첫 생성만 low로 실행한다. 원문 ID·숫자·기한·담당자 표현 검증과 별도 의미 검토는 유지하며, 의미 검토와 한 번의 수정은 medium이다. 모델·출력 한도·최대 호출 수·실패 시 기록 보존을 바꾸지 않는다. 초안을 검토 전에 화면에 노출하지 않는다.

## 검증

이전 main 소스를 별도 디렉터리에 고정하고 같은 분석 기록으로 변경 전후의 실제 인계만 비교한다. 분석을 다시 실행해 입력 상태가 달라지는 문제를 피한다. 기존 인계 6건은 각각 두 번, 신규 고정 기록 6건은 한 번씩 실행한다. 원문과 예상 사실·금지할 주장을 API 호출 전에 고정하며, 전후 실행 순서를 교대로 배치한다. 서버의 저장 성공과 별도로 개발 에이전트가 원문에 대조한다.

재문의·분석의 기존 평가 자료는 변경하지 않는다. 인계 전용 지침 선택, 재문의 지침 유지, 검토·수정의 추론 설정과 실패 시 편집한 초안 보존을 자동 검사한다. 최종 결정과 측정 한계는 인계 성능 보고서에 기록한다.

최종 18쌍 비교에서 인계 중앙값은 38.018→17.346초, p95는 96.808→51.875초였다. 개선안 18/18개 초안의 원문 대조, 인계·기존 검토 대조 16/16개, 자동 테스트 82개를 통과하여 채택한다. 기준 구현 1회의 미완성 실패 시간도 집계하고 누락 사용량은 0으로 가정하지 않았다. 토큰 비교는 양쪽 성공·사용량 확인 가능한 17쌍에서 28.10% 감소했다. 원문 대조의 범위와 채택하지 않은 후보, 정상 표현 과잉 거절, 수정으로 남은 긴 지연은 [인계 성능 보고서](../HANDOFF-PERFORMANCE.md)에 기록했다.

참고: [OpenAI 지연 최적화 가이드](https://developers.openai.com/api/docs/guides/latency-optimization)의 작업 완료 시간·토큰·수정 호출을 함께 측정하는 방법을 적용한다.
