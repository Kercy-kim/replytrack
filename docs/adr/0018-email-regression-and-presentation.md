# ADR 0018 — 기존 품질 회귀와 30초 이메일 발표 범위

- 상태: 채택
- 날짜: 2026-11-15
- 관련 결정: ADR 0017

## 결정

사용자는 이메일 추가 후 기존 배송·환불·구독 48건의 실제 API 회귀 평가와 문제 수정을 요청했다. ADR 0017의 “기존 일반 상담 프롬프트와 호출 수는 바꾸지 않는다”는 이메일 기능 분리 원칙은 유지하되, 이번 회귀에서 드러난 공통 판정 오류를 고치기 위한 기존 분석·경계 검토 지침 수정은 허용한다. 자동 정답 치환이나 평가 데이터·채점 기준 변경은 도입하지 않는다. 완료 통보 누락이 문구 수정 후에도 재현되어, 완료 표현이 있는데 생성된 처리 목록이 비어 있을 때만 의미 검토를 한 번 추가한다. 이는 품질 회귀 수정 요청에 따른 ADR 0017의 호출 수 유지 원칙의 제한적 예외다.

1. 같은 요금 항목의 다른 기간 금액과 질문 기간의 미정을 함께 안내하면 부분 답변이다. 아무 부분 정보 없이 미정만 알려 주거나 해소되지 않은 충돌이 있으면 확인 필요다. 별도 질문의 답을 재사용하지 않는다.
2. 특정 건을 이미 처리했다는 안내도 처리 약속 목록의 `reported`로 추출한다. 미래의 약속만 기록하도록 오해할 수 있는 문구를 고친다. 사용자 직접 확인 상태를 추론하지 않는다. 완료 표현 검출은 검토 요청 조건일 뿐 정답 판정이 아니다. 검토 AI는 일반 정책·부정·가정에는 빈 목록을 반환할 수 있다. 결과는 원문·기한 인용과 질문 연결을 검증하고, 오류·취소 때는 기존 기록을 보존한다. 모든 호출의 토큰은 분석 사용량에 합산한다.
3. 30초 발표는 영어 원문 → 한국어 설명·할 일 → 영어 재문의 → 새 답변 비교에 집중한다. 별도 준비된 가상 이메일을 기존 분석·업체 요청·비교 도메인 함수로 구성하고, 모든 장면에 API를 호출하지 않는 예제임을 표시한다.
4. 실제 이메일 등록·생성 기능은 기존 흐름을 유지한다. 발표용 화면 전환 속도를 AI 응답 속도로 보고하지 않는다. 메일함 자동 연동·발송·별도 메모·알림은 범위에 추가하지 않는다.

## 검증

[전체 회귀·발표 화면 검증](../EMAIL-REGRESSION-DEMO.md)에 최초 실패, 중단한 중간 실행, 최종 전체 재평가와 실제 이메일 평가를 구분한다. 고정 합성 사례의 통과는 임의 입력에서의 완전한 정확도를 의미하지 않는다.
