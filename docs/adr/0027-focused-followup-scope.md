# ADR 0027 — 재문의는 원문의 남은 정보만 요청

- 상태: 채택
- 날짜: 2026-11-16
- 보완: ADR 0024의 재문의 검토를 4개에서 5개 항목으로 확장한다. 생성·검토 최대 두 쌍과 실패 시 기존 초안 보존은 유지한다.

## 결정

1. 초안 생성·검토에 전달하는 질문 제목은 `topicHint`라는 식별용 힌트로 구분한다. 질문 범위는 고객 원문 `source`와 전체 메시지로 판단한다. 같은 원문에 여러 항목이 있으면 힌트로 선택한 항목을 식별하되, AI 제목의 괄호·부연을 새로운 사용자 요청으로 취급하지 않는다. 저장된 질문 제목과 사용자 편집 내용은 변경하지 않는다.
2. 답변받은 항목을 `answeredQuestions`로 함께 제공한다. 하나의 원문을 여러 질문이 공유해도 해당 힌트의 항목만 답변된 것으로 본다. 선택된 부분 답변 안에서도 이미 받은 항목은 반복하지 않고 실제 남은 정보만 요청한다.
3. 검토에 `noAnsweredRequests`를 추가한다. 지침은 원문에서 받은 정보·남은 정보를 구분한 뒤 초안을 대조하는 순서로 정리한다. 전반적인 승인과 다섯 항목이 모두 true여야 저장한다. 정보가 미정·확인 중이라는 회신은 구체적인 답을 받은 것이 아니며 해당 정보의 정상 재문의를 거절하지 않는다. 실제 상충·정정 확인도 유지한다.
4. 실제 환불일과 그 날짜를 안내할 기한, 접수일과 처리 완료일, 자료 수신과 계정 복구 상태를 분리한다. 선택한 원문에 없는 안내 시점·카드 반영일·대체 상태 질문을 덧붙이지 않는다. 구체적인 자료 답변을 받았는데 원문에 없는 추가 서류 가능성을 만들어 다시 묻지 않는다. 실제로 두 자료 중 하나가 빠졌거나 목록이 일부라고 명시되면 그 누락은 유지한다.
5. 한 항목은 정중한 한 문장으로 작성하며 불필요한 서두·괄호 속 동의어·중복 강조를 줄인다. 단순 문체 취향 때문에 검토 API를 추가하지 않는다. 의미 오류 검토와 최대 한 번 재작성은 기존 요청 안에서 수행한다.
6. 의미 검토기의 자유형 피드백을 새로운 사실·요구로 사용하지 않는다. 수정 때도 원래 원문·선택 질문으로 다시 작성한다. 숫자·근거·소비자 관점·선택 항목 누락·취소·동시 수정 보호를 유지한다.
7. 실제 AI 호출 없는 수리·환불 예제도 안내 시점을 반복하지 않고 남은 금액만 묻는다. 기존 저장·편집 초안은 자동으로 덮어쓰지 않으며 새로 작성할 때 적용한다.

## 검증과 한계

관측한 실제 웹 기록, 부분 답변·미정·상충·영어·실제 자료 누락 대조, 기존 재문의 사례를 실제 API로 생성·검토한다. 정상/오류 고정 초안의 검토를 별도로 검사하고 생성 문장을 직접 원문과 대조한다. 생성 품질과 검토기 분류 결과는 별도로 보고한다. [검증 기록](../FOLLOWUP-FOCUS-VALIDATION.md).

AI 검토는 모든 의미 오류를 제거하는 보장이 아니다. 상태 분석 로직과 프롬프트는 이번 변경 대상이 아니며, 분석에서 잘못 추출된 항목이 항상 자동으로 복구된다고 주장하지 않는다.
