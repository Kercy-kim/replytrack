# 최초 등록·분석 지연 개선

기준 main은 `fc25f087bb3ec547e9d367293b9cfee8153d46a0`, 모델은 `gpt-5-mini-2025-08-07`이다. 실제 OpenAI API를 가상 문의로 실행했다. 전송·가림·발화자 검토·원문 검증은 유지한다.

## 느린 구간

직전 [실제 Chrome 기록](../evals/results/email-tail/live-browser.json)의 최초 등록은 환불 47.945초, 영어 계정 복구 74.458초였다.

| 구간 | 환불 | 영어 계정 복구 |
| --- | ---: | ---: |
| 본문 전사 | 2.928초 | 3.950초 |
| 첫 분석 API | 12.982초 | 29.390초 |
| 분석 재검토 API | 29.072초 | 40.007초 |

등록·저장·화면 조작보다 직렬 API 분석·재검토가 대부분이었다. 당시 로그는 요청·첫 생성 본문을 보관하지 않아 해당 재검토가 어떤 개별 오류로 시작됐는지는 확정할 수 없다. 이번부터 가상 문의 웹 검사에는 요청과 원본 응답도 보관해 원인 추적이 가능하게 했다. 키나 실제 사용자 상담을 기록하는 기능을 제품에 추가한 것은 아니다.

[기준 코드 재측정](../evals/results/initial-analysis/diagnostic.json)은 환불 10.462초, 단순 영어 문의 13.254초, 심사 약속 포함 영어 문의 26.674초로 재검토 없이 통과했다. 같은 입력도 생성 결과·재검토 발생 여부·공급자 응답 시간에 따라 편차가 있다. HTTP 응답 헤더 대기에는 서버 추론·공급자 대기·네트워크가 섞이므로 각각의 시간을 분리해 단정하지 않는다.

## 변경

짧고 정정이 없는 최초 분석에서 불필요한 재문의 문장 출력·작성 지침을 제거한다. 일반 상담은 저장 약속 ID·기한 갱신 지침과 기한 삭제 출력도 제외한다. 단순 이메일은 원래 약속 지침·스키마 전체를 유지한다. **조건부 이메일은 출력 축소도 적용하지 않고 main의 지침·스키마·medium 경로를 그대로 유지한다.** 질문 분리·상태·보안·설명 규칙은 공유하며, 모든 원문과 기한 추출 및 medium 재검토를 유지한다. 세부 조건은 [ADR 0029](adr/0029-initial-analysis-output.md)에 있다.

## 중간 실패 보존

- `pilot.json`: 첫 계획 연결에서 복원 함수가 없는 초기 계획에 복원을 시도하는 구현 오류가 있었다. 추가 전체 재생성이 발생한 기록이며 성능 개선 근거로 사용하지 않는다. 단위 테스트로 수정했다.
- `pilot-fixed.json`: 집중 지침 후보의 대조 7건은 통과했으나, [48건 전체](../evals/results/initial-analysis/full48.json)에서는 상태·약속 기준 43/48, 설명 범위까지 포함하면 42/48이었다. 반품비와 환불액의 혼동, 배송 약속 누락, 조건부 상태, 원문의 악성 지시를 업무로 오인한 결과, 불필요한 부연이 있었다. 후보를 폐기했다.
- [기존 지침 복원 대조](../evals/results/initial-analysis/retained-rules-controls.json): 실패했던 6건·7단계를 통과했다. 이후 중복된 최초 추출 설명도 제거한 최종 코드로 전체 재평가와 교차 비교를 수행한다.
- `full48-final.json`은 48건·55단계와 설명 범위를 통과했다. 다만 추가 `timing-final.json`의 T04에서 첫 low 결과는 발송·운송장 안내 약속 두 개를 정확히 추출했지만, 후속 안내 근거가 포함돼 의미 재검토가 발생했고 재검토 결과에서 발송 약속이 빠졌다. 업체 메시지가 여러 개인 경우 기본 medium을 유지하도록 고쳐 `timing-routed.json`의 4건을 통과했다. `routing-audit.json`은 이 라우팅 수정이 기존 48건의 경로에는 영향을 주지 않았음을 기록한다.
- 첫 반복 비교 `paired.json`은 기존 9/9, 후보 8/9였다. 후보가 자료 확인이라는 선행 조건을 기한으로 표시했다. 중앙값도 16.140→17.724초로 느려졌으므로 성공 결과로 사용하지 않는다. 원래 정답 기준을 유지하고, 최초 분석의 기한·선행 조건 구분을 명시했으며 출력하지 않는 재문의 문장의 작성 지침도 제거했다. 이후 검증은 `*-verified.json`으로 분리한다.
- `full48-verified.json`은 다시 48건·55단계와 설명 범위를 통과했고, `email-flow-verified.json`과 `timing-verified.json`도 통과했다. 그러나 `paired-verified.json`의 반복 비교에서 조건부 영어 문의의 선행 검증을 독립 약속으로 추가하는 결과가 한 번 있었다. 따라서 이메일에서는 원래 약속 지침·스키마를 전부 유지하고 재문의 작성만 제외하도록 범위를 축소했다. 기준 코드도 T04 반복에서 약속 누락이 한 번 있었다. 두 실패 모두 원본에 보존하며 비교 정답을 완화하지 않았다. `email-scope-audit.json`은 이 마지막 이메일 전용 변경으로 기존 48건의 분석 계획이 바뀌지 않았음을 확인한다.
- `paired-final.json`에서도 조건부 이메일 3회 중 2회가 기한·부분 답변 기준을 통과하지 못했다. 이 유형은 재문의 출력 축소까지 철회해 기존 main 경로로 복원했다. 최종 `final-comparison.json`은 코드의 조건부 이메일 제외 변경만 있었음을 해시로 검증하고, **그대로 유지된 나머지 세 유형의 모든 3회 결과**를 집계한다. 실패한 조건부 행을 성공으로 바꾸거나 삭제하지 않는다. 복원된 경로는 `email-flow-final-scope.json`과 최종 실제 웹으로 별도 검증한다.

## 최종 검증

최초 분석 비교는 같은 원문으로 기준/개선안을 교차 실행하며, 분석·검사·필요한 재검토·저장 전체를 측정한다. 브라우저 등록과 본문 전사 시간은 별도로 측정한다. 비교 실행 중 다른 유료 평가를 동시에 돌리지 않는다. 고정 가상 자료의 소규모 반복 결과이므로 모든 문의의 정확도나 최대 지연 보장을 뜻하지 않는다.

### 실제 웹에서 추가 확인한 중복 분석

`live-browser-before-compound.json`의 환불 최초 결과는 금액=답변 받음, 결제수단=미답변, 예정일=답변 대기로 맞았다. 하지만 금액 질문의 근거가 답변 전체를 인용하면서 향후 안내 문장까지 포함했다. low 결과의 시간 대상 검사가 추가 medium 검토를 요청해 첫 12.786초 뒤 11.752초가 더 필요했다. 별도 반복 `paired-verified.json`에서도 같은 유형의 올바른 초안에 추가 검토가 발생했다.

향후 안내가 포함되고 물음표 구간이 여러 개인 최초 일반 상담은 처음부터 기본 medium을 유지하도록 조정했다. 의미 검토 조건 자체를 삭제하거나 자동으로 답변 상태를 결정하지 않았다. 48건 중 이 추가 경로 변경의 영향은 S06뿐이며(`compound-routing-audit.json`), 실제 API 재평가 `compound-s06.json`에서 최초·후속 2단계 모두 통과했다. 기존 T04와 함께 캡처한 첫 올바른 응답을 재생하는 단위 테스트로 중복 재검토와 약속 누락 회귀를 확인한다.

### 최종 전후 비교

[집계·코드 해시 대조](../evals/results/initial-analysis/final-comparison.json)는 최종 적용을 유지한 세 유형을 각 3회, 기준·개선안 각 9회 비교한다. 동일 원문·모델, 2개 실행 작업, 전후 순서 교차, 다른 유료 평가 없이 측정했다. 분석·검증·필요한 재검토·저장을 포함하며 전사·브라우저 시간은 제외한다. 최초 기록이 없는 일회성 분석으로 결과 캐시를 사용하지 않았다.

| 지표 | 기준 main | 최종 적용 범위 |
| --- | ---: | ---: |
| 평균 | 19.247초 | 16.211초 (15.8% 감소) |
| 중앙값 | 14.949초 | 16.414초 (9.8% 증가) |
| 관측 최댓값 | 33.140초 | 19.609초 (40.8% 감소) |

| 관측 총 토큰 | 71,379 | 59,339 (16.9% 감소) |
| 질문·약속·근거·설명 통과 | 8/9 | 9/9 |

위 집계에는 기준 T04의 약속 누락 실패 1회도 포함했다. **양쪽 모두 통과한 동일 8쌍만 비교하면 평균 17.511→16.474초(5.9% 감소)**다. 미확인 추가 요청은 이 18회에 없었으며, 전체 실험의 다른 요청에 사용된 토큰까지 절감했다는 뜻은 아니다.

| 유형 (각 3회) | 중앙값 전→후 | 최댓값 전→후 | 해석 |
| --- | ---: | ---: | --- |

이 결과의 핵심은 **중복 검토가 겹치는 유형의 긴 지연 감소**다. 모든 최초 문의가 빨라진 것은 아니며, 작은 고정 표본으로 서비스 전체의 p95나 최대 응답 시간을 보장하지 않는다. 조건부 영어 문의는 이 성능 집계에서 제외했고 속도 향상을 주장하지 않는다.

### 품질·웹·자동 검사

- [최종 품질 집계](../evals/results/initial-analysis/final-validation.json): 기존 배송·환불·구독 48건, 55단계 통과. 질문 상태·근거 71/71, 약속·기한 22/22, 원문 참조 162/162, 판정 이유 검사 통과. `full48-verified.json` 전체 실행 후 경로가 바뀐 S06만 실제 재평가로 교체했으며 이를 48건 전체 재실행으로 표현하지 않는다.
- 날짜 의미 대조 4건 통과(`timing-verified.json`). 마지막 변경은 T04 등 이 네 건의 경로를 바꾸지 않았다. 최종 반복 비교에서도 T04 3회 모두 통과했다.
- 최종 이메일 2건의 최초·새 답변 4단계 통과(`email-flow-final-scope.json`). 조건부 이메일은 원래 전체 출력 경로를 유지한다.
- 전체 단위 테스트 **271/271**, JavaScript 문법 검사 **140개 파일** 통과. 로컬 Chrome 9종 검사도 통과했으며 이 실행은 마지막 라우팅 변경 전이다. 변경 후 실제 API Chrome의 환불·영어 흐름을 아래처럼 각각 다시 확인했다.
- [최종 환불 웹](../evals/results/initial-analysis/live-browser-final-refund.json): 등록·분석 **23.382초**, 답변 반영 **8.829초**, 초안 생성·검토·편집·저장·복사·재접속 **11.895초**. 첫 분석 API는 16.575초, 추가 분석 없음.
- [최종 영어 웹](../evals/results/initial-analysis/live-browser-final-email.json): 등록·분석 **37.448초**, 답변 반영 **23.303초**, 영어 초안 흐름 **9.910초**. 조건부 최초 분석 API는 31.519초였다. 이 지연은 남아 있으며, 품질을 위해 기존 경로를 유지한 사례다.
- 두 웹 흐름에서 질문 상태, 약속, 변경 비교, 문의 진행 요약, 원문 근거, 모바일 가로 넘침, 초안 편집·복사·새로고침 후 보존, 브라우저 오류를 확인했다. 최종 화면의 데스크톱·모바일 캡처도 점검했다. 이번 핵심 흐름 검사는 별도 실행 기능인 공식 안내·업체 요청 추출·한국어 설명 전체를 재평가한 결과는 아니다.

웹 소요 시간은 각 1회이며 사용자 수동 대기 시간을 제외한 자동 조작 결과다. 이전 47.945/74.458초 기록보다 짧더라도 실행 시점·모델 생성 편차가 있으므로 그 차이 전체를 코드 효과로 주장하지 않는다. 실제 외부 사용자 검수와 장기간 지연 분포 측정은 남아 있다.

### 재현

로컬 `.env`에 설정된 키를 사용하며 아래 평가는 실제 API 비용이 발생한다. 기존 보고서는 덮어쓰지 않는다.

```powershell
# 기준 worktree가 없을 때만 준비
git worktree add --detach .artifacts/initial-baseline-fc25f08 fc25f087bb3ec547e9d367293b9cfee8153d46a0
node --env-file=.env scripts/benchmark-initial-analysis.mjs --run --variant=both --repeats=3 --only=WEB-REFUND,WEB-EMAIL,T04 --out=.artifacts/initial-recheck.json
node --env-file=.env scripts/evaluate-ai.mjs --suite full --analysis-only --model gpt-5-mini-2025-08-07 --out=.artifacts/initial-quality-recheck.json
node --test
node scripts/check.mjs
```

Chrome 실행 파일과 Playwright 경로를 프로젝트 환경에 맞게 지정한 뒤 `scripts/check-live-browser.mjs --run --core-only --existing-email-promise`를 사용하면 된다. 가상 입력·격리 메모리 DB를 사용하며 제품 사용자 자료를 외부 테스트 로그로 수집하지 않는다.
