# ReplyTrack AI 응답 시간·토큰 최적화

평가일: 2026-11-14. 이전 main `a8aabec56c17530e39d369ee235fa63bfae385e5`와 동일한 가상 상담을 실제 API로 실행했다. 입력·정답·채점기는 변경하지 않았다. 최종 실측과 검증 결과는 아래에 기록한다.

## 비교 조건

- 배송 7·환불 7·구독 6건인 `unseen` 자료를 양쪽에 동일하게 사용했다. 총 20건, 추가 답변을 포함한 분석 24회, 질문 상태 32회, 약속 8회, 초안 6건이다. 이 자료는 이전 품질 개선에도 사용했으므로 새로운 미사용 자료가 아닌 회귀 평가다.
- 모델은 양쪽 모두 `gpt-5-mini-2025-08-07`로 고정했다. 실제 반환 모델도 확인한다. 최대 동시 요청 2개, 출력 한도 6,500토큰, 분석·초안의 검증 및 한 번의 수정 한도는 같다. 실제 사용자 DB 대신 메모리 SQLite를 사용한다.
- baseline의 제품 소스 해시는 해당 main과 일치했다(LF/CRLF 차이를 구분해 확인). 비교용 작업 시간 측정만 평가 도구에 추가했다. 각 실행의 원문·출력·소스 SHA-256·요청 설정·모델·usage를 원본 JSON에 보존한다. 짧은 참조를 사용하는 실행의 응답 ID는 저장소의 원래 UUID로 복원한 값이다.
- **분석 완료 시간**은 초기 생성·필요한 인용 수정·경계 검토·저장까지, **초안 완료 시간**은 생성·검토·필요한 수정·저장까지 포함한다. 성공한 호출만 골라 계산하지 않는다. HTTP/UI 렌더링과 캡처·텍스트 전사 시간은 범위 밖이다.
- 중앙값은 정렬된 관측값의 `floor(n/2)` 위치(짝수이면 가운데 두 값 중 큰 값), p95는 nearest-rank 방식이다. 분석은 24개, 초안은 6개뿐이므로 p95가 극단값에 민감하다.
- 총 토큰은 API가 보고한 입력+출력이다. 캐시 입력과 추론 출력도 총량에 포함하며 별도로 표시한다. 실제 청구 비용은 계산하지 않았다. 사용량 없는 실패 호출이 있으면 비교 도구는 절감률을 내지 않는다.

## 변경 사항

1. API 요청 안에서 반복되는 UUID만 짧은 참조로 바꾸고 응답에서 복원한다. 원문·인용문·숫자·날짜는 줄이지 않는다. 입력에 이미 있는 문자열과 충돌을 피하고 요청별 매핑을 독립적으로 유지한다.
2. 기존 질문의 중복 AI 설명·추천 문장·화면용 필드를 분석 입력에서 제외한다. 모든 원문과 기존 질문의 ID·source·AI 상태·근거, 약속의 연결·기한·상태는 유지한다. 수동 수정과 실제 처리 확인·변경 이력은 저장 계층에 그대로 남는다.
3. 분석 지침의 반복을 줄이고, 독립 질문·정보 미정·정정·수행 완료의 기존 기준을 명확히 한다. 경계 검토는 이전 AI의 상태·넓은 인용 묶음을 받지 않고 원문과 질문 ID·제목·source로 판단한다. 다른 질문의 답을 먼저 제외하도록 하며, 다른 질문의 주제도 제공하지만 검토 대상 이외의 질문을 변경할 수 없다.
4. 인용 수정 때 잘못된 전체 출력을 다시 보내지 않고 오류 경로와 정확한 원문을 제공한다. 같은 원문은 한 번만 넣고, 서버가 잘못된 인용을 자동 교정하거나 검증 기준을 완화하지 않는다.
5. 재문의의 첫 생성만 `low`; 분석·인계·모든 검토·수정은 `medium`이다. 인계까지 낮춘 후보는 제외했다. 초안 출처 수는 원문 메시지 수 이하로 제한하고 약속이 없는 대화에 약속 항목을 만들지 않게 했다.

약속 추출 지침까지 줄인 후보에서는 완료 통보 누락과 단순 안내의 약속 오인이 나왔다. 따라서 이 부분은 이전 main의 상세 지침을 그대로 복원했다. 전체 원문·품질 검토와 핵심 설명을 유지하는 쪽으로 절감 폭을 조정했다.

기술 결정과 ADR 0007에서 바꾼 부분은 [ADR 0008](adr/0008-ai-request-efficiency.md)에 있다.

잘못된 초안 5개를 거절하고 정상 초안 2개를 허용하는 [최종 대조 검사](../evals/results/performance/controls-final.json)는 마지막 수정 후 같은 소스 해시로 7/7건 통과했다. [이전 대조 검사](../evals/results/performance/controls.json)도 보존한다.

자동 테스트 **78개**, JavaScript 문법 검사 **42개**를 통과했다. ID의 왕복 변환·원문 보존·동시 요청 격리·내부 참조 누출·원문 수정 피드백·경계 검토 입력 분리·추론 설정·비교 도구의 퇴행 검출을 포함한다. 화면과 확장은 변경하지 않았으며 브라우저 시연을 새로 수행하지 않았다.

## 원문에 대한 초안 대조

최적화 전·후의 초안은 제품 내부 검토 결과와 별도로 개발 에이전트가 원문과 대조한다. 외부 사람의 검수나 독립적인 제3자 평가가 아니다. 남은 질문 누락·새 요구·숫자/날짜 생성·담당자 추정·안내 순서·약속과 사용자 확인의 혼동을 확인한다.

최적화 전 6건은 모두 실질 내용이 원문과 일치했다. NS01은 답변 없는 접시 운송장만 요청했고, NR02는 검수 통과 여부, NU03은 실제 요금제 예약 여부를 물었다. NS03은 위치 확인 약속의 이행 안내와 경비실 위치를 전달하되 실제 수령을 주장하지 않았다. NR05는 카드→계좌→카드 정정 순서를 지켰고, NU06은 기존 날짜 철회와 새 날짜 미정을 반영했다. NS03의 항목 제목과 NR05의 불필요한 '별도 약속 없음' 문장은 내용 오류로 계산하지 않았다.

최종 20건에서 생성한 초안 6건의 별도 대조 결과:

| 사례 | 확인한 핵심 내용 | 결과 |
| --- | --- | --- |
| NS01 재문의 | 머그컵 번호를 되묻지 않고 접시 운송장만 요청 | 통과 |
| NS03 인계 | 기사 확인 약속 이후 위치 확인 완료·경비실 위치를 전달하고 실제 수령은 주장하지 않음 | 통과. 한 번의 수정 후 저장 |
| NR02 재문의 | 창고 도착을 검수 통과로 바꾸지 않고 통과 여부만 요청 | 통과 |
| NR05 인계 | 카드→계좌→카드의 정정 순서를 지키며 새 약속을 만들지 않음 | 통과 |
| NU03 재문의 | 방법을 다시 묻지 않고 실제 변경 예약 여부만 요청 | 통과 |
| NU06 인계 | 철회된 11월 23일을 현재 기한으로 쓰지 않고 안내 약속과 새 날짜 미정을 구분 | 통과. 한 번의 수정 후 저장 |

기존 28건의 초안 7건도 대조했다. S02는 도착일·배송비를 모두 요청했고, R02는 차감 관계를 전제하지 않고 최종 환불액만 물었다. U02는 해지 방법 대신 실제 해지 여부를 물었다. S06은 배송비 정정과 발송 확인 완료, U06은 해소되지 않은 청구 안내 충돌을 정확하게 전달했다. R03 인계는 기한 철회를 반영했으며, 마지막 수정 후 두 번 더 생성한 인계도 원문과 일치했다.

S04는 조건별 요금표를 특정 사용자의 확정 배송비로 바꾸지는 않았지만, '[배송 지역(예: 서울특별시)]'라는 입력 자리를 남겼다. 허위 확정 사실은 아니지만 **바로 복사하기 전에 사용자 편집이 필요한 출력**이다. 초안 문장 품질의 남은 한계로 기록하고 7건 모두가 편집 없이 완성된 문장이라고 주장하지 않는다. 발표와 실제 사용에서도 초안 확인·편집 단계를 유지한다.

## 재현 및 해석

```powershell
node --env-file=.env scripts/evaluate-ai.mjs --suite unseen --model gpt-5-mini-2025-08-07 --out .artifacts/eval/new-performance.json
node scripts/compare-evaluations.mjs evals/results/performance/baseline.json evals/results/performance/optimized.json
node scripts/evaluate-ai.mjs --rescore evals/results/performance/optimized.json
node --test
node scripts/check.mjs
```

키는 로컬 환경변수 또는 숨겨진 stdin으로만 제공하며 결과에 저장하지 않는다. 재실행은 유료 API 호출이고 출력 파일을 덮어쓰지 않는다. 비교 도구는 데이터·채점기·모델·케이스·작업 범위가 다르거나 기존 사례의 품질이 퇴행하면 실패한다. 초안 의미 대조는 별도로 필요하다.

소규모 합성 자료를 반복해 개선한 결과이며 실제 상담 전체의 정확도 100%를 뜻하지 않는다. 모델 출력은 실행마다 달라질 수 있고 최종 통과 이전의 실패도 이를 보여 준다. 외부 정답 검수·독립 홀드아웃·실사용 평가가 남아 있다. 최적화 전후를 순서대로 실행했으므로 캐시 적중·공급자 부하·네트워크 차이가 시간에 영향을 줄 수 있다. 따라서 관측한 전체 구성의 변화이며 개별 변경의 인과 효과나 청구액 절감률로 해석하지 않는다. 출력 한도를 줄이거나 검토·원문을 생략해 얻은 수치는 아니다.

측정 설계에는 [OpenAI 지연 최적화 가이드](https://developers.openai.com/api/docs/guides/latency-optimization)의 전체 작업 시간과 입력·출력 토큰 관점을 참고했다.
