# 일일 제한 제거 후 최종 운영 점검

2026-11-17. 참여자 30회·관리자 100회 일일 제한을 제거했다. AI 모델·프롬프트·판정·재검토 단계는 변경하지 않았다. 이번 검증의 연결·저장 성공과 AI 의미 판정의 잔여 문제를 구분한다.

## 자동 검증

- 전체 테스트 **283개 통과**, JavaScript **149개 파일 문법 검사 통과**.
- PGlite PostgreSQL 엔진에서 참여자 사용량 30회 이후 10건을 동시에 기록해 40회로 집계했다. 관리자는 100회 이후 101회 작업을 기록했다. 다른 계정 사용량은 0회로 유지했다.
- 같은 작업 ID의 중복 집계는 409로 차단했다. 별도 HTTP 시험에서도 30회·100회 이후 요청을 접수·완료하고 사용량만 증가하는지 확인했다.
- 일회용 초대·참여자 10명 제한·계정별 문의 소유권·세션·로그아웃·CSRF·버전 충돌 검증을 유지했다.
- 고정 AI 응답을 사용하는 10명 동시 HTTP 시험에서 실행 최대 2개와 사용자별 결과 분리를 확인했다. 실제 AI 동시 시험과는 구분한다.
- 운영 DB 외부 접속 차단은 유지한다. 이번 SQL 변경은 테이블을 추가·삭제하지 않으며, SQL 엔진 회귀는 PGlite에서 실행했다. 실제 Render PostgreSQL 다중 연결 검증 이력은 [다중 사용자 검증](MULTIUSER-VALIDATION.md)에 있다.

## 실제 OpenAI 연결·저장 검증

격리된 로컬 서버에서 계정 3개의 일일 사용량을 각각 30회로 설정한 뒤 실제 `gpt-5-mini`로 배송·환불·구독 전체 흐름을 동시에 실행했다. 30번의 유료 호출을 인위적으로 반복한 것이 아니라 이전 사용량을 시험 DB에 기록한 것이다.

본문 가림 → 발화자 추출 → 문의 저장 → 최초 분석 → 새 답변 저장·분석 → 재문의 생성이 모두 완료됐다. 각 계정은 자기 문의 1개만 조회했고, 일일 사용량은 34회였다. 웹 계정 화면도 `오늘 AI 작업 33회`처럼 사용량만 표시했다. 아래 시간에는 작업 대기와 0.6초 간격 상태 조회가 포함된다.

| 사례 | 본문 정리 | 최초 분석 | 새 답변 분석 | 재문의 |
| --- | ---: | ---: | ---: | ---: |
| 배송 날짜·추가 배송비 | 8.5초 | 10.3초 | 31.0초 | 21.3초 |
| 환불 금액·입금일 | 14.0초 | 14.0초 | 33.4초 | 17.0초 |
| 구독 해지·다음 청구 | 9.1초 | 17.6초 | 13.4초 | 26.7초 |

새 답변에서 받은 도착 날짜·환불 금액·해지 완료는 답변 받음으로 바뀌었다. 재문의는 각각 배송비·입금 예정일·다음 달 청구만 물었으며 이미 받은 답을 다시 묻지 않았다.

## AI 의미 판정의 잔여 문제

위 실행은 연결·저장·남은 질문 초안 검증을 통과했지만 AI 품질 전체 통과로 해석하지 않는다. 직접 화면과 결과를 확인하면서 다음 두 문제를 발견했다.

1. `최종 환불 금액은 42,000원입니다.`라는 값 안내를 `최종 환불 금액 안내`라는 별도 처리 약속으로 만들었다. 금액 답변은 답변 받음이 맞지만, 별도 업무 수행이나 기존 안내 약속의 이행이 없는 이 사례에서는 새 처리 약속이 없어야 한다.
2. `구독 해지가 완료되었습니다.`만 안내한 뒤 `다음 달에도 요금이 청구되나요?`를 부분 답변으로 판정했다. 해지와 다음 달 청구의 관계를 명시하지 않았으므로 이 사례는 미답변이어야 한다. 초안은 다음 달 청구 여부만 물었고 청구 중단을 사실로 단정하지는 않았다.

두 문제는 횟수 제한과 다른 AI 판정 경계의 문제다. 이번 변경에서 판정 로직을 수정하거나 재평가했다고 주장하지 않는다. 원문·질문 상태 수정 기능은 유지하며, 발표 시 모든 입력에서 완벽히 판정한다고 설명하지 않는다.

## 배포 확인

검증한 변경을 별도 브랜치에서 병합한 뒤 Render에 수동 배포한다. 운영 화면의 사용량 표시·기존 문의 유지·실제 AI 재문의와 로그인 여부를 확인하고 배포 결과는 PR 및 작업 결과에 기록한다.
