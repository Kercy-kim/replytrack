# 새 이메일 답변의 긴 분석·재검토 지연 개선

기준 main: `4aab25c5986144231a35598175c08c591b632b71`. 모델: `gpt-5-mini-2025-08-07`. 입력은 가상 고객지원 문의이며 실제 메일함·사용자 상담을 사용하지 않았다.

## 84초의 원인

[기존 실제 시연 기록](../evals/results/presentation/recording-2026-11-16-final.json)과 [진단 결과](../evals/results/email-tail/diagnosis.json)를 대조했다.

| 구간 | 시간 | 확인한 처리 |
| --- | ---: | --- |
| 첫 분석 | 55.719초 | 거래 ID 수신·심사 기간·미복구·향후 이메일 통지가 포함된 답변 분석 |
| 약속 재검토 | 28.586초 | 일반 기간을 기존 심사 약속의 기한으로 연결한 결과 수정 |
| 새 답변 분석 전체 | 84.308초 | 분석·검사·재검토·저장 |

첫 결과는 `The review will take 3 business days.`를 기존 검토 약속의 기한으로 붙였다. `durationPromiseNeedsReview`가 검토를 요청했고, 두 번째 호출에서 원래 검토 약속·자료 수신·심사 후 이메일을 구분했다. 단순 UI 렌더링이나 저장 시간보다 두 API 호출의 대기가 대부분이었다. 첫 호출의 응답 헤더 대기는 55.210초, 본문 수신은 0.507초였고 재검토는 각각 28.320초·0.265초였다. 공급자 내부의 대기열·추론·네트워크 시간을 이 관측만으로 분리할 수는 없다.

확인한 총 토큰은 15,445개이고 그중 추론 토큰은 7,616개다. 25초 후 보낸 보조 요청 한 건은 취소되어 사용량을 알 수 없다. 따라서 15,445개를 청구된 전체 토큰으로 간주하지 않는다.

## 구현 범위

기존 약속이 있는 짧은 이메일 갱신에서 질문 상태와 처리 약속을 병렬 분석한다. 일반 심사 기간, 자료 수신, 기존 검토, 결과 통지를 각각의 의미에 맞게 판단하게 한다. 원문을 줄이거나 medium 추론을 low로 낮추지 않았다. 두 결과를 합친 뒤 기존 원문·의미 검사와 필요한 재검토를 수행하고 한 번만 저장한다. 하나가 실패하면 다른 작업도 취소한다. 세부 결정은 [ADR 0028](adr/0028-parallel-email-update.md)에 있다.

## 채택하지 않은 후보

`evals/results/email-tail/pilot*.json`에 실패도 보관한다. 질문과 약속을 동시에 생성하는 짧은 지침은 심사 약속을 자료 수신 완료로 바꾸거나 통지 약속을 누락했다. 스키마 설명만 보강한 후보에서는 공유된 문자열 스키마에 설명이 퍼지는 구현 문제도 발견해 분리했다. 전체 지침을 유지하는 후보도 첫 생성·전체 재검토에서 93.144초가 걸리며 기한 오인을 남겼다. 약속 배열 분리·출력 순서 변경만으로도 통지 누락이 남았다. 병렬 분석의 첫 후보는 미복구 상태 설명을 독립 업무 통보로 잘못 추출해 부정·현황과 실제 업무 수행의 차이를 명시했다.

## 최종 비교와 회귀

기준/개선안을 같은 저장 상태에서 실행한다. `OBSERVED-84`, 일반 기간 표현, 명시적 완료 기한을 각 3회 비교한 [예비 교차 결과](../evals/results/email-tail/paired.json)에서 기준 5/9회, 개선안 9/9회가 금표준을 통과했다. 중앙값은 68.725→26.970초, 최장은 87.220→37.190초였다. 기준의 품질 실패도 시간 집계에 포함했다. 확인한 토큰은 120,854→127,642개로 5.6% 늘었고, 사용량 미확인 요청은 9→7건이었다.

이후 검토 단어가 단순 조건에만 쓰인 정상 접수 약속을 오탐하지 않도록, 기존 약속에 명시적인 검증·심사 수행 확약이 있는 경우로 검사 대상을 좁혔다. 최종 코드는 같은 세 자료를 각 2회씩 다시 교차 비교했다. 완전한 새 답변 분석·검사·저장 시간을 측정하며 번역·업체 요청 분석·등록은 제외한다. 작업 두 개를 동시에 진행하고 각 개선 작업 안의 질문·약속 요청은 병렬이다. 각 비교 중 다른 유료 평가를 함께 실행하지 않았다. 반복한 가상 자료의 결과이며 일반 정확도·최대 지연 보장을 뜻하지 않는다.

### 최종 코드 전후 비교

[원본 12회](../evals/results/email-tail/final-paired.json)와 [집계](../evals/results/email-tail/summary.json). 기준 코드의 품질 실패 두 번도 전체 시간·토큰에 포함한다.

| 항목 | 기준 main 6회 | 개선안 6회 |
| --- | ---: | ---: |
| 완료 시간 중앙값 | 56.548초 | **30.464초** |
| 최장 | 97.693초 | **46.462초** |
| 품질 기준 통과 | 4/6 | **6/6** |
| 직렬 재검토 호출 | 3회 | **0회** |
| 확인한 입력 토큰 | 42,491 | 54,564 |
| 확인한 출력 토큰 | 34,918 | 30,156 |
| 확인한 전체 토큰 | 77,409 | 84,720 |
| 사용량 미확인 보조 요청 | 6건 | 5건 |

중앙값은 **46.1% 감소**했다. 양쪽 모두 품질을 통과한 네 쌍만 비교해도 중앙값은 56.440→30.464초였다. 원래 84초가 관측된 동일 입력은 이번 기준에서 38.786·74.093초, 개선안에서 **32.011·28.917초**였다. 기준의 두 품질 실패는 명시적 완료 기한 대조에서 발생했다. 개선안은 일반 소요 기간을 기한으로 옮기지 않으면서 명시적인 완료 기한과 별도 이메일 통지를 유지했다.

관측 전체 토큰은 **9.4% 증가**했다. 양쪽 품질 통과 네 쌍에서는 47,125→57,271개로 21.5% 증가했다. 병렬화로 입력이 두 요청에 전달되는 영향이며 비용 절감으로 주장하지 않는다. 캐시·미확인 요청 비용 때문에 실제 청구 증감률도 이 수치로 계산할 수 없다. 같은 모델·원문·추론 수준에서 얻은 소규모 교차 비교이고 공급자 변동이 남아 있다. 개선안에서도 46.462초가 관측돼 모든 요청의 30초 이내 완료를 보장하지 않는다.

### AI 품질·실제 웹

- [기존 이메일 새 답변 20건](../evals/results/email-tail/email20.json): 20/20 통과. 상태, 원문 연결, 약속/처리 통보 개수, 사용자 확인을 자동 생성하지 않는 기준을 검사했다.
- [새 행동 대조](../evals/results/email-tail/action-controls.json): 다른 기간 표현, 실제 심사 완료, 자료 미수신의 세 사례를 통과했다. 환불 대조의 초기 입력에 계정 복구용 저장 제목이 남아 있어 해당 자료의 한국어 제목도 고친 뒤 [환불 심사 한 건을 재평가](../evals/results/email-tail/refund-control-final.json)해 통과했다. 원본은 그대로 보관했다. 네 대조 모두 원문 인용·상태·기한과 실제 완료의 구분을 직접 대조했다.
- 단위 테스트 **265/265**, 문법 검사 **138개 파일**, 로컬 Chrome 회귀 **9종** 통과. 병렬 결과 합산, 원문 보존, 한쪽 실패 시 다른 요청 취소, 사용자 취소, 잘못된 약속 연결의 재검토·저장 차단을 포함한다.
- [실제 OpenAI API + Chrome](../evals/results/email-tail/live-browser.json): 환불·영어 계정 복구 각각 등록, 새 답변 반영, 전후 비교, 재문의 생성·검토·편집·복사·재접속 통과. 브라우저 오류 0건. 데스크톱·390px 모바일 화면과 원문·질문·약속·진행 요약을 확인했다.

| 실제 웹 구간 | 환불 | 기존 심사 약속이 있는 영어 이메일 |
| --- | ---: | ---: |
| 등록·본문 읽기·최초 분석·화면 반영 | 47.945초 | 74.458초 |
| 새 답변 입력·분석·화면 반영 | 25.404초 | 32.825초 |
| 재문의 생성·검토·편집·복사·재접속 | 14.948초 | 10.391초 |

영어 갱신의 두 분석 요청은 각각 23.940초·25.938초로 병렬 실행됐다. 32.825초에는 이메일 본문 읽기와 화면 조작도 포함된다. 이전 84.308초 기록과 이 웹 전체 구간은 측정 범위가 다르므로 직접 절감률을 계산하지 않는다. 질문은 기간 안내를 받았다고 표시하되 기존 심사 약속·자료 수신·결과 이메일을 구분했다. 재문의는 아직 답변받지 못한 문의 번호만 물었고, 서류·기간·자료 수신을 다시 묻지 않았다.

최초 등록에서 생긴 긴 분석·재검토는 이번 병렬 경로 대상이 아니다. 배송·환불·구독 48건 전체의 실제 API 재평가는 이번에 실행하지 않았다. 가상 자료의 정답과 의미 대조는 개발 에이전트가 수행했으며 외부 사람의 검수나 실제 사용자 전체의 정확도를 뜻하지 않는다.

### 재현

기준 checkout이 없으면 `git worktree add --detach .artifacts/email-tail-baseline-4aab25c 4aab25c`로 만든다. 로컬 `.env`를 설정한 뒤 새 출력 경로로 실행한다. 기존 결과 파일은 덮어쓰지 않는다.

```powershell
node --env-file=.env scripts/benchmark-email-tail.mjs --run --repeats=2 --out=evals/results/email-tail/recheck.json
$env:EMAIL_REPLY_REPORT='evals/results/email-tail/email20-recheck.json'
node --env-file=.env scripts/evaluate-email-reply.mjs --run
node --env-file=.env scripts/evaluate-email-actions.mjs --run --out=evals/results/email-tail/actions-recheck.json
node --env-file=.env scripts/check-live-browser.mjs --run --core-only --existing-email-promise
```

Chrome/Playwright 경로 설정과 로컬 회귀 실행은 [개발 안내](DEVELOPMENT.md)를 따른다. 실제 API 실행은 유료이며, 병렬 요청과 취소된 보조 요청까지 고려하면 비용 절감은 보장하지 않는다.
