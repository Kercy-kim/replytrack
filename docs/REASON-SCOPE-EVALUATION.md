# ReplyTrack 판정 이유 범위·간결성 평가

평가일: 2026-11-14. 시작 main: `1dc8742e64c42e037c92316a73ae1177de3a6464`.

## 변경 이유와 범위

기존 전체 회귀의 상태 점수는 통과했지만, 답변을 받은 질문에도 요청하지 않은 부족 사항이 붙었다. 분석 JSON 스키마가 상태와 무관하게 제공된 정보와 빠진 정보를 각각 설명하도록 요구한 것이 프롬프트의 범위 제한과 충돌했다.

분석에서 상태를 먼저 출력하고, 분석·경계 검토 모두 같은 상태별 reason 기준을 쓰도록 변경했다. 답변 받음은 받은 답, 부분 답변은 받은 부분과 질문한 대상 중 남은 부분, 답변 대기는 안내 약속, 확인 필요는 미정·식별 불가·상충 사유만 짧게 쓴다. 판단 과정을 해설하거나 원문을 길게 재인용하지 않는다. 업체 완료 안내는 안내받았다고 표현한다. 보통 30~70자를 목표로 하지만 필요한 조건이나 숫자를 강제로 자르지 않는다.

제품 변경은 `src/prompts.mjs`와 `src/schema.mjs`뿐이다. 상태 정의, 원문·근거 검증, 질문·약속 ID와 수동 상태 보존, 기한 계산, 인계 생성 지침, 모델 및 추론·호출 상한은 유지했다. 회귀 중 발견한 재문의의 추가 절차 질문과 예약 가능성을 실제 예약 상태로 오인한 사례도 지침에 보완했다. 인계 검토 지침은 공통 초안 검토 지침을 조합하므로 이 검토 강화의 영향을 받으며 최종 수정본에서 다시 검증한다. 새 AI 호출이나 문장 잘라내기·정규식 보정은 넣지 않았다. [ADR 0014](adr/0014-question-scoped-reasons.md)에 결정과 한계를 기록했다.

## 평가 방법

- 모델은 모든 실행에서 `gpt-5-mini-2025-08-07`로 고정했다. 실제 Responses API와 제품의 분석·추가 답변 반영·초안 생성 경로를 사용했고, 가상 상담과 메모리 SQLite만 사용했다.
- 기존 배송 17·환불 17·구독 14건의 원문·정답·채점기는 수정하지 않았다. 전체 48건은 후속 답변을 포함한 55개 분석 단계, 질문 71개, 약속·기한 22개, 미해결 정답 37개, 지정 초안 13개다.
- 대조 상담 4건/질문 5개를 최초 API 호출 전에 고정했다. Q01은 실제로 상세 경로를 요청한 부분 답변, Q02는 실제 입금 시각 미정, Q03은 실제 불량 확인 시 환불 가능 예외, Q04는 별도로 물은 배송 날짜와 방문 시각이다. 최종 수정본에서 두 번 반복한다. 미사용 실상담 성능이 아닌 합성 대조 회귀다.
- `reasonGrade`는 빈 이유, 알려진 판정 해설, 특정 사례의 불필요한 항목과 필요한 사실을 검사한다. 질문 원문 메시지와 일대일로 대응하며 대응이 없거나 모호하면 실패한다. 길이 자체를 합격 기준으로 삼지 않는다. 정규식 보조 검사와 모든 저장 이유의 원문 대조를 구분한다.
- 이전 main에서 채택한 `full-regression/accepted.json`을 전 결과로 사용한다. 같은 질문 71개를 사례·분석 단계·원문 메시지·고정 기대 주제로 대응한다. 이전 실행을 재사용했으므로 무작위 교차 실행한 속도·토큰 벤치마크가 아니다.
- 별도 고정 인계 18회와 기존 정상/오류 초안 검토 대조 18개도 다시 실행했다. NU03 실패를 발견한 뒤 재문의 검토에 실패/정상 대조 2개를 추가해 최종 대조는 20개다. 저장 성공을 의미 검토 성공으로 자동 간주하지 않고 본문을 원문과 대조한다.

평가 원칙은 [OpenAI 평가 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices)의 과제별 기준·경계 사례·자동 검사와 의미 검토의 결합을 참고했다. 정답 작성과 원문 대조는 개발 에이전트가 수행했으며 외부 사람의 검수는 아니다.

### 문구 검사 오탐의 별도 재채점

최종 실행의 R06에서 질문 제목/원문은 “불량일 때 반품비는 누가 내나요?”이고, 이유는 “업체가 반품비를 부담한다고 안내받았습니다.”였다. 근거에도 “불량이면 업체가 반품비를 부담합니다.”가 남았다. 초기 어휘 검사는 이유에 `불량`이 반복되지 않았다는 이유로 경고했지만, 질문과 함께 읽으면 조건과 답이 모두 있어 불필요한 질문 반복을 없애려는 목적에 맞다.

원래 질문에 명시된 조건은 질문 원문과 이유를 함께 검사하도록 R06 보조 검사만 수정했다. 질문에 없고 답변에서 새로 제시한 Q03의 불량 확인 예외는 여전히 이유에 반드시 남아야 한다. 두 경우를 구분하는 자동 테스트를 추가했다. 기존 48건의 상태·근거·약속 정답과 API 입력·출력은 변경하지 않았다.

원본 `final.json`에는 당시 reasonGrade 경고를 그대로 두고, `scripts/rescore-reasons.mjs`로 현재 보조 검사의 결과를 별도 파일에 기록한다. 원본/현재 채점기 해시와 원본 파일 해시를 보존한다. API를 다시 호출해 원하는 표현을 뽑는 방식으로 경고를 없애지 않았다. 최종 판정은 원문 대조와 재채점 결과를 함께 사용한다.

## 범위와 한계

이 변경은 다음 AI 분석부터 적용된다. 이미 저장된 상담을 자동으로 재분석하거나 사용자 수동 상태를 덮어쓰지 않는다. 기존 상담의 이유를 갱신하려면 다시 분석해야 한다.

이유가 짧아져도 원문 근거와 약속/기한은 별도 데이터로 보존된다. 근거 전체를 이유에 반복해야 하는 것은 아니다. 생성 문장의 조사·어미와 세부 길이에는 변동이 있고, 글자 수 감소만으로 자연스러움이나 실제 사용자 효용을 보증하지 않는다. OCR/음성, 실제 사용자 데이터, 다른 모델, 독립 사용자 검수와 장기 반복 안정성은 이번 범위 밖이다.

일부 출력에는 “했습니다라고” 같은 어색한 어미 결합이 남았다. 이번 통과는 고정 자료의 질문 범위·상태·근거·약속·초안 의미 기준이며, 문장 교정의 완전성을 뜻하지 않는다. 반복 중 관측한 실패와 오탐도 함께 보존해 이후 평가에서 재사용할 수 있다.
