2026-11-16(KST). 시작 main `bbad7832eba92f0a69e47bef00e73a88a1931e86`, 작업 브랜치 `codex/usability-completeness`. 가상 문의와 메모리 DB만 사용했다. 실제 고객 자료·메일함에 접근하거나 메시지를 발송하지 않았다.

## 범위와 제품에서 참고한 점

핵심은 질문별 답변 분석, 지금 내가 할 일, 한국어 설명·재문의, 새 답변 전후 비교 네 가지다. 새 관리 메뉴나 범용 챗봇을 더하지 않고 이 흐름의 읽기·확인·복귀를 보완했다.

공식 공개 자료를 비교했으며 경쟁 제품에 직접 로그인해 성능을 평가한 것은 아니다.

| 공식 자료 | 참고할 장점 | 이번 적용 |
| --- | --- | --- |
| [Gmail AI Inbox](https://support.google.com/mail/answer/16845247?hl=en) | 다음 행동과 관련 메일 연결, 사용자의 완료 표시 | 질문·초안의 근거 원문을 확인한 뒤 원래 항목으로 돌아오는 동선. 기존 직접 수행·결과 확인 분리는 유지 |
| [NoReply 변경 기록](https://usenoreply.com/changelog) | 문의별 다음 단계, 작성 내용의 직접 편집·확인 | 기존 다음 행동·편집 기능을 검증하고, 원문을 보러 가도 작성 중인 답장과 펼친 근거가 유지되도록 보완 |

이 기능이 다른 제품에 없다고 주장하지 않는다. ReplyTrack의 초점은 질문 충족 여부·처리 약속·실제 결과 확인을 분리하고 새 답변의 변화를 한 문의 안에서 연결하는 것이다.

## 발견 사항과 수정

1. **원문을 본 뒤 돌아올 위치를 잃음:** 해당 메시지에 `확인하던 내용으로 돌아가기`를 추가했다. 탭·모바일 보기·질문 필터·펼친 근거·정확한 인용 버튼 포커스를 복원한다. 같은 원문을 여러 질문에서 인용해도 첫 버튼으로 잘못 돌아가지 않는다. 다른 문의나 새 버전에는 이전 복귀 위치를 적용하지 않는다. 비동기 작업 완료가 복귀한 위치를 다시 빼앗지 않도록 탐색 변경으로 기록한다.
2. **작성 중인 답장 맥락이 끊김:** 원문 왕복 뒤에도 편집 텍스트와 근거 펼침 상태를 유지한다. 이메일 설명·할 일 이력·변경 이력의 펼침 상태도 기존 상태 보존 체계에 연결했다.
3. **안내 문구가 작음:** 입력·가림·검토·빈 상태·저장·오류 안내를 14px 이상과 1.75 줄 간격으로 조정했다. 모달·작은 행동 버튼은 높이 44px 이상, 긴 문구는 줄바꿈한다. 비활성 버튼의 커서를 계속 작업 중인 것처럼 표시하지 않는다.
4. **분석했지만 질문이 없는 상태를 잘못 설명:** ‘원문에서 질문을 찾지 못했다’와 ‘아직 분석하지 않았다’를 구분하고 다음 행동을 안내한다. 질문이 0개라는 이유로 답장 화면에서 ‘모든 질문에 답변받았다’고 하지 않는다.
5. **실제 API의 날짜 의미 혼동:** ‘환불 예정일을 11월 18일까지 안내하겠다’를 환불 예정일 답변으로 처리한 실패를 발견했다. 처리 날짜와 답을 알려줄 날짜를 명시적으로 구분하도록 분석 지침을 보강했다. 향후 안내·답변 약속이 있는 대화는 첫 분석에 medium 추론을 사용한다. 정규식은 추론량만 선택하며 질문 상태를 자동 판정하지 않는다. 추가 AI 검토 호출을 일괄 삽입하지 않았다.
6. **재문의 검토가 오히려 추정을 유발:** S04의 첫 초안은 정상적인 배송비 재문의였으나 검토기가 배송지 설명을 추가하라고 요구했다. 수정 초안에 근거 없는 ‘배송지는 제주도입니다’가 들어갔고 검토도 통과했다. 질문 분석 채점과 API 성공만으로는 이 오류를 잡지 못했다. 지침 보강만으로는 잘못된 피드백 재현을 막지 못해, 의미 검토 실패 뒤에는 검토기의 자유형 지시와 거절된 초안을 넘기지 않고 원문·선택 질문만 기준으로 다시 작성하도록 바꿨다. 검토도 소비자 관점·질문 전체 포함·원문 사실·추가 요구 없음의 네 항목 모두 통과해야 저장한다. [ADR 0024](adr/0024-draft-review-source-boundary.md).
7. **공식 안내에 불필요한 준비물 나열:** Microsoft 안내에서 서비스 사용 조건과 선택적인 기기·위치 팁의 범위를 더 명확히 했다. 정상 문의 3회·조직 계정 1회를 실제 웹에서 재검증했다. 최종 출력은 ‘해당 계정으로 사용한 서비스’라는 조건을 보존했고 기기·위치 팁을 덧붙이지 않았다. 서비스별 예시 목록은 여전히 생성될 수 있어, 모든 출력을 짧은 동일 문장으로 제한했다고 주장하지 않는다.

새 가독성 검사의 안내 문구는 Chrome 계산값 14px, 글자색 `rgb(83,105,88)`, 흰 배경이었다. 스크린샷을 직접 확인했고 가로 넘침 없이 모달 하단 행동까지 스크롤할 수 있었다. 이는 실제 휴대전화·스크린리더·사용자 연구 또는 전체 접근성 인증이 아니다.

최종 집계는 [로컬 결과](../evals/results/usability/local-completeness.json), [읽기 동선 결과](../evals/results/usability/reading-flow.json)에 보관한다. 스크린샷과 개별 로그는 로컬 `.artifacts/reading-flow/`, `.artifacts/completeness/`에 있다.

11개 작업 모두 통과했다. 최종 단위 테스트는 **231/231**, 구문 검사는 **120개**다. 개별 공식 안내·이메일 HTTP 검사는 샌드박스가 로컬 연결을 차단한 실행이 있었으며, 로컬 통신 권한을 사용한 전체 검사에서 통과했다. 이를 애플리케이션 결함으로 집계하지 않았다.

## 실제 OpenAI 및 공식 웹 검증

실제 모델은 `gpt-5-mini-2025-08-07`이다. 원문·출력·호출 사용량·코드 해시를 남겼으며 API 키는 보고서에 저장하지 않는다.

- [변경 전 웹 실패](../evals/results/usability/live-before.json): 환불 예정일 질문이 `answered`로 잘못 판정됐다. 향후 안내 약속은 추출됐지만 질문과 요약은 잘못됐다. 실패를 숨기거나 기대 상태를 바꾸지 않았다.
- [수정 후 등록·후속 답변·재문의](../evals/results/usability/live-core.json): 환불·영어 문의 두 흐름을 다시 검사했다. 각 단계의 실제 상태, 원문, 진행 요약, 동일 질문 ID, 초안 편집·저장·복사·재열기를 확인한다.
- [최종 전체 웹 흐름](../evals/results/usability/live-full.json): 위 흐름에 영어의 한국어 설명과 업체 요청 추출·새 답변 뒤 이전 설명 표시까지 포함한다.
- [항목별 재문의 검토 적용 후 영어 웹 흐름](../evals/results/usability/live-email-final.json): 등록·분석, 새 답변·진행 요약·비교, 영어 재문의·편집·저장·복사·재열기 통과. 새 답변 반영 16.1초, 재문의부터 재열기까지 9.9초였으며 관측값이지 속도 보장은 아니다. 실제 측정값은 보고서 `steps`를 기준으로 한다.
- [기존 48건 전체 평가](../evals/results/usability/full48.json): 고정 배송·환불·구독 **48/48건, 분석 55/55회**, 질문 상태 71/71·약속 22/22·원문 인용 162/162 통과. 이유 검사 실패·API 오류 없음. 그러나 재문의 7개를 직접 검토했을 때 S04에서 위 오류를 발견했으므로 **이 실행 전체가 의미적으로 완전 통과한 것은 아니다**. 제거된 인계 생성은 평가하지 않으며 성공 초안 수로 세지 않는다. 기존 48건의 정답·사례는 변경하지 않았다.
- [재문의 최종 검증](../evals/results/usability/draft-checklist-final.json): 위 48건 중 현행 재문의 대상 7건을 저장된 실제 분석 결과로 다시 생성·검토한다. S04 반복 2회, 잘못된 검토 피드백을 주입한 복구 경로 1회, 오류·정상 검토 대조 4건을 추가한다. 피드백 주입만 합성 재현이며 그 뒤 생성·최종 검토는 실제 API다. 대조는 추정 배송지 거부·질문만 묻는 정상 초안 허용·사용자가 실제 밝힌 배송지 허용·상담원 역할로 바뀐 초안 거부를 구분한다. 질문 분석 프롬프트는 이 단계에서 바꾸지 않아 48건 분석을 중복 호출하지 않았다.
- [정상 수정 대조](../evals/results/usability/draft-checklist-omission.json): S02의 도착일 질문을 빠뜨린 초안을 주입한 뒤 실제 검토기가 거절하고, 원문·선택 질문에서 다시 작성해 두 질문을 모두 복구하는지 확인한다. 피드백을 버린다고 실제 누락까지 그대로 통과시키지 않도록 검사한다.
- [공식 안내 실제 웹 10건](../evals/results/email-reply/official-web-usability.json): 정상 표시 4건·생략 6건 통과. 미지원 문의처·다른 주제·개인별 결과·조건 부족·상담과 충돌·다른 계정 유형을 포함한다. 실제 공식 본문 조회와 AI 생성·독립 검토를 사용한다. 이 테스트의 질문 분석은 준비된 fixture이므로 분석 품질 평가에 합산하지 않는다.
- Microsoft 표현 보완 뒤 [정상 3회](../evals/results/usability/official-ms-concise.json) 모두 표시·조건 보존·편집 유지, [조직 계정](../evals/results/usability/official-ms-org.json)은 생략을 유지했다. 다른 제공자의 지침은 바꾸지 않았다. 이 독립 보조 기능의 변경은 질문 분석·재문의 결과를 변경하지 않는다.

재문의 중간 실패도 보존한다. [프롬프트 보강만 적용한 실행](../evals/results/usability/draft-grounding.json)은 오류 피드백 재현에서 새 배송지 질문을 추가해 실패했고, [피드백 차단 뒤 실행](../evals/results/usability/draft-grounding-final.json)은 그 재현을 통과했으나 별도의 상담원 관점 초안을 승인했다. 이에 최종 항목별 검토를 추가했다. `final`이라는 중간 파일명이 최종 합격을 뜻하지 않으며, 실패를 성공 실행에 합산하지 않았다. [첫 누락 복구 대조](../evals/results/usability/draft-repair-omission.json)도 별도로 보관한다.

**최종 재문의 검증은 14/14, 별도 누락 복구 대조 1/1 통과했다.** 기존 7개 재문의의 최종 문장도 직접 읽어 선택 질문과 대조했다. S04는 정상 초안을 한 번 거절하는 검토 변동이 있었지만, 원문에서 재작성해 근거 없는 배송지를 추가하지 않고 통과했다. 이 거절·재작성은 시간이 더 걸릴 수 있으므로 검토기가 항상 정답이라고 주장하지 않는다. [최종 코드·검사 기록](../evals/results/usability/final-validation.json)에 단위·구문 검사 수와 코드 해시를 정리했다.

### 날짜 대조 사례와 평가 도구 보정

기존 48건과 별도로 T01 처리 날짜 미정/안내 약속, T02 안내할 날짜 자체를 질문, T03 실제 처리 예정일, T04 처리 예정일과 별도 후속 안내가 함께 있는 경우를 만들었다. 질문 상태 기대값은 각각 `waiting/answered/answered/answered`이며 수정하지 않았다.

초기 [timing.json](../evals/results/usability/timing.json)은 평가 정답의 약속 필드명을 잘못 사용해 채점기가 오류를 냈다. 제품 API 오류가 아니며 성공으로 세지 않았다. 정답 형식을 기존 채점기 형식으로 고치고, T04의 두 약속을 서로 다른 메시지에서 식별하도록 분리한 뒤 두 번 실행했다.

[첫 실행](../evals/results/usability/timing-validated.json)과 [두 번째 실행](../evals/results/usability/timing-final.json)은 모두 질문 상태 4/4, 원문 인용 14/14였다. 다만 T04의 ‘발송 후’를 기한 문자열로 남길지에 관한 평가 정답이 일관되지 않았다. 이는 특정 날짜나 마감 기한이 아니라 행동 순서이며 두 출력 모두 원문 인용에 보존했다. `dueText`는 빈 문자열 또는 정확히 ‘발송 후’만 허용하고 `dueAt=null`을 요구하도록 채점 기준을 명확히 했다. 임의 날짜와 사용자 완료 확인을 여전히 거부하는 단위 검사를 추가했다.

모델 출력을 고치거나 성공할 때까지 재생성하지 않고 **동일 저장 출력** 두 묶음을 오프라인 재채점했다. [보정 기록](../evals/results/usability/timing-calibration.json)에 원본 보고서 SHA256·새 정답 해시·각 판정을 보존했다. 각각 4/4 통과다. 신규 대조 사례의 평가 보정이며 기존 48건의 기준을 완화한 것이 아니다.

## 해석과 남은 한계

이 검증은 로컬 시제품의 고정 사례 회귀 검사다. 모든 문의의 정답률이나 실제 사용자의 편의성을 입증하지 않는다. AI 결과는 변동할 수 있고, 실패·취소·불확실할 때 사용자가 원문을 확인하고 수정할 수 있어야 한다. 공식 안내는 지원하는 문의처·주제만 다루며 자료·조건 검증 실패 시 생략한다.

이번 날짜 경계 보완은 품질 우선의 제한적 추론량 조정이다. 응답 시간 단축 실험이 아니며 일부 분석은 여전히 수십 초 걸린다. 30초 발표는 사전 실제 결과 재생이며 실시간 API 전체 처리 시간과 구분한다. 메일함 연결·자동 발송·리마인더·범용 챗봇은 추가하지 않았다. 실제 일반 사용자에게 처음 사용해 보게 하는 과제 수행 검증과 사용자별 데이터 분리는 후속 과제다.
